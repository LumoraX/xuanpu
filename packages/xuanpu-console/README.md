# xuanpu-console

xuanpu 控制台：给员工、业务方和租户管理员用的网页界面。纯静态页面（HTML、脚本与样式表，没有构建步骤、没有第三方依赖），直接调用平台的 HTTP 接口。

平台服务启动时自动挂载在 `/console/`（`xuanpu-cli` 已经带上了本包）。不想对外提供的话，在反向代理上屏蔽这个路径。

## 使用

员工打开 `http://<平台地址>/console/`，用企业飞书账号登录，直接输入需求开始使用。无需填写地址、API key、模型或业务包名称。首次页面说明直接对话流程，示例问题只填入、不自动发送。系统根据已生效业务的能力说明自动分流，未匹配时说明未接入或继续追问；模型识别失败保留草稿供重试。

管理员通过页脚「管理员入口」进入 `/console/?admin=1`，才显示凭据连接表单；平台地址留空表示当前站点。普通入口不读取浏览器残留的管理员 key 或地址。

同源部署并已配置飞书时，可以点击「用飞书登录」；租户取地址栏 `?tenant=acme`，省略时用 `identity.default_tenant`。登录失败按 `login_error` 显示原因；成功显示当前姓名、角色与退出按钮。切换飞书前清除旧 key，cookie 模式请求不带 Authorization，写请求带 `X-Requested-By: xuanpu`。接入与首位管理员见[飞书登录手册](../../docs/guides/feishu-login.md)。

| 页签 | 能做什么 | 需要的角色 |
| --- | --- | --- |
| 会话 | 新建会话、流式对话、停止生成、处理审批（批准 / 拒绝）、关闭会话、查看已关闭的会话 | 普通员工只看本人会话；重新打开时经本人会话历史接口加载消息，成员无需管理员审计权限 |
| 业务包 | 上传归档发布、切换生效版本、对任意版本跑评测并看报告 | 租户管理员 |
| 审计 | 按会话、事件类型、来源筛选，逐页查看 | 租户管理员 |
| 用量 | 按日期范围查看每天的轮数与 token | 租户管理员 |
| 用户 | 姓名、角色、状态、最近登录、待核实标记；按状态/角色/待核实过滤、翻页；改角色、停用、启用 | 租户管理员 |

流式输出时「发送」按钮换成「停止」（拿到这一轮的 `submission_id` 之后才可点）。它只停这个页面正在看的那一轮，不碰同一会话里别的标签页、别的凭据发起的对话；那一轮已经结束或还没开始时提示「这一轮还没开始或已经结束」。被停的一轮在对话里标「已停止」，排队中被停的标「已停止（还在排队，没有开始）」。

控制台没有的功能：租户管理（平台管理员的事，用 HTTP 接口）、API key 与密钥管理、飞书应用配置。业务包、审计、用量和用户页仅管理员显示；普通员工不发这些管理请求。最后管理员操作冲突（409）与停用收尾失败均有明确提示。

## 凭据存在哪

- API key 存在浏览器的 `sessionStorage` 里：按标签页隔离，关页时清除；不要据此视为安全保管库。
- 平台地址存在 `localStorage` 里，下次打开还在。
- 飞书登录令牌在平台签发的 HttpOnly cookie 中，脚本不读取它；退出撤销当前登录会话并清空页面中的员工与业务数据。

API key 模式是给可信内部人员的管理入口：未代调用的 key 可访问本租户全部会话。员工使用飞书登录时按身份隔离。面向外部终端用户的界面请经自己的后端接入（见[应用接入](../../docs/guides/integrating.md)）。页面拒绝 iframe 嵌入，姓名用文本渲染，头像仅收 HTTPS URL。

## 作为参照实现

`static/app.js` 里有一份不依赖任何库、用 `fetch` 读事件流的实现（`streamTurn`），可以在写自己的前端时参照。

## 挂到别的 ASGI 应用上

```python
from xuanpu_console import static_dir
from xuanpu_server.api import create_app

app = create_app(platform, console_dir=static_dir())
```

普通用户无需填写平台地址、API key 或业务包名。页面默认同源，飞书使用部署默认租户；登录后即可直接输入；平台仅从本租户已生效业务中选择能力，不让员工选择业务包。管理员凭据连接仅在独立管理员模式中显示，成员登录后隐藏；空业务目录仍可说明需求并使用玄圃原生文件、事项、待办、日程、个人能力和提醒。

历史加载统一走受会话归属保护的 `/history` 接口，成员不需要管理员审计权限，刷新后自动恢复最近一次可见对话和消息；已退出或切换身份的历史响应不能回填。

每条新需求先经 `/v1/assistant/route` 识别，复用适用的本人会话或创建新会话；业务执行仍走原消息流和人工审批。本人主对话、澄清及模型建议均持久化；刷新恢复最新100条，可逐页加载更早记录。未确认操作在刷新后或“我的待办”中继续处理；同一确认只创建一次。业务会话保留原历史与审批链路。

## 原生提醒与通知

员工直接说提醒需求，确认绝对日期、时间、时区与重复方式后保存；查看需求会按需展开对话内清单，其中可编辑、取消已有提醒。一次/每天/每周提醒由服务端持久调度，无需业务包。已有提醒编辑保留原时区与未改动的时间精度。

通知中心初载最近100条，SSE按游标补读新增通知；外部发送状态每15秒补查，身份切换取消请求与定时器。服务端每两秒重新鉴权；关闭网页不会删除任务。飞书是可选发送渠道，权限问题显示发送失败，站内通知不受影响。未承诺网页关闭后的系统弹窗。

系统能力默认隐藏：提醒通过自然语言提出并确认，查看/修改/取消时才展开对话内清单。顶栏“通知”独立接收结果，后台读取不打开列表；新对话、切换会话或身份会清理临时能力界面。


## 个人工作站

对话始终居中，左侧“我的文件、事项、待办、日程、个人能力、助手设置”按需打开工作窗口。“功能”页提供同样入口；模块的手动新建、编辑、回收/恢复不依赖模型。

文件支持真实上传、下载、目录、搜索、属性/移动、标签、事项关联、不可变版本与回收站。输入区与底部工具栏放在同一圆角容器中；左下角“＋”展开附件菜单，再次点击、点击外部或按Esc可关闭，也支持方向键与Tab。菜单独立于业务确认卡，不会清除其中的编辑。输入框“＋”、拖放、粘贴与“加入对话”使用同一个人空间；附件显示为可下载卡片。事项聚合关联资料、待办、日程及本事项对话进展。待办也聚合本人待确认操作；日程可进入提醒管理。个人能力为启用的工作指令，不能扩大权限；助手偏好只影响本人。

退出/切换身份清空全部个人界面；迟到响应不能覆盖新身份、新会话或新回复。窄屏工作窗口适配375px。详细用法、限额及尚未接通的企业流程见[本地试用](../../docs/guides/local-trial.md#个人工作站)；存储与确认事务见[个人工作站架构](../../docs/architecture/personal-workspace.md)。
