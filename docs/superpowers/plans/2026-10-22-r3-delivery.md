# R3 企业数据与协同实施总计划 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans逐项执行；只有用户明确选择委派时才使用subagent-driven-development。Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 员工连接真实企业微信只读数据，按组织职责完成共享事项、跨部门交接、组织审批和成果签收。

2026-10-23 范围补充：[到人优先设计](../specs/2026-10-23-r3-person-first-amendment.md)。当前试点无业务部门，直接指定陈翔和 drYang 承办与审批；部门模式保留可选，不再把真实部门或四名员工作为本次试点前置条件。

**Architecture:** 复用现有身份、密钥加密、逐请求凭据、ExecutionScope、R2执行及统一通知；新增连接委托、组织、共享事项、交接与顺序审批领域。跨员工变更使用同一个协调事务，不把私人工作区扩大为组织公开区；供应商只做适配。

**Tech Stack:** Python/FastAPI/Pydantic、async httpx、既有cryptography AES-GCM、PostgreSQL和memory双实现、原生JS控制台、Python SDK/CLI、pytest/Node/CUA、既有Linux rootless Docker。

## 2 公共契约与实现纪律

文件路径规则：分计划中未带packages/docs/examples前缀的服务端模块均相对`packages/xuanpu-server/src/xuanpu_server/`；tests相对`packages/xuanpu-server/tests/`；console static相对`packages/xuanpu-console/src/xuanpu_console/static/`；SDK/CLI分别相对其包src下`xuanpu_sdk/`、`xuanpu_cli/`。花括号表示列出的每个具体文件。所有新目录同时创建`__init__.py`，不得形成未说明的重复实现。

- 所有mutation：`request_id`+`expected_version`，create无旧版本；同key同payload返回原回执，不同payload409；旧版本409，没有权限404、无员工身份403。Cookie写接口继续CSRF。
- 页游标使用稳定复合键，默认50、上限100；统计独立于当前页，并先过滤ACL。`not_checked`/不可用字段不回填为0或已完成。
- actor/tenant/user来自认证，所有实体及外键带tenant；模型/客户端不能提交任意执行身份、外部企业、密钥或更高权限。
- 所有新领域默认关闭并逐租户开放：`connections`、`organization`、`shared_matters`、`handoffs`、`organizational_approvals`。关闭后停止新业务动作，兼容读取、撤销、撤回、取消及必要已有决定保留；每个阶段明确可用动作。
- private workspace原归属和API不变；shared matter是新领域。R2八status、unknown、预算账本、单实例及rootless资源限制不变。
- 业务扩展仍进程外；不另开模型worker、调度队列、Celery/Temporal、任意BPMN或内核同伴消息队列。
- 协调事务复用成熟PG行锁/咨询锁和已有连接池。身份/跨域失效先收紧鉴权，再异步收尾；HTTP、模型、对象I/O不在DB事务内。
- A0定义新增fixture；每包先写反例/故障测试，看到目标失败，再实现最小通过，补架构与手册，运行门禁，独立复核后提交。已有文件按职责拆分，模块≤800行、函数≤80行；中文文档/注释/commit。

## 4 公共测试脚手架（A0定义，后续按包扩展seed）

Create `packages/xuanpu-server/tests/r3_contract/conftest.py`：
- `r3_http`：dict[str,httpx.AsyncClient]，键alice/bob/tenant_admin/manager/approver/outsider/machine；正常员工带真实测试Cookie+CSRF，machine无员工，outsider另一租户。
- `r3_ids`：dict[str, Any]，服务端seed产生的installation、user、department、position及各CAS版本（版本值为int）；C/D增加shared_matter、material、handoff、approval及operator_two身份/客户端；A4增加revoked_connection_task、revoked_task_version和old_pending_request失效场景；测试不得硬写另一人的认证标识代替身份。
- `r3_now`：float，注入平台的确定时钟；expiry用该值加有效秒数，不写未来年份的常量。
- `r3_provider`：实际本机异步HTTP测试服务器，提供token、code身份、本人信息和分页目录；记录请求、支持过期/可见范围缩小、暂停回执和故障。它不能作为真实企业验收证据。
- 测试memory/PG参数共用契约；PG事务与HTTP服务真实运行。fake clock只控制到期时刻；崩溃窗口用子进程和SIGKILL，不用直接改record状态假装恢复。

所有分计划中的`r3_http/r3_ids`均由此定义；fixture模块在A0只创建基础，C/D对应任务中新增seed字段。精确API、状态、角色和payload以下方分计划为准。

## 5 总体验收样例

1. Alice真实企微登录/绑定，明确授权本人资料只读；Bob和机器key不能借用她的委托。本人撤销后旧会话/后台恢复不能继续调用。
2. 管理员预览应用真实可见部门，确认一次本地映射；没有返回的员工保持未知，不能批量停用。岗位调动不提升租户角色。
3. Alice创建共享核对事项，发布指定文件revision，授予目标部门必要可见性；Bob不能枚举Alice其他材料。
4. Bob/Carol竞争认领只有一个成功；接收方要求补充，Alice补新材料并明确重新提交；旧审批版本不授权新内容。
5. 接收方提交成果申请组织审批；审批人通过后承办人交付，Alice查看固定成果并原生签收。发送通知/模型说完成/R2 task成功均不能替代签收。
6. 回放同一决定、重复业务事件、乱序提交、身份/岗位撤销、进程重启，均不出现双认领/双审批/越权正文；外部写API计数始终0。
7. 模型不可用时，原生查看/认领/退回/补充/批准/签收仍可用；无实质变化不重复通知。
