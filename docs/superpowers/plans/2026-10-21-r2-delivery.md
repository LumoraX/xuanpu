# 玄圃 R2 持久执行与后台推进 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Use superpowers:subagent-driven-development only when the user explicitly selects delegated execution. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让已授权工作按时间或可信事件受理，进程重启后从安全阶段推进，保留预算、人工决定和权威业务回执。

**Architecture:** 扩展现有WorkTask、PostgreSQL员工事务与独立rootless执行；TaskRegistry仍是平台唯一执行生命周期入口。新增attempt、检查点、效应意图、触发定义/occurrence与事务outbox，复用R0审批回执及现有提醒、主动业务和通知。

**Tech Stack:** Python 3.12+、FastAPI、Pydantic、PostgreSQL、现有memory事务与Local/S3对象存储、taifeng稳定接口、taifeng-sandbox Docker、原生JavaScript控制台、Python SDK/CLI。

## 关键契约一览

| 契约 | 定义所在工作包 | 必须保护的事实 |
| --- | --- | --- |
| WorkTask + ExecutionGrant + TaskAttempt | A1 | 八个旧业务status保持；新字段有严格兼容默认；授权不等于cookie存活 |
| claim(owner, epoch) / checkpoint CAS | A2 | 失效执行者不能写回、不能提交下一步副作用 |
| cumulative reservation / usage | A2 | 不能通过新attempt、新session、重启重置任务预算 |
| EffectIntent / Receipt | A3 | 派发前写意图，结果未知不重发；R0批准记录不代替下游回执 |
| RecoveryDecision / artifact staging | A4 | 安全重算与真正阶段续跑分别展示；成果恢复不再调模型 |
| TaskDefinition / Occurrence | B0 | 版本和稳定触发键唯一，确认后才能安排，修改不重跑旧版 |
| TaskDomainEvent / Delivery | B2 | 与业务同事务outbox，逐条ack，不能因乱序提交丢事件 |
| TaskActivity / notifications | C0 | 本人可见、管理脱敏；同一语义转移只通知一次 |

## 默认策略与停止条件

- 单实例保持：总托管执行8、每员工1，租户并发仍取现有更小值；不为后台任务另开逃逸额度。
- 建议最多3次attempt，退避30/120秒，恢复窗口30分钟；每次实际执行600秒。部署可调低，不能由模型调高。
- 周期once/daily/weekly，使用IANA时区；默认15分钟迟到宽限、至多合并补1次，重叠跳过并留记录。
- 已登记write/external派发意图、预算账本不可读或请求上界无法证明、资源退场未核实、授权失效或固定输入不完整时停止自动推进。
- 自动核实外部结果只接服务器登记且已验收的连接器适配器；没有适配器就保留outcome_unknown和证据。
- A0若发现稳定内核契约不满足，只阻塞对应原提交续接，先到taifeng独立立项；不导入私有类、不复制内核恢复代码。纯办公重算和已冻结成果恢复可继续实施。
- 原R1终态和旧运行记录不追溯自动重跑；原始失败案例、模型输出和数据库回执分开保留。
