# 玄圃 R0 与 R1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Use superpowers:subagent-driven-development only when the user explicitly selects delegated execution. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 先形成有明确权限与执行语义的单实例基线，再交付会议材料整理与办公表格汇总两条员工任务闭环。

**Architecture:** 沿用玄圃现有身份、个人空间、业务包、会话、效应闸门和审计。R0 分离内容访问与管理权限并确定操作回执，R1 增加工作任务、按员工与会话隔离的执行环境以及成果写回；泰逢只通过稳定接口使用。

**Tech Stack:** Python 3.12、FastAPI、PostgreSQL、现有对象存储、taifeng、taifeng-sandbox、原生 JavaScript 控制台；模拟模型用于自动回归，真实模型与 Linux Docker 用于发布前验收。

## R1 与后续阶段的分界

R1 的任务接收、状态、输入版本和成果索引持久化；执行由当前进程持有。浏览器断开、刷新、切页不取消已受理任务。服务进程退出时停止执行；重启将遗留任务结算为中断或结果待核实，不自动重放。自动续跑、任意定时执行和事件工作流由 R2 交付。

R1 使用内置办公业务包组合文件处理与平台原生建议。完整岗位组织模型、部门交接、员工 OAuth、任意多个业务包融合不作为 R1 验收前提；相应结构不封死后续扩展。
