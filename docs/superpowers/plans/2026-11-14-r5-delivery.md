# R5 管家—匠人编排、执行追踪与极简入口实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans，逐任务实施、保留检查点。本文件是交付计划，不自动开始实现。

**Goal:** 员工只对管家说话；管家自办或派给匠人、可编组；每次请求有可核对的执行树与瀑布；员工页收敛为概览、对话、输入、提示。

**Architecture:** 不新建执行内核。管家是平台内置 agent；匠人是员工可用的业务包入口；派工复用 R2 任务与既有会话；span 由平台按租户持久化。见 [ADR 0017](../../decisions/0017-butler-artisan-orchestration.md) 与 [R5 设计](../specs/2026-11-14-r5-butler-artisan-design.md)。

**Tech Stack:** Python 3.12、Pydantic、FastAPI、asyncpg/PostgreSQL、taifeng 稳定层、原生 JS、pytest。依赖以开工时 `uv.lock` 为准。

## 3 文件与接口约定

`S/` = `packages/xuanpu-server/src/xuanpu_server/`，`T/` = `packages/xuanpu-server/tests/`，`C/` = `packages/xuanpu-console/src/xuanpu_console/static/`，`Q/` = `packages/xuanpu-console/tests/`，`SDK/`、`CLI/` 同 R4 计划。新 Python 目录带中文 docstring 的 `__init__.py`；文件不超过 800 行。

写接口带 `request_id`，同键同体回原回执、不同体 409；改已有对象带 `expected_version`；无数据权限 404；Cookie 写接口保留 CSRF。列表默认 50、上限 100、稳定游标，总数在授权过滤后计算。

新配置对象 `execution_trace`、`butler`、`artisan_groups`、`minimal_entry`，默认 `enabled=false, tenants=[]`。

## 5 与 R4 的衔接

- C0 引入 `ArtisanResolver` 接口：现在包 `_catalog`，R4-B 合入后换成 `CapabilityDecision`，派工记录存决策引用。两者谁先合入，后者负责适配并补反例测试。
- R4 未完成不阻塞 R5-A、B；R5-C 之后的真实跨人上线签收须等 R4-B。

## 6 风险

| 风险 | 处理 |
| --- | --- |
| 内核稳定层提升滞后 | B 的存储与接口可先做，采集开关保持关闭；不 import 实验层 |
| 一次请求烧多个匠人的 token | C0 先做预算与上限，再放开派工 |
| 管家多一层判断导致变慢或误派 | 保留路由降级与「更多」；真实模型回归集记录误派率 |
| 页面精简丢功能 | E1 逐模块对照清单；旧页保留一个版本 |
