# 本地真实业务可用实施计划

> 使用 subagent-driven-development，先红后绿，独立审查后交付。用户已确认继续完成 Responses 与可选事件加密两项改造，不再重复要求确认。

**目标：** 本地控制台使用用户配置的真实模型，走通工单查询、沙盒脚本、人工审批；飞书可先登录、后启用加密事件。

**范围：** 本地部署与现有网页产品。不把模拟登录视为真实飞书验收，不扩展飞书聊天机器人，不发布云端。

**方案：** 复用 taifeng 稳定客户端，显式选择 chat / responses / codex_responses；默认 chat 兼容旧配置。所有档位采用相同协议，避免会话历史混用；Postgres 外部会话主存不支持 Responses 时配置阶段拒绝。飞书可缺少事件密钥，缺失时事件入口关闭，不允许明文事件；存储采用可空引用与迁移，登录只依赖 App Secret。
