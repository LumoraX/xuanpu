# 个人工作站整体实现与验收

依据：已接受的 ADR 0012、工作站 v7、2026-10-02 产品设计，以及用户 2026-10-05 明确的玄圃企业核心定位与本地完整实现授权。

## 产品闭环

对话始终是主入口；“我的文件、事项、待办、日程、个人能力、助手设置”随时可打开并独立操作。普通员工不填写模型、连接器地址或密钥。企业接入与管理员功能保留。所有列表展示本人真实持久数据，不使用原型假数据。

- 文件：文件夹、上传、下载、搜索、重命名/移动、标签/事项关联、版本、回收站；输入附件直接进入同一个人空间。
- 事项：创建、修改、状态、关联文件和待办，可从事项进入对话；不伪装已接通外部财务/审批系统。
- 待办与日程：本地记录、完成/取消、起止/截止时间；已有定时提醒/通知与人工确认入口继续可用，时间展示按用户时区。
- 个人能力与设置：可保存和启停个人指令，在本人对话中生效；助手名称、称呼、风格、时区持久化，不得扩大权限。
- 对话：保留业务包路由与真实工具确认；平台能力可由自然语言提出草稿并由本人确认，附件权限先校验。主对话历史持久化；无需先选业务。
- 工作站：主对话和模块能同时使用；窄屏可切换；加载/空/失败/重试/保存中明确可见；保留管理员入口和网页悬浮通知。

## 实现顺序

1. 原生工作区领域及 HTTP 契约：严格类型校验，用户与租户双重隔离，内存和 PostgreSQL 同契约，事务版本控制与审计，对象存储内容不可变版本，限额、回收站和目录约束。
2. 工作站真实界面：模块按需打开、数据管理表单、文件附件、主对话及现有提醒/通知整合。
3. 对话平台能力：受限模型提案、确认执行、主对话持久记录、附件读取、个人设置/能力应用，业务包执行仍使用已有权限与确认链路。
4. 交叉验收和独立审查：模块之间的数据关联、刷新和进程重启、跨用户/租户拒绝、并发版本与重试、模型不可用时人工兜底、真实浏览器和窄屏。
5. 全量门禁、文档/版本、构建、合入本地 main、本地升级与真实持久数据检查。

## API 契约

`/v1/workspace/items` 管理严格校验的个人记录：folder、file、matter、todo、event、skill。外层统一 `id/kind/data/version/created_at/updated_at/trashed_at`；各 kind 的 data 由独立模型校验。创建含 request_id，更新/移入回收站/恢复带 version，外键只允许指向本人非回收站记录。GET 列表返回 items，并支持 kind/trashed/search。

`POST /v1/workspace/files?name=&parent_id=&request_id=` 为有界原始字节上传；`PUT /files/{id}/content?version=&request_id=` 创建不可变内容版本；`GET /files/{id}/content?revision=` 下载；`GET /files/{id}/versions` 版本记录。元数据更新走 items。默认单文件 20 MiB、个人空间 1 GiB，版本和回收站计入容量。

`GET/PUT /v1/workspace/settings` 返回并保存本人助手设置，更新带 version。`GET /v1/workspace/summary` 汇总本人记录数量与空间占用。

持久主对话存储由领域提供独立方法与路由；模型建议只生成待确认操作，不能自行突破用户权限。最终对话契约在集成阶段补充。
