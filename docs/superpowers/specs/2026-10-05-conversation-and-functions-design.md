# 对话优先与独立功能兜底

用户明确：功能逻辑始终存在，对话是主要入口；用户可主动查看并直接操作功能模块，也可以始终不用模块页面。

## 交互与范围

- 默认仍是会话页，不自动打开管理表单。辅助导航增加“功能”，提供已经实现的提醒、通知入口。
- 功能 → 提醒可以新建、查看、修改、取消、筛选历史，直接调用现有个人提醒接口，无需模型、业务包或外部消息平台。
- 对话仍可生成确认卡或按需展示提醒列表；两种入口共用一套界面组件和后台数据、鉴权、版本检查、幂等键与调度。
- 通知入口统一读取站内记录。新通知只更新未读提示，不切页、不展开模块。
- 尚未实现的报销、签收等不展示为可用模块；后续业务须同时设计对话入口和必要的直接操作兜底。

## 设计选择

常驻侧栏表单会挤占对话；完全移除表单则失去兜底。采用独立功能页，仅用户主动打开时显示管理界面。复用一份提醒工作区，挂载到当前对话或功能页，避免两套表单与权限规则分叉。

切页清除未提交确认和表单，使旧异步结果不能覆盖新页面；正在识别的对话响应作废但输入保留，用户返回可重试。已发送到后端的操作继续执行，重新打开模块读取真实状态。注销清空工作区和个人入口。

登录初始化完成后才展示功能入口，防止恢复会话时清空用户刚填写的表单。路由识别后的会话目录、历史、审批读取也逐次校验代际，切页后不得启动旧业务消息。

手动新建首次提交冻结正文和请求ID。网络结果不确定时只能重试相同请求，避免重复创建；服务端明确拒绝输入时恢复编辑。保存成功清表单并展示成功状态；列表读取失败明确提示，不重复提交已成功操作。
