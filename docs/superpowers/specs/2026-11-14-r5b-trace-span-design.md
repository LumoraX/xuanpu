# R5-B：trace 与 span 设计

日期：2026-11-14。状态：待实施。上级：[R5 设计](2026-11-14-r5-butler-artisan-design.md)。依赖 R5-A。

## 1 目标

员工一次请求引出的所有执行，能还原成一棵树和一张瀑布：谁派了谁、各自何时开始结束、现在在等什么、各用了多少 token。重启后仍在。

## 2 模型

- **trace**：由员工的一次输入创建，`trace_id` 服务端生成。定时或事件触发的工作也各建一条，`origin` 区分 `user | schedule | event`。
- **span**：

| kind | 何时产生 | 父级 |
| --- | --- | --- |
| `butler` | 管家的一次尝试 | 无（根） |
| `dispatch` | 一次派工 | 发起它的管家 span |
| `group` | 一个编组 | 派工 span |
| `artisan` | 匠人的一次尝试（内核 attempt） | 派工或编组 span；包内子技能挂在其上 |
| `tool` | 一次工具或连接器调用 | 所属尝试 |
| `wait` | 等本人确认、等输入 | 所属尝试 |

- 状态：`queued | running | waiting_children | waiting_input | completed | failed | cancelled | unknown`。取消请求不等于已取消，见到真实终态才收敛。
- 字段：租户、员工、trace、span、父 span、kind、显示名（技能或工具名，不含参数）、会话或任务引用、状态、起止时间、输入输出 token、`usage_complete`、结束原因代码、`incomplete`。
- **不存**：正文、工具参数与输出、推理内容、凭据。详情从既有会话历史与审计按原权限读取。

## 3 采集

- 平台已有引擎事件订阅（审计、SSE）。新增一个只读消费者把带执行身份的事件折成 span 行；与审计同一提交口径，失败记错误并标 `incomplete`，不阻塞对话。
- 跨引擎关联：派工时把 `trace_id` 与父 span 写进任务或会话的绑定记录；匠人引擎的根尝试据此挂到派工 span 下。内核不知道 trace，租户概念不下沉。
- 序号跳号、迟到、容量截断、冷恢复前的缺口一律标 `incomplete`，界面显示「记录不完整」，不展示为完整进度。
- 用量按尝试自身的绝对值更新，重复快照不重复记；父子不相加；缺失显示未知，不填 0。

## 4 接口（拟）

| 接口 | 说明 |
| --- | --- |
| `GET /v1/traces?state=active|done&cursor=` | 本人 trace 列表；默认 50、上限 100、稳定游标；总数在授权过滤之后算 |
| `GET /v1/traces/{id}` | 树：span 列表与父子关系、汇总用量、是否完整 |
| `GET /v1/traces/{id}/waterfall` | 按开始时间排序的行：偏移、时长、深度、状态 |
| `GET /v1/traces/{id}/events` | SSE 增量，断线后按游标补齐 |

无权返回 404。管理员经既有审计入口按 span 元数据查询，不因此获得员工正文。SDK 与 CLI 各加只读方法。

## 5 OTel 导出

- 配置 `telemetry.otel`：`enabled`（默认 false）、端点、协议、资源属性、采样；由构造注入，不读环境变量。
- 用内核 `OtelTelemetrySink`；平台补 `xuanpu.tenant`、`xuanpu.trace_id`、span kind 等资源或属性。导出同样不含正文。
- 端点由平台管理员配置，不接受租户或业务包自报地址。导出失败只计指标，不影响执行。

## 6 保留与容量

- span 默认保留 90 天，可配；按租户分批清理，清理不删审计。
- 单条 trace 的 span 数上限（默认 2048），超出停止新增并标 `incomplete`。

## 7 验收

合成场景：同名匠人并行两个不合并；工具归属正确；匠人挂起再恢复仍是同一 span 的新尝试；进程在派工后被杀，重启后树仍能读出且标记缺口；跨租户、跨员工读取 404；OTel 关闭时零连接。真实模型跑一次并行派工，核对瀑布里确有时间交叠、各自用量之和与会话计量一致。
