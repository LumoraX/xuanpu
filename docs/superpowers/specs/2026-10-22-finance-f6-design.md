# 财务F6：正式接入准备与可重复端到端验收

日期2026-10-22。基线7516a79；沿用用户已确认的独立存储、进程外API、7个Skill和真实HITL。用户授权本轮持续完成设计、计划、开发、验证及本地提交；无需再次选择执行方式。真实供应商仍未选定，正式支付/税务/归档验收不能由本轮模拟替代。

## 缺口与选择

F0–F5已有内部闭环，剩余项目分为三类：可立即补齐的检查/证据工具；需企业真实制度、岗位、凭据和供应商完成的外部验收；需正式环境/官方票样/模型执行的专门验证。本轮完成第一类，并为后两类提供明确交付清单。A01/A18/A22/A26/A28/A35等partial不能因为F6编号自动关闭。

比较方案：仅补文档无法持续发现失配；直接选供应商和打开正式通道缺少现有授权/材料；采用只读检查与可重复隔离验收，可在当前边界交付实际软件并保留外部证据要求。采用第三种。

## 一、配置与接入检查

离线入口`xuanpu-finance --config FILE --preflight`：只读取显式配置及固定凭据文件，不连接数据库、平台或供应商，不迁移、不启动worker。复用FinanceConfig结构校验；补密钥文件可读/有界、私密文件权限、服务/网关/供应商令牌分离、回调密钥至少32字节、AES原件密钥32字节、Ed25519公钥可解析、显式数据库地址及网关/对象TLS、公司/岗位/制度/渠道准备状态。秘密正文、路径、DSN、账户令牌不出现在JSON或错误中。输出稳定检查code/status/detail；机器发现阻断时退出2，结构错误脱敏退出2。不声称联网或正式验收通过。

在线`getFinanceReadiness`（GET `/v1/finance/readiness?legal_entity_id=...`）：当前同公司reviewer只读，其他角色/租户/撤权拒绝。使用repeatable_read读取财务独立库的当前政策版本/代数、渠道版本/能力/启停、岗位和受控账户；严格tenant/company SQL，不从启动配置缓存伪造当前可用性。检查实际审批链人员当前角色、付款/记账岗位分离、结算/合规版本绑定与能力、专用资金五场景链、发票/账套期间/账户前提。输出只包含检查结果、非敏感版本摘要和配置摘要，禁止输出账户token/政策正文/密钥/URL/对象路径。固定绑定变化导致摘要变化。模式/实例锁/worker故障单独反馈；配置可用不等于单据可执行，也不替代逐单预检和HITL。

统一报告保留`production_status=not_verified`，正式制度批准、供应商实测、官方票样/签章、WORM、异机DR、真实模型和生产负载列为外部未验；没有人工写一个passed的接口，不新增批准或执行权限。检查工具永不改变正式开关。

## 二、可重复隔离验收入口

新增仓库运维脚本`scripts/finance_acceptance.py`。只接受显式DSN文件和新输出目录，先验证loopback、真实current_database以finance_test开头且可用，再执行固定测试清单（不可任意shell命令）。quick覆盖实际HTTP、cookie/CSRF、资金闭环、归档ZIP/补包、dump/restore、生命周期、双向凭据隔离；full执行整个仓库既有门禁测试。使用成熟pytest/JUnit XML而非自建测试框架。报告保存源码HEAD及工作树摘要、清单、时间、真实tests/failures/errors/skips和证据SHA；失败、零测试、缺少预期模块、缺失JUnit或财务skip不能标passed；full既有非财务skip明确单列为partial/有skip，不静默吞掉。输出不能泄露DSN文件正文；不自动创建或操作正式资源，不调用真实渠道。取消/超时终止测试子进程且保留失败报告。

补真实PG隔离演练：本轮专属finance_test管理库中创建随机两个临时数据库及独立非超级用户，撤销PUBLIC CONNECT，分别证明各自库可操作、相互连接拒绝；不修改平台现行数据库/账户。清理连接、临时库和角色，即使断言失败也清理。证明范围为测试角色和隔离实例，不冒称正式凭据已验。既有备份/恢复工具保持独立存储。
