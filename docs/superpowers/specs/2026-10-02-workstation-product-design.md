## 1. 一句话

每个员工有一台云端的工作站和一个自己的助理。打开就是对话；员工说一件事，助理去办；要紧的一步回来问本人；人不在时它接着干，回来先告诉你它做了什么。

## 2. 它像什么，不像什么

| 像操作系统的地方 | 对应 |
| --- | --- |
| 用户与权限 | 飞书登录、以你的身份、闸门与审批 |
| Shell | 底部的对话 |
| 文件系统 | 个人空间，加上经连接接入、留在原处的公司资料 |
| 应用 | 助理会的事（能力包）；外部系统是连接 |
| 进程与多任务 | 事项，以及每个事项里跑着的对话和任务 |
| 窗口 | 日程、待办、事项、文件、设置、外部网页，按需打开 |
| 通知 | 待办；人不在时发飞书消息 |
| 定时与自动化 | 触发 |
| 搜索 | 对助理说「找一下」 |

不在这里完成的：高带宽的创作（表格、设计、代码、视频）在各自的工具里做，从这里打开、做完回到这里；人与人的实时沟通和会议在飞书；本机的外设与离线。

## 3. 屏幕

```
┌ 顶栏：玄圃 · 租户 · 我 ─────────────── 飞书 ● Gmail ● 等你确认 1 ─ 时间 ┐
│ 左栏                 │ 对话（常驻，占满中间）                             │
│  小玄                │   昨天 ──                                         │
│   你的助理           │   ● 报销系统 · 起草 BX-2311 · 写，放行              │
│   [报销][出差][请假]  │   填好了，¥1,280，你确认提交。                      │
│   它可以直接做的      │   ● 你确认 · 提交 · 审计 #70                        │
│   [设置]             │   ● 财务部 · 已受理，排在今天的批次                  │
│  我的                │   今天 ──                                         │
│   日程  今天 2 个会   │   早上好。你不在的时候：……  [看待办][看今天的日程]      │
│   待办  1 件要你确认  │                                                   │
│   事项  4 件在办      │ ┌ 附件标签 ─────────────────────────────────────┐ │
│   文件  2.3/10 GB    │ │ ＋ │ 跟小玄说……                           发送 │ │
│   我的 skill         │ └───────────────────────────────────────────────┘ │
│                      │ [带上三张发票报了] [下周二去上海] [提醒我周五交周报]   │
└──────────────────────┴───────────────────────────────────────────────────┘
                                                   窗口叠在右侧，可拖、可关
```

- **常驻的只有对话**。日程、待办、事项、文件、设置都是窗口，点左栏打开，也可以对助理说「打开日程」。
- 左栏「我的」每项带一行摘要（「1 件要你确认 · 共 4 件」「今天 2 个会，15:00 复盘」），不打开窗口也知道大概。
- 顶栏右侧是连接的状态和「等你确认」的数量。
- 按 `/` 随时回到输入框。

## 4. 对话

对话是和助理的**主对话**，长期存在，按天分隔。里面出现的东西：

| 元素 | 样子 | 说明 |
| --- | --- | --- |
| 你说的 | 右侧气泡 | 可以带附件 |
| 助理说的 | 左侧气泡，流式 | 用它对你的称呼和你设的风格 |
| 事件行 | 一行小字带圆点 | 它做的每一步：`报销系统 · 查询费用科目 · 以你的身份 · 读，放行`。绿点是放行或完成，橙点是停下等你 |
| 部门进展 | 蓝点事件行 | `财务部 · 已受理 BX-2312，排在今天的批次`。对方那边是人还是助理在接，对你透明 |
| 确认卡片 | 橙边卡片：要做什么、参数、为什么要问、[确认][不要] | 对外操作停在这里；同一张卡也出现在待办里 |
| 文件卡片 | 缩略图加来源 | 你带上的附件；它产出并写回空间的文件，点开 |
| 回来时的开场 | 一段话加几个按钮 | 「你不在的时候……」，按钮直接开窗口或事项 |

**停止生成**在流式输出时出现。**路由由助理自己做**：你不选能力包；说「把发票报了」它知道用报销的能力、调报销系统；说「下周二去上海」它知道查日历、问行政部。

### 附件

输入框左边的「＋」，四条路：从我的文件选、上传本机文件、拖到对话区域、粘贴截图。选中的先以标签排在输入框上方，可逐个去掉；发送后作为文件卡片跟在你的消息后面。

规则：上传的文件先进个人空间（限时链接直传对象存储），再带进会话；助理处理时把它关联到事项、打上标签。

## 5. 窗口

### 日程

一周七天可切换，一天一条时间线，四种东西混排：

| 颜色 | 来源 |
| --- | --- |
| 绿 | 飞书日历的日程（经连接读，平台不建日历） |
| 蓝 | 你让助理记的提醒 |
| 橙 | 助理的定时任务（「每周一 09:00 汇总上周工单」） |
| 红 | 事项与交接的截止 |

空档也标出来。「明天下午约小李开会」：助理查双方空闲，在飞书日历里建日程、发邀请，日程里立刻出现。

### 待办

四种混排，要你确认的排最前，做完的划掉：

| 种类 | 例子 | 点开 |
| --- | --- | --- |
| 要你确认的 | 提交报销单、订机票 | 定位到对话里的那张卡片 |
| 你让它记的 | 提醒、定时任务 | 规则窗口，可改 |
| 交出去的 | 报销单在财务部审核 | 事项 |
| 要你批的 | 别人的申请等你点头 | 那条申请 |

飞书日历、飞书任务里已有的待办经连接读进来显示；平台自己只存触发规则和等确认的事。人不在工作站时经飞书消息提醒，消息里带回到工作站的链接。

### 事项

列表：标题、最近一条进展、状态标签（等你确认 / 某部门处理中 / 已完成）。点开一个事项：谁在办、进展时间线、这件事的文件、「问助理进展」「归档」。

事项是个人的。项目管理经连接接现有工具，每个人的事项只是「我这边的那一份」。

### 文件

全部文件，带属性（时间、事项、标签、来源、人）。同一份文件在日程（按时间）、事项（按项目）、标签（按主题）里都能找到；目录只是属性之一。属性由助理填，员工可改。

### 设置（助理）

名字、性别或声音、怎么称呼你、说话风格；它不用问就能做的（读取、起草、算账、改我的日历、约会议……在管理员定的上限之内勾选）；它会用的个人 skill。只影响你自己看到的。

### 我的 skill

列表与新建：名字、一句话说明、指令、可调用的其他个人 skill；右侧实时生成 SKILL.md。详见整体设计 7.8。

### 外部网页

飞书文档、CRM 页面、WOPI 编辑器以窗口打开。高带宽的工作从这里出发、做完回到这里。

## 6. 助理与别的部门

- 员工只有一个助理。它用管理员按岗位给它的能力包办事，必要时直接调系统接口（报销系统、差旅系统、飞书审批）。
- 别的部门那边是部门养的岗位 agent（有自己的身份、企业凭据、队列，审计记在部门名下）。员工看不到它，只看到「某部门 · 进展」。想知道进展就问自己的助理，助理去问。
- 两个助理之间的交接是平台机制：从哪个员工的哪个事项、交给哪个部门、状态，两边各记审计。

## 7. 岗位怎么不同

形态一样，差别只在三处：助理会什么（能力包按岗位上架）、接了什么系统（连接）、自己沉淀了什么（个人 skill）。资料的权限由来源系统决定，平台不再配一遍。

| 岗位 | 事项长什么样 | 常用的连接 |
| --- | --- | --- |
| 销售 | 客户 | CRM、邮件、飞书 |
| 研发 | 需求、缺陷 | 代码仓、工单、文档 |
| 财务 | 自己的事项照旧；部门的审核在岗位 agent 里 | 账务系统 |
| 管理者 | 待办里多「要你批的」 | 飞书审批 |
| 项目经理 | 项目在项目管理工具里，事项是我这边的那份 | 飞书项目、Jira |

## 8. 手机端

至少三件事：看待办、确认或拒绝、看进展。飞书消息里的提醒直接链到这里。其余等桌面端稳定后再定。

## 9. 平台要有的东西（给详细设计）

| 实体或接口 | 说明 | 子项目 |
| --- | --- | --- |
| 助理 | 按员工组装：可见的能力包 + 个人 skill 合成一个 skill 目录，连接器取并集，版本逐包钉住；主对话长期存在，事项会话由它派生 | P2、P4 |
| 事项 | 所属用户、标题、状态、会话集合、文件、进展（由审计推导）、交接 | P5 |
| 待办索引 | 事件枢纽在挂起、核销时维护；触发规则、交接、待批的事也写进去；按用户查 | P9、P11 |
| 文件属性 | 标签、关联事项、时间、来源、人；按属性查询的视图 | P3 |
| 日程 | 飞书日历经连接读写；平台不存日程 | P6 |
| 触发 | 定时、连接上的事件、口头交代的提醒；到点以员工身份跑一轮 | P9 |
| 交接 | 平台实体，两边审计 | P11 |
| 助理设置 | 每个员工自己的：称呼、风格、不用问的范围（上限由管理员定） | P1、P2 |
| 会话历史、停止生成、审批卡片的人话预览 | 见整体设计 7.6 | P0、P5 |
| 外部网页窗口 | 嵌入策略、登录态、跨域 | P7 |
| 手机端 | 待办、确认、进展 | P5 |

## 10. 迭代里否定过的（别再提）

| 方案 | 否定原因 |
| --- | --- |
| 页签式工作台（会话 / 应用中心 / 空间 / 连接） | 管理后台的样子，不是一台电脑 |
| 应用中心，员工先挑应用再对话 | 员工不该先知道「该用哪个应用」 |
| 同事列表里每个岗位一个 agent（财务小青、行政阿远） | 让员工误以为「丢给财务」就完事；其实是以员工身份在办 |
| 显示别的部门的助理 | 多一层员工不需要理解的东西；交接是基础设施 |
| 日程、待办、事项常驻在屏幕右侧 | 打开日历看日程、打开待办看待办；桌面只常驻对话 |
| 文件只按目录管 | 一份文件要能从时间、项目、标签多个方向找到 |
