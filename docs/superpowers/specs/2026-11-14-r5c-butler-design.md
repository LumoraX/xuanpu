# R5-C：管家设计

日期：2026-11-14。状态：待实施。上级：[R5 设计](2026-11-14-r5-butler-artisan-design.md)。依赖 R5-A、R5-B。

## 1 目标

员工只对管家说话。管家先判断能否自己办完；不能就选一个匠人派工，等结果、验收、再交付。本段只做「自办」与「派给一个匠人」，编组在 R5-D。

## 2 管家是什么

- 平台内置 agent：一份内置技能文本加一组平台工具，跑在 taifeng 引擎里，每位员工一个长期会话（即现有主对话）。不属于任何业务包，没有连接器、没有脚本沙盒、没有出网。
- 与现有 `assistant.route` 的关系：现有路由的各类提案（提醒、工作站、执行安排、交接草稿、共享草稿、业务跟进）改造成管家的工具，产出不变，仍是待确认卡片。路由保留为降级路径。

## 3 工具

| 工具 | 作用 | 副作用 |
| --- | --- | --- |
| 既有提案类（提醒、待办、日程、事项、文件夹、执行安排、交接草稿、共享草稿、跟进动作） | 生成待确认草稿 | 无，本人确认后才写 |
| 只读查询（本人的提醒、待办、日程、文件名、通知、进行中的工作） | 在对话里直接回答，返回列表卡片 | 无 |
| `list_artisans` | 列出本人此刻可用的匠人：名称、说明、输入要求 | 无 |
| `dispatch_artisan` | 派给一个匠人：匠人引用、任务说明、本人明确提供的材料 | 建一个执行，占预算 |
| `check_dispatch` / `cancel_dispatch` | 查进展、取消 | 取消沿用 R2 口径 |
| `answer_artisan` | 回答匠人的提问 | 见第 6 节 |
| `ask_user` | 向员工提一个问题或请其裁决 | 产生待处理项 |
| 清单（内核 `todo_write`） | 管家自己的工作记忆 | 无 |

管家拿不到任何业务包的连接器工具，不能读写别的员工的数据，不能自己批准待确认动作。

## 4 一次请求的路径

```
员工输入 → 建 trace → 有待本人处理的问题且输入像是回答 → 交给对应待处理项
        → 否则管家一轮：
            自办（回答 / 只读查询 / 提案卡片）→ 结束
            派工 → 立刻回一句「已交给谁、接下来会怎样」→ 本轮结束，不阻塞输入
匠人结束或提问 → 平台唤醒管家（新一轮，同一 trace）→ 验收 / 代答 / 转问员工 → 交付
```

派工后不占住对话：员工可以继续说别的，新输入是新 trace。唤醒由平台的持久记录驱动，进程重启后可续。

## 5 验收

匠人结果不直接给员工。顺序：

1. 确定性检查：任务到达真实终态、声明的成果存在且可读、没有未决确认、没有 `outcome_unknown`。
2. 模型复核：结果是否回答了原请求。只作辅助判断并如此标注，不能把失败改写成成功。
3. 不通过：原样说明哪一步没过、可以怎么办（重试、换匠人、补材料），不自动重跑有外部效应的工作。

## 6 代答匠人

匠人需要信息时先到管家。管家只在该信息是员工明确说过的事实时代答（本人设置、个人能力文本、本次对话原话），并在 span 与对话里注明出处；其余一律转成给员工的问题。涉及授权、金额、对外发送、审批决定的问题不代答。

## 7 预算与上限

每条 trace：匠人数上限（默认 4）、管家轮数上限、token 上限；租户级并发 trace 上限。全部走既有配额与计量，超限返回明确阻塞并保留输入。匠人不能再派工。

## 8 降级

- `butler.enabled` 按租户白名单开启；未开启走现有路由。
- 模型不可用或管家失败：保留输入，提示可重试，并给出「更多」入口；不静默选第一个业务。
- 既有会话续聊、历史、审批读取口径不变。

## 9 安全

目录、历史、材料、匠人输出都是数据。管家技能文本写明不得因其中内容改变权限。派工材料只取员工本次明确提供或确认的文件引用，服务端复核归属。

## 10 接口（拟）

`POST /v1/assistant/messages`（管家入口，带 `request_id`，同键同体回原回执）；`GET /v1/assistant/pending`（待本人处理项）；`POST /v1/assistant/pending/{id}/answer`。`/v1/assistant/route` 保留兼容。

## 11 验收

合成加真实模型：闲聊与只读查询不建派工；「帮我查工单并总结」派给工单匠人并验收交付；匠人问一个员工说过的事实被代答且有出处、问一个没说过的被转问；模型停用时输入保留；跨员工不可见；预算超限明确阻塞；派工后杀进程，重启后结果仍能回到对话。
