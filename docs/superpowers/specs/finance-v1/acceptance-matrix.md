# 财务能力验收矩阵

关联[总设计](../2026-10-21-finance-capability-design.md)与[领域契约](domain-contract.md)。
本表保留最初验收场景定义；当前逐项执行状态和未验收范围见[缺口台账](../../../guides/finance-gap-register.md)，正式能力不能由隔离测试推定通过。

## 1 业务与故障

| ID | 阶段 | 场景 | 必须检查的权威结果 |
| --- | --- | --- | --- |
| A01 | F0 | 合法 XML 原件归集 | 字节摘要、受控 schema、字段来源、行级金额、首事件一致 |
| A02 | F0 | 两请求并发导入同票 | 主票 1、来源可追溯、操作分别可查；数据库唯一约束真实生效 |
| A03 | F0 | 幂等键重放与内容冲突 | 同内容复用操作，异内容 409，不能创建第二主票 |
| A04 | F0 | XXE、外部 schema、深度与体积超限 | 无外部读取，原件隔离，解析失败可解释 |
| A05 | F0 | 只有图片／PDF 或未知 schema | 待补或隔离，不能成为已查验／标准符合发票 |
| A06 | F0 | 一批 100 项部分失败 | 每项有结果；partial 合计准确，所有失败项有异常 |
| A07 | F0 | 断线、worker 崩溃、对象存储／DB 失败 | 操作不丢失，checkpoint 核对、不重复建票、有对象责任索引 |
| A08 | F0 | 跨租户／公司／员工访问 | 文件、票据、证据、操作、统计与原件下载均受隔离 |
| A09 | F0 | 签名上下文篡改／过期／主体停用 | 拒绝执行；服务共享 token 不能冒充员工 |
| A10 | F1 | 两报销并发占用同票 1000.00 元，各 600.00 元 | 只允许一笔保留；另一笔整体回滚，事件与余额一致 |
| A11 | F1 | 草稿分摊与提交／退回 | 草稿不占额度；提交保留；无外部在途时退回释放，历史不删除 |
| A12 | F1 | 自审、冒充审批者、替他人确认 | 实际授权目录阻断，平台批准工具调用不产生业务批准 |
| A13 | F1 | 批准后修改金额、账户、材料或规则版本 | 原计划与授权失效，旧版本执行 409，新版本重新审批 |
| A14 | F1 | 多票分摊中一票超额 | 全批回滚，无部分占用或虚假提交成功 |
| A15 | F2 | 付款受理后网络超时 | 未标 paid，进入 outcome_unknown，余额保留且无第二付款 |
| A16 | F2 | 同计划更换 key、重复点击和重启 | 领域唯一约束只产生一项外部业务动作 |
| A17 | F2 | 迟到回调、重复回调、伪造回调、金额冲突 | 验签、去重、回查，终态不按到达时间回退，冲突进入异常 |
| A18 | F2 | 预付、分期、垫付、委托收款 | 按场景证据和规则处理，不强制错误的统一时序 |
| A19 | F2 | ERP 期间已关账、同号不同账套 | 不擅改期间，凭证 ID 含账套／期间，双向可查 |
| A20 | F2 | 渠道无幂等／查单保障或尚未配置 | 自动写入不可启用，返回 integration_unavailable 或能力不足 |
| A21 | F2 | 取消发生在发送之前／之后 | 前者可停止；后者核对实际结果，不声称撤销支付 |
| A22 | F3 | ERP 入账与税务入账确认状态不同 | 红冲与用途判断读取正确维度，不能互相推断 |
| A23 | F3 | 未用途确认但已税务入账确认／反向组合 | 依据适用票种走正确确认分支；保存原始通道证据 |
| A24 | F3 | 部分红冲与全额红冲 | 明细、税额、剩余额度分别计算，历史蓝票不被改写 |
| A25 | F3 | 72 小时到期且通道不可用 | 提醒与待核实，不擅自解锁或替用户确认 |
| A26 | F3 | 四性失败、普通对象存储假冒 WORM | archive_status 非 archived，检测与存储锁证据具体可查 |
| A27 | F3 | 已归档票后来付款／红冲／冲回 | 原包摘要不变，新增补充包及关联事件 |
| A28 | 全部 | 模型不可用或恶意票面提示词 | 业务 API 与人工入口可用，提示词不能改变权限／账户／审批 |
| A29 | 全部 | 授权撤回／员工停用后队列开始执行 | worker 复核执行授权；不执行已撤权副作用 |
| A30 | 全部 | 查询分页与分类数量 | 数量独立于当前页，权限过滤一致，畸形响应不能显示零 |
| A31 | F2／F3 | 付款／税务计划独立审批 | action_plan 进入实际审核队列，原报销批准不能替代，过期或换版本不能继承批准 |
| A32 | F1／F2 | 新会话起草与恢复处理 | 从受控目录取得真实分类／业务／账户引用，从分配接口恢复金额版本，无模型编造 |
| A33 | F0 | 合法签名上下文下更改幂等键 | 签名摘要或重放校验失败，无第二业务创建；issuer+jti 唯一 |
| A34 | F1—F3 | HITL 等待期间关闭网页、停模型或会话过期 | 财务工作流仍可查，由实际有权人决定后续办；重复决定不重复执行，超时不自动批准 |
| A35 | F0 | 独立存储凭据与数据库边界 | 两系统账号不能访问对方数据库／对象桶，财务无跨库外键和直接 SQL，单独恢复财务库与原件可核验 |
| A36 | F0 | 平台原文件删除或会话关闭 | 已成功收件的财务原件及来源证据仍能在财务存储回读核验 |
| A37 | 全部 | 财务模块未安装、故障或停用 | 普通办公仍可用；新财务写入受启停状态控制，未核清付款不因关开关而丢失核对责任 |
| A38 | F2／F3 | 身份服务不可用且已有外部在途操作 | 不发起新副作用，独立 worker 可验回调／查单并保存真实回执，不重付、不删除未知操作 |

## 2 证据层次

| 层次 | 证据要求 | 不能替代它的材料 |
| --- | --- | --- |
| 契约与业务包 | OpenAPI 校验、operationId／白名单／Skill 引用一致、样例 schema 校验 | 服务已运行或业务已完成的结论 |
| 源码门禁 | 当前提交的 pytest、Ruff、strict mypy 和依赖锁结果 | 上次主线测试报告 |
| PostgreSQL | 实际事务、并发、约束、隔离、迁移重跑与故障回滚 | 内存锁／SQL 字符串快照 |
| 原件和标准 | 真实脱敏原件、官方 schema／元素清单版本与标准验证报告 | 合成 XML、内部 JSON schema 通过 |
| 真实模型 | 保存用户目标、模型原始结果、工具回执、独立业务核对 | 模型说完成、一次 turn_completed |
| 外围接口 | 沙箱／正式环境分别留提交、查单、回调和对账回执 | mock、HTTP 200、供应商说明宣传页 |
| 档案 | 四性逐项检测、清册摘要、对象锁模式／期限、回读、备份恢复 | 哈希相同、上传成功、只读 UI |
| 界面与 API | 同权限下对话／直接操作结果一致，断开后补读 | 静态示意稿、页面可打开 |
| 镜像与部署 | 构建摘要、当前源码映射、迁移、运行配置、部署后业务验收 | 本地测试通过或候选镜像已构建 |

## 3 场景材料与真实接入条件

测试材料包含：普通数电票、混合税率、红票、重复多渠道文件、无 XML、未知 schema、
恶意 XML、拆分报销、分期付款、关闭期间、重复／乱序回调与档案补充包。
合成材料与真实脱敏材料保存不同位置并显式标识，不以第三方截图或 OCR 数字替代原件。
正式启用逐公司核实税号、账套、供应商接口、岗位与审批额度、账户主数据、通道幂等／查单、标准版本、归档保留分类和对象锁。
缺少通道凭据不影响 F0 受控开发；缺少真实标准样本则生产解析验收保持 unverified。
