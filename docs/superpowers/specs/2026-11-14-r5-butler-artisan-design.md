# R5：管家—匠人编排、执行追踪与极简入口设计

日期：2026-11-14。状态：待实施；接口、表、配置均为拟新增，不得写进使用手册冒充可用。决策见 [ADR 0017](../../decisions/0017-butler-artisan-orchestration.md)，计划见 [R5 总计划](../plans/2026-11-14-r5-delivery.md)。

依据：用户 2026-11-14 三条要求（极简入口；管家自办或派给匠人、可编组；deepseek-harness 的编排、trace、span）。参照物只读：`luwu`（角色模型）、`deepseek-harness`（subagent、workflow、agent-team、trajectory）。

## 1 目标

员工说一句话，管家决定自己办还是派工；派出去的工作在概览里看得到谁在做、卡在哪、等不等我；做完的结果经验收后回到对话；每一步有可核对的时间与用量记录。

## 2 现状与缺口（2026-11-14 源码核对）

| 要求 | 现状 | 缺口 |
| --- | --- | --- |
| 只对管家说话 | `assistant.route` 接所有输入 | 它只选一个入口，不规划、不验收 |
| 管家自办 | 问答、摘要、提醒/待办/日程/文件草稿加确认卡 | 多步自办、清单式工作记忆 |
| 派给匠人 | 业务包会话或 R2 后台任务相当于一个匠人 | 没有派工动作、没有父子关系 |
| 并行、接力、编组 | 无 | 全部 |
| 交付前验收、代答匠人 | 无 | 全部 |
| trace、span | 只有审计与单轮回放 | 执行树、瀑布、OTel |
| 极简入口 | 37 个脚本、8 模块、15 功能卡 | 概览接口、对话内卡片 |

内核已有而平台未启用：`make_spawn_skill_tool`、`make_await_skills_tool`、`make_join_skill_tool`、`make_send_message_tool`、`make_wait_peer_tool`、`make_todo_write_tool`、`OtelTelemetrySink`（均在稳定层快照）。执行身份、执行树投影与瀑布在 `taifeng.experimental`。

## 4 名词

| 名词 | 含义 |
| --- | --- |
| 管家 | 平台内置 agent，每位员工一个长期会话；唯一对员工说话的一方 |
| 匠人 | 员工当前有资格使用的 `(业务包, 版本, 入口)`；不新增实体 |
| 派工 | 管家请求平台为某匠人建一个执行（R2 任务或会话），带 trace 归属 |
| 编组 | 一次派工里的多个匠人及其协作方式：并行、接力、会诊 |
| trace | 员工一次请求引出的全部执行 |
| span | trace 里的一个执行单元：管家一轮、匠人一次尝试、一个编组、一次工具调用 |

## 5 贯穿约束

- 六条红线不变。管家的技能文本是平台内置内容，不是业务方代码。
- 租户与员工归属在每张新表、每个新接口上强制；管理员默认看不到员工正文（0011）。span 不存正文。
- 写入先确认；外部结果未知不自动重放（沿用 R2 口径）。
- 匠人输出、编组消息、材料内容都是数据，不能改变权限或成为指令。
- 新配置对象默认 `enabled=false, tenants=[]`，显式白名单才启用；关开关不移除归属与撤权检查。
- 每条 trace 有匠人数、深度、token 三项上限；超限明确阻塞，不截断成通过。
- 模型不可用时：概览、通知、确认已有决定、「更多」页手动操作仍可用。

## 6 与 R4 的关系

R4-B 把「该员工能用哪个发布」做成服务端决策。R5 派工只通过一个解析接口取匠人清单：R4-B 落地前它包一层现有 `_catalog`，落地后换成 `CapabilityDecision`，派工记录保存决策引用。R5 不占用 R4 候选迁移号 0021–0024，开工时按实际 ledger 顺延。

## 7 暂不做（R5-F，另立设计）

- 带依赖关系的共享任务板（deepseek-harness agent-team）。
- 跨多轮自动推进的持久目标（goal）。
- 把 Codex、Claude Code 等外部 agent 作为匠人。
- 管家起草匠人或技能并提交审核。
- 匠人再派工（深度固定为 1）。

## 8 验收口径

合成租户、合成员工、真实模型各有预算上限；真人验收沿用 `deferred_by_user`，不写成通过。每段的技术门禁是全量 pytest、门禁 ruff、strict mypy 全绿并贴出实际输出。
