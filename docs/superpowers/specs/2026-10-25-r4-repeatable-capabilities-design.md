# R4：业务能力可复制交付设计

日期：2026-10-25。状态：实施计划配套设计，待实施；不代表新增能力已上线。

依据：[已批准总路线](2026-10-20-platform-capabilities-design.md)、[R3到人优先补充](2026-10-23-r3-person-first-amendment.md)。用户本轮明确暂缓真实员工验收，先拆R4详细计划。R3的真实双员工闭环为`deferred_by_user`，真实管理员目录预览仍未验，二者不得改成passed；恢复验收时必须重新检查身份、材料与当前版本。

## 1 目标与首个样板

让一项经过验证的业务能力可以被登记、配置、分配、评测、发布给指定员工，并在升级、撤权、故障和回退时保留可核实的工作记录。

首个样板选择“办公材料汇总与交接复核”：固定本人办公文件，按已授权的流程说明整理出可核对成果，再由本人决定是否通过现有R3入口交接。直接指定员工即可，不要求部门。部门、岗位分配只在企业实际配置后使用，不创建占位组织。

样板首先证明跨两个隔离合成租户、不同员工和不同本地配置的复制交付；不自动复制用户、文件、授权、密钥、审批人或历史。真实员工试点暂缓，合成复制验收不能代替真人业务签收。

## 2 路线选择

| 方案 | 收益 | 代价与处理 |
| --- | --- | --- |
| 先补交付治理，再做一个办公样板（采用） | 复用现有包、任务、协作和存储，尽早验证重复安装、分配、升级与回退 | 知识先覆盖有界文本来源，复杂检索及更多业务后续扩展 |
| 先做通用插件市场与多代理编排 | 容易增加可见入口 | 安装数量不能证明业务可用；R4不新建市场、代理通信或通用BPMN |
| 直接将财务分支整体并入平台 | 能覆盖较深领域 | 财务有独立存储、规则和F系列验收；本轮不合并、不假定已上线，只保留通用包与适配边界 |

不新建包加载器、队列、工作任务或向量数据库。复用`PackageRegistry`的不可变归档和摘要、R2持久任务、R3协调事务及来源检查。自建部分限于现有组件没有提供的交付状态、员工分配、评测证据绑定和权限传播规则，符合ADR0003。

## 3 当前基线与缺口

源码检查点`4707751`，业务代码检查点`2f5b6d5`；main和现有r3-a工作区一致。server/console/CLI/SDK为2026.10.24.1，已发布平台迁移到0019。上轮正式部署与分层证据见[R3记录](../../guides/releases/2026-10-24-r3-acceptance.md)，不是本轮重新部署或R4验收。

| 已有接缝 | 能复用什么 | R4必须新增什么 |
| --- | --- | --- |
| `packages.py`、`package_cache.py` | 发布后版本不可覆盖、对象摘要、本机缓存、活动版本切换 | 安装前提、配置修订、权限差异、发布证据和灰度人群 |
| `assistant.py::_catalog(tenant)` | 活动包及入口描述 | 按当前员工分配过滤；目录过滤必须配合执行出口鉴权 |
| `api/app.py`业务包及评测路由、`evals.py` | 管理API、contains/notContains/maxTokens、正常闸门计量 | 隔离评测、持久结果、固定用例/模型/配置摘要、业务与安全门禁 |
| `work_tasks/`、`task_triggers/` | 固定package版本与digest、恢复、预算、结果未知、后台发生实例 | 能力调用快照、当前分配复核、发布切换后旧任务保持固定 |
| `organization/` | 真实任职、职责与员工生命周期 | 直接到人及可选岗位/部门的能力分配，不能推导正文或审批权 |
| `shared_matters/`、`runtime/source_guard.py` | 固定来源、受保护只读会话、撤权检查 | 有权限的文本索引、引用、派生回答及删除传播 |
| `audit_usage.py`、`workspace/task_usage.py`、`metrics.py` | 审计元数据、用量和运行指标 | 按能力/发布/场景归因，区分任务成功与业务签收 |

现有私人`SkillData`只表达个人能力记录，不成为安装或管理员授予执行权的依据。现有向量记忆槽位不等于已接入受治理知识库，R4不把它直接打开后宣称知识完成。

## 4 核心对象与边界

| 对象 | 固定内容与状态 | 权威与访问 |
| --- | --- | --- |
| CapabilityRevision | capability_id、revision、包名/版本/归档digest、入口、输入输出契约、声明权限、场景标识；不可变 | 玄圃；管理员维护，员工只看已分配的说明 |
| Installation | 精确revision、本地配置修订与digest、秘密引用、前提检查结果；staged/ready/draining/disabled | 玄圃；秘密不出密钥库，摘要不包含秘密明文 |
| Assignment | user/position/unit目标、目标代次、有效期、revision范围；active/revoked | 玄圃；直接到人为默认，岗位需真实任职；分配不授予文件或外部数据权 |
| Release | 精确能力/安装修订、评测报告、目标员工的固定快照、发布epoch；candidate/active/retired/revoked | 一个员工同一能力只能解析到一个发布；多个候选命中时拒绝而不猜测 |
| InvocationBinding | 实际员工、任务或会话、发布/分配依据、精确包digest、配置digest、entry、来源快照、预算归因 | 由服务端保存；客户端不提交actor或任意执行身份 |
| EvaluationRun | 固定能力/配置/用例digest、模型配置指纹、输入版本、预算、原始制品引用、独立判断 | 元数据可管理；正文按显式评测数据权限访问 |
| KnowledgeSource/Build | 原来源稳定引用/版本/SHA、提取器版本、构建租约、chunk范围、权限依据；pending/ready/stale/revoked/deleted/failed | 索引是派生数据，绝不成为新的授权来源 |
| OutcomeObservation | 场景与预定验收项、实际执行/成果/决定引用、统计版本 | 只接受权威记录及明确人工判定；模型自报完成不入业务完成分子 |

`xuanpu/v1`包规范本轮不改成带岗位、员工或密钥的业务包格式。交付描述使用独立的`delivery.json`、版本`xuanpu-delivery/v1`：引用已发布包及digest，携带安装条件、声明权限和评测套件；不放员工、租户凭据、源材料、外部Secret或财务领域模型。新增平台接口与旧包格式分别演进。

交付描述不进入它引用的包归档：样板把可执行包置于`examples/office-review/package/`，外部delivery与evals为同级文件，先确定性构建ZIP再计算摘要。文件型能力由服务端completion profile选择office_files，不沿用只读能力的HTTP回执完成条件；本样板输入仅CSV，输出沿现有table_summary的CSV/XLSX/report/evidence四角色。

同一租户`package+entry`只归一个capability_key，避免旧API仅给包/入口时无法确定本地配置。登记与预检尚不改变旧包执行；首次发布时将整个包原子纳管，未登记的入口拒绝运行。纳管前必须排空该包无绑定的在途任务/会话并暂停旧后台安排，预检明确列出影响；不为旧工作猜测补分配。已有终态/unknown账本及必要只读核实保留，开关关闭不撤销纳管标记。

## 5 访问、版本与回退不变量

1. 目录、原生手动运行、显式`/v1/sessions`、续聊、任务、后台发生实例、批准恢复及SDK/CLI全部复用同一能力决策；不能只隐藏前台入口。机器身份无默认员工委托，评测使用明确隔离身份。
2. 每次新任务冻结InvocationBinding。每次恢复、模型发送及工具/外部出口前复核当前员工、分配、安装状态、来源与预算。任职重授形成新代次，不能复活旧授权。校验仓储不可用时拒绝新调用，不使用缓存放行。
3. 包内声明、管理员安装许可、员工分配、连接授权、来源权限与操作确认逐层取交集。目录可见、岗位匹配、租户管理员都不代表可读个人正文或代别人审批。
4. 发布仅改变未来受理的解析结果；旧任务保持精确包、配置和输入。正常回退不自动重跑、取消或改写旧任务。安全撤销禁止其后续业务出口，已发送的不确定操作进入既有核对路径。
5. 修改涉及工具、出网、连接、数据范围或确认等级时，不沿用旧许可。配置、能力或用例digest改变均使旧发布证据不匹配；密钥引用轮换或同名值覆盖都使旧安装依据失效，但不把秘密明文混入摘要。凭据出站从同一版本记录校验并解密，不能核对后另读新值；旧运行时凭据缓存回收。远端MCP的工具名、参数schema和effect必须冻结成批准集合，装配时拒绝未声明增长；可取得的适配器部署版本另记，无版本依据时不宣称同实现已验。
6. 停用区分停止新受理、排空、只读与撤销。历史、合法取消、结果未知核实及已批准独立签收保留；不得通过停止回调或删账本伪造“已停干净”。
7. 灰度是固定员工ID与lifecycle_epoch清单，单次最多100人；直接到人无部门依赖。角色/部门范围必须先预览为明确名单并确认；新的任职不自动加入旧灰度。
8. R4开关关闭后不退回旧的全租户目录与无分配执行。已纳管包保留治理标记及拒绝新调用；未纳管旧包只在明确兼容模式运行。已有任务的收尾逐条核查。

按员工发布不再用全租户`active_version`校验覆盖用户决策；`assistant._resolve_business`、显式会话和任务都使用同一解析结果。旧`publish?activate=true`与`activate`对已纳管包必须阻止绕过。正常retired/draining允许原绑定在原授权有效时继续；disabled阻止后续模型/工具，revoked还使原执行许可失效；当前有权历史、取消、只读未知核实及独立R3决定分别保留。完整矩阵见[R4-B](../plans/2026-10-25-r4b-assignment-execution.md)。

## 6 知识与工作记忆的首期范围

员工明确选本人TXT/Markdown/CSV/JSON固定版本，或有权的R3固定正文/材料；默认不抓聊天、企微目录、财务存储、网页和全盘文件。UTF-8纯文本读取复用成熟标准解析器，单文件20MiB、单次导入8份，知识库最多200个来源、总文本50MiB、最多25000个chunk；超限明确拒绝，不能静默少索引。

先用现有PostgreSQL参数化关键词查询和有界分块；查询先按租户及当前来源权限过滤再排序/计数。memory实现同语义。中文子串与标点作为确定性用例，首期不宣称语义向量召回或中文分词能力。上限查询返回10条、每条不超过2000字符，精确引用source_id/revision/sha256/chunk起止。无依据时说明未找到；原文里的指令不增加工具权。

构建用PG持久租约与意图记录、唯一构建键，不增加调度中间件；提取与对象I/O在事务外，提交前复核来源。删除/撤权先收紧查询与旧上下文访问，再清理chunk/提取文本和回答缓存；清理失败有可重试状态。最迟下一次检索、模型请求、流块外发或下载前拒绝；不承诺追回已发出的字节。原有问答历史和派生成果继续携带来源依赖，不能通过摘要/记忆转存洗掉权限。

个人偏好与业务事实分开：现有个人偏好支持本人查看更正；R4不让模型自动写入跨人的永久事实。知识库是来源可追溯的检索，个人工作记忆新增候选仅由本人明确确认，可查看、更正和删除，不带有工具授权意义。记忆更正/删除增加代次，旧上下文、摘要和回答缓存同时失效，保留源依赖；不能用“记住了”保留已撤销内容。

首期不自动将知识问答或共享正文送入R2办公沙盒。阅读与办公执行分开：办公任务仍仅处理本人明确选定的文件；未来共享知识转执行须另验用途授权及派生输出权限。

## 7 评测、业务样板和运营

评测套件固定输入、确定性断言、预期人工决定及版本。隔离环境中运行正常权限和计量流程，禁止生产密钥、真实外部写入或员工隐式授权。分别固定部署配置digest、实际测试配置digest和显式替换策略digest；仅允许已核对的地址/秘密引用/测试身份替换，权限与工具schema不得放宽。替身连接结果不证明生产供应商实现。安全反例全部通过、固定结构与金额/行数等断言全部通过才允许发布；真实模型语义结果保留原始报告与独立判断。合成模型、真实模型、生产运行及真人签收分列，任何not_checked不能转换为pass。条件未满足时可保存candidate，不能active；staged安装仅可进行隔离评测，ready由有效发布事务确立。

首个样板的业务模块只包括平台原生准备/校验/办公执行/成果复核及R3交接导航；不新建通用工作流，也不允许业务包在平台进程内加载Python插件。知识阅读保持只读保护；模型给出的知识建议经本人核对后形成显式材料引用，再决定执行或交接。涉及R3共享正文仍使用既有用途授权和固定成果规则，不能直接把只读知识工具送进办公沙盒。

运营展示按能力、发布、场景、直接员工汇总；部门仅在已有任职且有权时作为可选维度。至少给出受理、阻塞/取消/未知、任务完成、实际业务验收、token、耗时、失败原因与版本。任务成功率和业务签收率分母在测试批次/统计周期预先定义；重试不增加业务样本数，跨周期更新另记观察时间。没有价格表不显示0元成本，显示tokens及`price_unavailable`。没有前后对照不能声称节约了工时。

## 8 分段交付及完成口径

R4-A目录与安装契约 → R4-B到人/岗位分配和执行复核 → R4-C评测、灰度与回退 → R4-D来源知识和个人记忆治理 → R4-E首个可复制办公样板 → R4-F效果与成本面板 → R4-G分层发布验收。每段有独立可用产物与关闭新受理策略，不等全部完成才验证。

R3真人待项不阻塞R4设计、隔离开发和合成复制；使用实际跨人业务做R4真人试点之前补回相关R3链路。R4默认不扩大企微范围、不新增外部写通道、不合并财务分支、不重启共享宿主。

最终分层记录：源码门禁、PG故障/恢复、原生网页/无模型兜底、真实模型、镜像与安装字节、迁移与旧账本、隔离复制、真实业务。真人被暂缓时允许“技术交付通过、真人验收暂缓”，不能写R4真实业务全部完成。

详细任务、API、文件、测试及提交边界见[R4总实施计划](../plans/2026-10-25-r4-delivery.md)。
