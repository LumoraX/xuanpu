# 桌面客户端

`packages/xuanpu-desktop` 使用 Tauri 2 和 macOS 系统 WebView 提供原生窗口、菜单与下载。复用成熟桌面容器，避免自行维护浏览器内核。第一份交付面向 Apple Silicon Mac，连接已经部署的玄圃服务。

## 业务与数据归属

客户端加载管理员预置的 `/console/` 服务地址，页面、HTTP API、HttpOnly 登录 Cookie 与 SSE 都保持同源。桌面壳不复制静态业务页面，不新增另一套业务规则，也不保存模型、飞书应用或数据库密钥。文件、待办、日程、提醒、审批和审计仍以玄圃后台为中心。

提醒继续由后台持久化调度；退出客户端不会停止后台调度。客户端开启并联网时沿用站内通知与悬浮卡片。本版没有新增 macOS 系统通知或离线业务执行。

## 连接与身份

签名应用资源中的 `desktop.json` 是管理员发布配置，普通员工没有地址或 API key 输入步骤。服务只能是 HTTPS 或本机回环 HTTP；含用户名、密码、查询参数的预置地址会被拒绝。初始连接页检查固定服务的 `/healthz`，失败显示重新连接入口。

WebView 使用独立的持久会话存储。首次需要员工正常登录，不导入其他浏览器的 Cookie。登录授权仅允许配置中明确列出的来源继续在客户端内跳转，回调仍落回玄圃。正式企业部署使用稳定 HTTPS 域名，并在身份供应商后台登记同一个回调地址。

## 原生权限边界

- 本地启动页只有 `connect_service` 命令权限，命令不接收 URL、路径或凭据参数；异步检查前后再次验证调用页面与窗口。
- 远程业务、登录和文档页面没有 Tauri 原生 API 权限。没有为网页启用通用文件系统、shell 或进程调用。
- 业务和授权来源必须精确匹配协议、域名和端口。其他 HTTPS 文档交给默认浏览器；任意明文远程地址、文件协议和自定义协议不作为客户端导航。
- 文件选择使用系统文件对话框。下载只接受业务来源，落入用户的下载目录；文件名清洗后追加唯一标识，不覆盖既有文件。
- 菜单的刷新、返回、重新连接和打开下载目录都使用固定操作；不从页面接收脚本或本机路径。

## 交付边界

本机试用版包含桌面前端，不包含 PostgreSQL、Docker 或后台服务管理。企业可由管理员修改部署资源并重新签名构建，员工安装后直接登录。macOS 本地构建采用 ad-hoc 签名；跨设备正式发布需要 Developer ID 和 Apple 公证。本次不提供未经实机验证的 Windows 或 Intel 安装包。
