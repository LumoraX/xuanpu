# 能力目录与安装契约

R4-A已实现能力登记、配置预检和待发布安装。分配、运行绑定、评测发布属于R4-B/C，当前没有有效release，任何安装都不能变为ready。部署与验收范围见[本段记录](../guides/releases/2026-10-25-r4a-acceptance.md)。

## 数据归属与兼容

业务归档正本仍由PackageRegistry和ObjectStore管理。独立delivery.json指向精确包名、版本、归档SHA256与入口，不能放进自己引用的ZIP形成自引用摘要。能力标识与同租户package+entry永久一一对应，每份修订、预检和安装配置不可改写。不同版本可追加同能力修订；相同描述复用已有修订。

新增capabilities领域复用现有协调事务，不另建发布数据库或执行内核。0020增加capability_root/revision/preview/config/installation五表，租户复合外键限定引用。当前安装可通过CAS替换配置指针，旧配置继续保留。登记、状态、outbox事件及操作回执在一次协调提交中落库；内存后端同样异常回滚。所有请求依据服务端当前身份，机器管理密钥不能冒充员工。

登记与staged安装不会改变旧包active_version、旧会话或R2执行规则。首次包纳管、分配、旧任务排空和所有执行入口保护尚属B/C；当前不能将A作为旧业务安全迁移完成的证据。私人工作方法记录也不授予执行权。

## 严格描述与权限

格式为xuanpu-delivery/v1；未知字段拒绝。输入与输出只接受office_files、capability_receipt或read_only_answer固定契约，成果类型须匹配输出契约。A只核对声明，文件成果适配及运行完成核验留给B2。

permissions固定脚本命令/出网、审批等级、模型档位、预算，以及外部工具名称、参数schema SHA256和effect。这些值须匹配已校验的包清单；未填写的包预算按平台默认值解析后比较。MCP必须在包中明确白名单，不能开放全部工具。连接要求使用可替换的wecom只读连接契约。

公开参数只能填写requirements声明的键、类型与枚举。secret_refs是逻辑槽至本租户保管库名称的绑定，connection_refs是连接槽至本租户已安装连接的绑定；均不接受秘密明文。公开响应只显示凭据配置状态，内部密文变化指纹、实际秘密引用和连接元数据不回显。交付描述不得携带企业身份、材料或机器路径；文本本身由管理员核对，服务端不声称能识别自由文本里的所有敏感内容。

## 两阶段预检与提交

1. 管理员显式请求预检；读取精确修订、现有安装版本和当前身份，不创建业务任务。
2. 事务外核对归档真实字节及摘要，打开声明需要的沙盒，启动连接器并列出工具。只握手/列工具，不调用业务工具，不调用模型、不读取员工材料。stdio启动会执行交付方声明的连接器启动程序，仍受既有沙盒规则约束。
3. 固定完整实际MCP清单（白名单外新增工具也改变摘要）；获准工具另按名称、schema、effect精确核对。HTTP依据归档OpenAPI声明核对，HTTP/远端实现版本无法核实则内部标implementation=unverified；不声称已核实业务服务语义或远端部署版本。
4. 重新进入协调事务，重查当前身份、配置版本、密文及连接版本，写预检证据与回执。默认900秒到期，探测默认30秒，单个平台串行探测。
5. 人工确认preview_id、expected_version和布尔confirmed=true。应用前再次执行完整预检，证据须相同；最终事务再核本地证据和CAS，然后只追加staged配置及安装事实。数字1或字符串true不能代替确认。

凭据证据使用随机化SecretRecord密文的SHA256，不对秘密明文计算摘要。get_bound一次读取、比对并解密同一记录，避免先核版本再另读新秘密。底层连接secret_ref同样记录密文版本；覆盖、删除、重建均使旧预检失效。PG在最终协调事务内通过FOR SHARE持有秘密行直到提交，避免最后核对与写安装之间被覆盖。A不缓存业务运行凭据；实际运行缓存失效属于B。

预检列明缺失配置、凭据、连接范围、预算或依赖故障；不足条件不能安装。安装确认时过期、工具/schema增长、依赖变化、配置并发变化均409，要求重新预检。输入422、无权403、异租户记录404；清理未完成503，不伪装成安装成功。

## 资源关闭与冷恢复

每次探测使用专属data_dir/capability-probes/probe_*目录。启动中尚未交出句柄的异常也登记清理凭证，全部收尾完成才删除目录。某个关闭失败保留责任；关闭被取消时保留当前及后续句柄供重试，平台关闭会等待在途探测及遗留清理。

Docker可按确定工作目录映射的容器名回收，不扫描其他部署。未知的本机遗留目录无法证明内存进程跟踪之外的进程已退出，因此保留现场并拒绝继续启动或预检；管理员须核实对应进程退出后处理该专属目录，不能直接据目录存在判定安全。全量关闭开关也不跳过遗留资源回收。

## 入口和运行边界

管理员使用“能力配置”登记、预检、查看权限差异、保存与停止安装；员工“功能→我的能力”仅查询本人可运行目录，A返回明确空集合。关闭capability_delivery新受理仍允许管理员查询和停止旧安装。SDK、CLI和原生界面共用HTTP服务、当前权限、CAS及操作回执，不自动补确认或重发写请求。
