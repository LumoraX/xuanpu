## 现状

第一版加上 P0 底座升级（[ADR 0011](../decisions/0011-system-design-decisions.md) 决策 1）与 P1 用户身份：业务包规范、平台服务（控制面 + 运行时 + HTTP 接口 + 评测运行器）、命令行、Python 客户端、控制台五个包可用。

P0 之后：会话主存可以放进 Postgres、业务包归档放进对象存储，多个实例不再共用数据目录，节点本地盘上只剩缓存；能停止正在生成的那一轮；平台代为运行的 MCP 连接器进程跑在单独的连接器沙盒里；能以部署在别处的 MCP server 作连接器（`transport: remote`）；人工拒绝的连接器调用有过闸记录；有 Prometheus 指标端点与配额修改接口。依赖 taifeng `2026.10.1.10`。

## 分层与依赖方向

P1 的飞书登录、离职回调、对账和控制台已经本地实现，并用真实 CLI 与模拟飞书验证；真实飞书接入仍待[实机清单](../guides/feishu-login.md#6-本地验证边界与真实应用核对清单)。

```
业务包（声明 + 进程外扩展）
        │ 发布
xuanpu
  ├─ xuanpu-spec          业务包规范（对外契约，不依赖其他组件，也不依赖 taifeng）
  ├─ xuanpu-cli           校验 / 打包 / 生成凭据 / 迁移 / 启动服务 / 运行评测
  ├─ xuanpu-sdk-py        Python 客户端（只依赖 HTTP 库）
  ├─ xuanpu-console       控制台：纯静态页面，调用 HTTP 接口；服务装了本包就挂在 /console/
  └─ xuanpu-server        控制面 + 运行时 + HTTP 接口 + 评测运行器
        │ 只依赖稳定层
taifeng-sandbox · taifeng-stores
        │
taifeng
```

依赖只能自上而下；下层永远不 import 上层，也不出现上层概念。

## 四个平面

按 [ADR 0004](../decisions/0004-planes-and-effect-gates.md)，平台分四个平面。下表是各平面在代码里的落点（`runtime/` 下各模块的分工见[运行时的模块](#运行时的模块)）：

| 平面 | 职责 | 模块 |
| --- | --- | --- |
| 计算面 | 组装并承载内核引擎、会话租约、事件分发、停止生成 | `runtime/assembler.py`、`runtime/sessions.py`、`runtime/leases.py`、`runtime/events.py`、`runtime/cancellation.py`、`runtime/resolutions.py` |
| 效应面 | 副作用的出口：脚本沙盒与连接器沙盒、连接器（stdio MCP、远端 MCP、HTTP）、模型 | `runtime/sandbox.py`、`runtime/connectors.py`、`runtime/mcp_connectors.py`、`runtime/remote_mcp.py`、`runtime/connector_process.py`、`runtime/http_api.py`、`runtime/gate_audit.py`、`runtime/models.py`、`runtime/approval.py` |
| 状态面 | 会话主存与线程目录、业务包归档、本地缓存、长期记忆 | `bootstrap.py` 里的 `PostgresStateBackends`（实现来自 taifeng-stores）、`objectstore/`、`package_cache.py`。长期记忆的槽位在（`StateBackends.memory_store`），但配置文件尚未接入 |
| 治理面 | 租户、凭据、业务包版本、密钥、配额、审计、用量、评测、指标 | `platform.py`、`tenancy.py`、`packages.py`、`secrets.py`、`quota.py`、`audit.py`、`evals.py`、`metrics.py`、`controlplane/` |

所有外部依赖（控制面存储、密钥保管库、模型客户端工厂、沙盒供给方、状态面后端、对象存储）都经 `Platform` 的构造参数注入；平台代码不读环境变量，环境变量只在命令行入口读取。

## 状态放在哪里

| 状态 | 正式部署（`state.backend: postgres`、`object_store.backend: s3`） | 试用与单机（两者都是 `local`） |
| --- | --- | --- |
| 控制面：租户、凭据摘要、业务包登记、密钥密文、会话记录与租约、用量、审计 | Postgres（`control_plane.backend: postgres`） | 同左，或内存（进程退出即丢） |
| 会话主存与线程目录 | Postgres，每个租户一组带专属前缀的表（taifeng-stores 的 `PostgresMessageStore`、`PostgresThreadDirectory`） | 数据目录下 `threads/` 里的 JSONL 文件与 SQLite 索引 |
| 业务包归档（正本） | 对象存储，键 `tenants/<租户>/packages/<名>/<版本>/<sha256>.zip` | 本机对象存储，默认 `<data_dir>/objects/`，键相同 |
| 业务包解包后的文件 | 各实例自己的数据目录 `cache/packages/`，用到时从对象存储取归档、核对指纹、解包 | 同左 |
| 脚本沙盒工作区、连接器工作目录 | 各实例自己的数据目录 `workspaces/`、`connectors/` | 同左 |

正式部署下，节点本地盘上只剩可以重建的缓存与工作目录：别的实例接手会话时从库里续接，用到业务包时从对象存储重建缓存，多个实例**不共用数据目录**。反过来，一个数据目录也只能归一个进程：业务包缓存的锁只在进程内，启动时还会清掉暂存目录的残留。

会话主存在库里时：每个运行时（引擎池）用一个自己的 `PostgresMessageStore`，全部共用一个连接池；不再给内核 `storage_dir`，也不再挂消息镜像（镜像与主存写的是同一张表）。线程目录用按租户共享的 `PostgresThreadDirectory`。外部主存只支持 Chat 协议的模型客户端（内核在建池时拒绝 Responses 协议），平台模型可选 Chat、Responses 或 Codex Responses；后两者使用本机会话主存，外部 Postgres 主存仍限 Chat。

数据目录的内容：

```
<data_dir>/
├── cache/
│   ├── packages/<租户目录>/<包名>/<版本>/          业务包解包后的文件
│   ├── packages/<租户目录>/<包名>/.<版本>.digest   这个版本目录对应的归档指纹
│   └── .staging/                                 发布与重建缓存时的暂存目录，启动时清空
├── workspaces/<租户目录>/<包名>/<版本>/            脚本沙盒的工作区
├── connectors/<租户目录>/<包名>/<版本>/            连接器沙盒的工作目录（有 stdio 连接器才有）
├── objects/tenants/<租户>/packages/<包名>/<版本>/<sha256>.zip
│                                                 本机对象存储（object_store.backend 为 local 时）
└── threads/<租户目录>/<包名>/<版本>/              会话主存（state.backend 为 local 时）
```

`<租户目录>` 是「租户标识-摘要」（如 `acme-822b33ad`），对象存储的键里直接用租户标识。

## 一轮对话的路径

```
POST /v1/sessions/{id}/messages
  │ 认证 → Principal（带租户）
  ▼
SessionManager.send_message
  ├─ 配额：租户可用？当天用量未超？
  ├─ 取会话（按租户过滤；别的租户的会话按不存在处理）
  ├─ 取得租约（别的实例持有且未到期 → 409，带上持有者）
  ├─ PackageRegistry.resolve —— 本地缓存里有就用；没有就从对象存储取归档、核对指纹、解进缓存
  ├─ RuntimeAssembler.get —— 首次使用时组装：
  │     连接器：stdio  —— 开连接器沙盒 → 取密钥 → 在沙盒里启动 MCP server → 列工具 → 按白名单筛
  │             remote —— 核对密钥已配置 → 连远端 MCP server → 列工具 → 按白名单筛
  │             http   —— 读包内 OpenAPI 文档 → 核对密钥已配置 → 按白名单筛 operation
  │     审批：按业务包的审批强度与工具的副作用分类生成权限策略
  │     脚本沙盒：受限读 + 只写工作区 + 按声明决定是否出网
  │     模型：按档位路由的客户端
  │     → taifeng.EnginePool.create(...)（会话主存：库里的 message_store，或数据目录下的 storage_dir）
  ├─ 确认持有（准备期间租约中断过 → 503，可重试），改用最新的会话记录
  ├─ pool.get_or_create（有线程标识则从会话主存续接）
  ├─ 再确认一次持有，才放进本实例；EngineEventHub 建立全量事件订阅
  └─ engine.submit → 同步登记本轮的事件流
  ▼
响应：Server-Sent Events，直到本轮结束（完成 / 失败 / 挂起 / 被停下）
```

事件枢纽同时做几件事：把事件分给各轮对话的事件流、成批写审计、在一轮对话结束时把用量入账（被停下的一轮按上下文估算被打断那次采样的输入）、把内核对送回审批的结论对到在等它的那次送回上。

送回审批（`resume`）的路径：读审计里最近一次挂起的待办 → 送回里有已经核销过的待办就整次 400 → 提交 `Resume` → 等内核的结论（`suspension_resolved`、`suspension_partially_resolved` 或 `suspension_resolve_rejected`）→ 为这次确实核销了的人工拒绝补过闸记录。

停止生成（`cancel`）的路径：只看本实例上这个会话在途的那几轮 → 逐个等它出现在内核的在飞表里（最多约 1 秒）→ 提交 `CancelTurn` → 记一条 `turn_cancel_requested`。被停的那一轮照常从它自己的事件流收尾。

## 运行时的模块

| 模块 | 做什么 |
| --- | --- |
| `assembler.py` | 按「租户 + 业务包 + 版本」组装运行时：连接器沙盒、连接器、权限策略、脚本沙盒、引擎池；收尾按相反的顺序 |
| `sessions.py` | 会话的建、发消息、送回审批、停止生成、关闭；会话的持有与释放 |
| `leases.py` | 会话租约：取得、续期、确认、释放。确认时发现租约中途到期过（哪怕又续上了）就按持有中断处理 |
| `session_history.py` | 只读审计推算出来的视图：还挂着的待办、一轮对话的回放、送回里哪些待办已经核销过 |
| `cancellation.py` | 停止生成：等内核受理再提交 `CancelTurn`，只返回真正提交了取消的那几轮 |
| `events.py` | 一个引擎一条全量事件订阅，分给各轮的事件流、写审计、入账用量 |
| `resolutions.py` | 把内核的核销事件对到在等结论的那次送回上，算出「这一次新核销了哪些」 |
| `gate_audit.py` | 过闸记录的字段集合；人工拒绝的连接器调用的补记（送回前取待办、等内核确认核销后再写） |
| `connectors.py` | 三种传输共用的闸门（白名单 → 审批 → 调用 → 审计）与按传输分派 |
| `mcp_connectors.py` | stdio 与远端 MCP 共用的启动流程（建连、列工具、核对白名单、筛工具）；stdio 连接器的进程与排障线索；`env` 里的 `LD_*`、`DYLD_*` 在这里再拦一次 |
| `remote_mcp.py` | 远端 MCP：经 `McpHttpClient` 连远端 server；凭据传输在每次请求发出时现取密钥、只发同源；结果与错误按值脱敏 |
| `connector_process.py` | stdio 连接器进程的排障线索（退出码、stderr 末尾）；给内核 MCP 的 logger 挂过滤器，外部内容不进日志 |
| `http_api.py` | HTTP 连接器：按 OpenAPI 的 operation 发请求 |
| `sandbox.py` | 脚本沙盒与连接器沙盒的供给（本机隔离、Docker） |
| `approval.py`、`models.py`、`session_metadata.py` | 审批强度到权限策略的换算、档位到模型的路由、会话 `metadata` 的校验 |

## 资源回收

引擎、连接器进程、沙盒都占内存与进程，不能随会话数无限增长。平台实例每隔租约的三分之一做一次维护：

| 对象 | 条件 | 动作 |
| --- | --- | --- |
| 会话的引擎 | 没有进行中的对话，且空闲超过 `session_idle_seconds`（默认 300 秒） | 释放引擎、放弃租约；会话保持活动，下次对话时从会话主存续接（等审批的会话同样如此） |
| 运行时 | 引擎池里没有活着的会话，且空闲超过 `runtime_idle_seconds`（默认 900 秒） | 依次关闭引擎池、连接器（stdio 进程与远端连接）、连接器沙盒、脚本沙盒；下次使用时重新组装 |

内核因还有后台子任务而拒绝释放引擎时，什么都不动，下一轮再试。

业务包缓存与两种工作目录不回收：缓存不做淘汰（版本不可变，体积有限），工作目录不自动清理。

## 配额与停机

| 配额 | 检查点 | 超出时 |
| --- | --- | --- |
| `max_active_sessions` | 建会话 | 429 |
| `max_daily_tokens` | 每轮对话开始前（用量在一轮结束时入账，拦的是下一轮） | 429 |
| `max_concurrent_turns` | 每轮对话开始前（本实例内计数） | 429 |

配额每次检查都现读控制面，平台管理员改了配额（`PUT /v1/admin/tenants/{id}/quota`）立即生效。

平台关闭（`Platform.close`）先取消提醒扫描与渠道投递并等待所有在途发送，关闭提醒发送客户端；然后取消身份维护与对账、等待有界失败收尾，再等待员工停用后台任务（最多 5 秒）；之后拒绝新的对话（503 `runtime_unavailable`），等在途对话跑完，最多等 `shutdown_drain_seconds`，到期仍未结束的被取消。之后释放本实例持有的全部会话，会话保持活动，可由别的实例接手，最后关闭身份客户端。

`xuanpu serve` 下，平台关闭排在 HTTP 服务器自己的收尾之后：服务器先停止接受连接，并等已打开的响应（事件流）发完，最多等 `shutdown_drain_seconds` 加 5 秒（uvicorn 的 `timeout_graceful_shutdown`），到期断开还没发完的响应，那几轮对话转到后台。`shutdown_drain_seconds` 在平台阶段约束的是调用方已断开、仍在后台跑的对话；P1 身份对账取消后，失败审计与释放租约各有最多 30 秒的清理窗口，不能再把 `2 × shutdown_drain_seconds + 5` 当成整个停机上限。

## 效应闸门

| 出口 | 放行条件 | 审计 |
| --- | --- | --- |
| 沙盒内脚本、命令 | 内核工具层按权限策略检查；需要审批时本轮挂起 | 内核事件（工具调用、脚本执行） |
| 连接器工具（stdio MCP、远端 MCP、OpenAPI 描述的 HTTP 接口，共用一个闸门） | 在清单白名单内；按副作用分类与审批强度放行或挂起 | 每次调用一条 `connector_call`：连接器、传输、工具、副作用、决定、耗时、参数摘要、归属的那一轮。人工拒绝的调用走不到闸门，由平台补一条 `decision=rejected` |
| 模型调用 | 租户可用、当天用量未超、会话预算未超 | 内核事件；开启留痕时另记完整请求 |

审批强度与副作用的对应关系见[编写业务包](../guides/writing-packages.md#审批强度)（实现在 `runtime/approval.py`）。没有被规则覆盖的副作用一律走审批。

连接器进程在哪里跑、碰得到什么：stdio 连接器在每个运行时单独的连接器沙盒里（只读业务包目录、只写连接器工作目录、可出网），与脚本沙盒分开；远端 MCP 不进沙盒，请求从平台节点发出，凭据只发往清单 `url` 同源的地址。设计理由见 [ADR 0013](../decisions/0013-connector-sandbox-and-remote-mcp.md)。

## 租户隔离

taifeng 不知道租户。隔离体现在平台组装运行时注入的每一样资源上：

| 资源 | 隔离方式 |
| --- | --- |
| 控制面记录 | 每次读写都带 `tenant_id`，存储实现按它过滤 |
| 平台用户与外部身份 | 用户、身份配置、用量与租约按租户过滤；外部身份以 `(tenant_id, provider, subject)` 唯一。cookie 摘要、OAuth state 的入口查找先取得记录，再从记录确定租户并验证启用状态 |
| 员工会话 | 普通成员（包括被代调用者）只能访问 `user_id` 为本人的会话，其他人的按 404；管理员及未代调用的 API key 可访问本租户全部会话 |
| 业务包归档 | 对象存储的键以 `tenants/<租户>/` 开头；取用时核对登记的键就是按记录算出来的那一个、内容与登记的指纹一致 |
| 业务包缓存 | `<数据目录>/cache/packages/<租户目录>/<包名>/<版本>/` |
| 会话存储 | 状态面 Postgres：每个租户一组带专属前缀的表。本机：`<数据目录>/threads/<租户目录>/<包名>/<版本>/` |
| 脚本沙盒工作区 | `<数据目录>/workspaces/<租户目录>/<包名>/<版本>/`；沙盒里只读得到业务包目录与系统运行时目录 |
| 连接器工作目录 | `<数据目录>/connectors/<租户目录>/<包名>/<版本>/`；连接器沙盒里另外只读得到业务包目录、系统运行时目录与部署方放开的目录 |
| 密钥 | 密文以「租户 + 密钥名」作附加认证数据，挪到别处解不开 |
| 连接器进程 | 环境只有清单声明的变量加最小集合，不继承平台进程的环境 |
| 模型凭据 | 可配置为各租户用自己在保管库里的网关凭据 |

访问别的租户的资源一律按「不存在」处理，不透露它是否存在。

## 身份与员工停用

身份域在 `identity/`，只依赖治理面与存储，不依赖运行时；关闭会话能力由平台装配到停用监听者。内存与 PostgreSQL 共用 `IdentityStore` 契约。平台用户 ID 为 `usr_` 加 24 位十六进制，飞书 `union_id` 仅用于租户内的外部映射，不用邮箱或手机号认人。

登录使用授权码、PKCE 与一次性 state；另用登录尝试 cookie 绑定发起浏览器。登录 cookie 默认名为 `__Host-xuanpu_session`，每个请求验证登录记录、用户与租户，停用立即生效。API key 认证优先；仅获 `act_as_users` 能力的 key 可用 `X-Xuanpu-Act-As`，生效角色取 key 与员工中的较低者。[认证细节](http-api.md#认证)

停用统一标记用户、撤销其登录会话，再通知监听者关闭会话。主人已停用的会话不能继续发消息或送审批，后台收尾失败可重复停用重跑。飞书离职事件经加密验签处理；每日对账与清理登录共用维护循环，跨实例用 120 秒租约互斥，并在批次、员工和完成步骤前续期。查不到只标记待核实；只有明确的离职、退出、暂停状态才停用。

会话里的全部审计 `user_id` 是主人，`actor` 是触发者；员工管理操作的 `user_id` 是被操作员工。按员工用量包括主人会话的正常与估算入账，不含无主人的系统会话。P1 仍仅允许管理员查审计与用量。配置与接入见[飞书登录手册](../guides/feishu-login.md)。

## 审计

审计记录只追加，来自三处：

| 来源 | 内容 | 去重 |
| --- | --- | --- |
| `engine` | 内核事件。流式增量不记，改在一轮结束时记一条 `turn_text` 带回复全文；被停下的一轮另记一条 `usage_estimated`；含完整提示词的事件默认不记 | 按 `(事件流, 序号)`；引擎每次被创建是一条新的事件流 |
| `gate` | 连接器调用的过闸记录，含平台补记的人工拒绝 | 不去重 |
| `control` | 控制面操作：租户与配额、凭据、密钥、业务包、会话、用户发出的消息（`message_sent`）、送回审批、停止生成 | 不去重 |

内核因队列满丢事件时，事件枢纽会记一条 `audit_gap`，审计不完整不会悄悄发生。

## 已知限制

隔离与出网：

- 隔离强度按沙盒后端区分。**macOS 本机后端只用于开发试用**：沙盒里的进程能读到同一用户下其他进程（包括平台进程）的完整参数与初始环境（`KERN_PROCARGS2`，seatbelt 管不到），出网时能连本机任意 TCP 端口。Linux bubblewrap 不过滤 Unix 套接字、没有 seccomp 与 Landlock。生产用 Linux，推荐 `docker` 后端。部署方要把住的几处见[运维手册的安全须知](../guides/operations.md#安全须知)。
- 出网范围平台不限：HTTP 连接器的 `baseUrl`、远端 MCP 的 `url` 由租户管理员在清单里声明（含内网与云元数据地址），连接器沙盒允许出网，平台节点能到的地方连接器都能到。出网范围靠部署的网络策略约束。凭据方式不含 OAuth2 换取令牌的流程（ADR 0008）；远端 MCP 也不支持 OAuth 与私有 CA。
- 同一业务包内的连接器互信：它们共用一个连接器沙盒与工作目录，docker 与 macOS 下能看到彼此的进程环境（含密钥）。同一运行时下的会话共用脚本沙盒的工作区与连接器工作目录。
- 按值脱敏覆盖得不一致：远端 MCP 的结果与错误、stdio 连接器的错误文本与日志里的排障线索都按值脱敏，stdio 连接器**成功**的结果与 HTTP 连接器的响应不脱敏（外部系统回显了凭据就会原样交给模型、进审计）。按值脱敏也只认得原样与常见转义的明文，凭据被编码、拆开后再输出就认不出来。
- 远端 MCP 的工具在组装运行时时定下，不随 `tools/list_changed` 增减；远端的 MCP 会话过期（404）后不重新握手，要等运行时空闲回收后重新组装（缺口清单第 28 项）。

状态与多实例：

- `state.backend: local` 时会话主存是节点本地文件，跨实例接手要共用数据目录，而数据目录又不能被多个进程共用，所以 `local` 只适合单实例。`postgres` 状态面绑定 Chat 协议的模型客户端。
- 会话租约：续期与回收空闲会话、空闲运行时在同一个维护循环里串行执行，实际续期间隔是「租约时长的三分之一 + 一次维护的耗时」，维护卡住太久时租约可能在持有者还在写时到期；租约期限按各实例自己的墙钟判断，依赖 NTP；会话存储不核对租约（没有 fencing），单写者完全靠持有者及时察觉、及时停写（见 `runtime/sessions.py`）。
- 连接 Postgres 的连接池取连接没有时限：池满时一直排队，`pool_max` 要按并发留足。
- 业务包缓存不自动淘汰，实例停机时可以整个清空（下次用到时从对象存储重建）；运行中清空要重启实例。版本号的预发布段可以含大写字母，在大小写不敏感的文件系统上（如 macOS 默认）只差大小写的两个版本缓存目录相撞，交替使用时反复重建。对象存储里的归档与登记的指纹不符时返回 `400 package_invalid`，其实是服务端的数据损坏。

对话：

- [停止生成](http-api.md#停止生成)只停在途、且内核已经受理的那一轮：会话正在准备引擎时取消返回空列表，随后开始的那一轮不受影响；内核约 1 秒内没受理的不提交取消；平台确认受理到内核处理取消之间还有约一个事件循环迭代的窗口（缺口清单第 20、21 项）。送回批准之后紧跟着停止，被批准的调用照样执行。
- 关闭会话、持有权丢了之后强制收尾、停机时等不到在途对话跑完，内核会直接中止这一轮，正在进行的连接器调用也随之中止：外部系统可能已经执行了，结果平台不知道。闸门照样记一条过闸记录（`decision=allowed`、`is_error=true`、`detail=cancelled`），写不进去只记错误日志。
- 被停下的一轮，被打断的那次采样网关报不出用量，平台按内核的上下文估算计入输入（估算不精确）；拿不到估算时按 0 计。
- 调用方断开后只能经回放接口补齐已审计的事件，拿不到流式增量（回复全文在 `turn_text` 里）。
- 配额拦的是「下一轮」，当天实际用量可能超出上限一轮对话的量；并发对话数只在本实例内计数。
- 人工拒绝的连接器调用走不到闸门，过闸记录（`decision=rejected`）由平台补记：送回之前按审计里的待办取出被拒的那些，等内核确认这次送回确实核销了它们再写（内核整次拒绝的送回、重复送回的同一个拒绝都不会多记）。待办以审计为准，挂起事件还没写进审计时就送回，会缺这一条；补记写库失败只记错误日志并计入指标，不让送回失败（见 `runtime/gate_audit.py`）。
- 只送回了一部分待办之后，再送回已经处理过的待办，内核会受理并再做一遍（批准过的工具再执行一次，缺口清单第 30 项）。平台在提交之前按审计拦下（`400 invalid_request`），审计滞后的那一小段里紧跟着的重复送回拦不住。
- 内核自己发起的几类挂起（重试、资源上限、工具结果未知）被送回中止时，内核不发收尾事件，这次送回的事件流等不到结束（缺口清单第 23 项）。平台发起的审批不走这条路。

其他：

- 对账查不到员工不会自动停用；缺状态字段也不推断离职，需管理员检查通讯录范围与字段权限。
- 飞书 HTTP 事件回调要求公网可达；P1 不使用长连接。真实飞书自建应用尚未验收。
- 管理员仍可查看本租户全部会话正文，未代调用的 API key 也保留租户级可见范围；[ADR 0011](../decisions/0011-system-design-decisions.md) 规则 7 的内容可见性要在 P6 上线前收紧。

- 前台 shell 与文件类工具未开放：内核已在稳定层提供，平台要等按用户隔离执行环境（P4）之后再开。
- 长期记忆没有接进配置文件：taifeng-stores 提供了向量记忆后端，但平台还没有嵌入服务的配置项。以库的方式装配平台时可以自己注入（见 `packages/xuanpu-server/README.md`）。
- 没有删除租户的接口。
- 主密钥轮换后没有批量重新加密的工具，要逐条重写密钥。
- 审计表没有内置的清理与归档。
- 内核事件里的工具调用参数是一段 JSON 文本，按键名脱敏对它不起作用（见[审计与用量](../guides/audit-and-usage.md#审计里有哪些敏感内容)）。

## 本地可用接入

模型协议由管理员配置 `models.protocol`，默认 chat；responses 与 codex_responses 复用内核公开客户端。普通用户不填写模型、地址或密钥。控制台通过租户内的只读业务包目录自动加载已生效业务，管理员连接收在折叠入口。飞书登录不再依赖事件加密配置；缺任一事件凭据时 `events_enabled=false`，回调保持拒绝，不降级到明文。

## 企业核心与原生提醒

[ADR0014](../decisions/0014-enterprise-core-and-durable-reminders.md)明确玄圃为企业核心，外部系统可替换。`Platform.reminders`装配同后端的`control.reminder_store`，随平台启动/关闭后台扫描与outbox发送。Postgres迁移0006持久保存提醒、通知与投递任务；内存后端仍只适合测试，重启不保留。

自然语言只生成草稿；员工确认后创建、查看、编辑、取消本人提醒。定时不依赖浏览器、飞书连接或模型服务。到期数据库事务原子创建通知并推进计划；外部发送在事务外，UI通过SSE接收新增通知、周期补查投递状态。用户停用在身份事务中取消提醒，重新启用不自动恢复。

当前纯提醒不是“到点自动执行业务”的通用工作流。后者必须在独立设计中接入会话运行时、权限和审批。身份双向同步、真实报销和文档签收仍是后续领域，不因新增提醒而具备。

到期检查和外部投递使用两个独立且可取消的后台循环；外部请求变慢不会阻塞下一轮站内到期检查。关闭平台时同时取消并等待两个循环和所有在途发送，之后再关闭连接池。每轮数据库扫描仍受当前数据库响应时间影响，不承诺硬实时。

控制台采用[对话优先与独立功能兜底](../superpowers/specs/2026-10-05-conversation-and-functions-design.md)：默认会话页，提醒确认和本人清单在对话中按需展示；员工也可主动进入“功能 → 提醒”手动新建、查看、修改、取消并筛选历史，或从“功能 → 通知”查看通知。手动操作直接调用同一组个人HTTP接口，不依赖模型、业务包或外部平台。单一提醒工作区在两个入口复用；切页清除未提交表单并隔离迟到响应，身份切换清空个人状态。通用通知入口独立显示未读提示，不强行打开面板。后台生命周期不依赖这些面板显隐；未实现的领域不作为可用功能展示。
