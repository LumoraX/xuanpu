# 极简入口（活文档）

> R5-E。为什么这么定见 [ADR 0017](../decisions/0017-butler-artisan-orchestration.md) 决策 8；设计与计划见 [R5-E 设计](../superpowers/specs/2026-11-14-r5e-minimal-entry-design.md)、[R5-E 计划](../superpowers/plans/2026-11-14-r5e-minimal-entry.md)。已随 2026-11-15 生产发布部署，所有租户默认关闭（见[R5 生产发布记录](../guides/releases/2026-11-15-r5-production.md)）。

## 概览（`dashboard/`、`api/dashboard.py`）

`GET /v1/dashboard` 一次返回四块，每块是数量加至多 5 条摘要（接口细节见 [HTTP 接口](http-api.md#员工概览r5-e0)）：

- **今天**：本人时区里当天到期的活动提醒、与当天有交集的日程、当天及之前到期的未完成待办（逾期的标 `overdue`）。
- **等我处理**：未处理的助手草稿（`WorkspaceService.pending_proposals`，最多统计最近 100 条）、管家待本人处理项（管家开启时）、`waiting_user` 的交办工作、轮到本人审批的组织审批（审批开启时；读取审批列表与审批页面同口径，会同样把已失效的待审批标为阻塞）。
- **进行中**：本人活动 trace（执行追踪开启时才有这一块）；摘要标出是否有 span 在等本人输入、记录是否完整。
- **未读通知**：通知中心的站内通知（提醒、业务跟进、执行安排等同一张表），总数由存储计算（`ReminderStore.unread_notifications`）；共享事项与协作通知各有自己的流，不计入。

规则：

- 先校验员工身份；机器身份、停用员工、暂停租户整个请求 403。
- 四块并发读取、互不依赖。平台错误把这一块标成 `error` 并给错误码；意外异常记日志「概览块 … 读取失败」后给 `internal_error`。都不影响其他块。
- 全程不调用模型；模型停用时概览照常可用。

## 新页（`xuanpu-console` 的 `entry.html`）

只有四样：概览、对话、提示、输入；页脚是「更多 · 通知 · 退出」。「更多」进入功能页（`index.html?classic=1`），新页默认不加载功能页的脚本。

- **对话**：`POST /v1/assistant/messages`（每次新请求标识 `web-<uuid>`）；支持顶栏「自主办理：开/关」一键切换本人设置 `auto_execute_personal`，以及输入框「附件」上传个人工作台文件（`POST /v1/workspace/files`）并随 `input_files` 交由管家自动读取整理。待发输入区与对话气泡（含刷新后由 `GET /v1/workspace/messages` 恢复的历史消息）里的附件均渲染为可交互条（`entry-attachments.js`）：点击文件名可在页内安全预览（支持 Markdown 排版/原文切换、纯文本、图片、PDF 及二进制下载兜底），点击「下载」直接经 `/v1/workspace/files/{id}/content` 下载原件。回执与主对话历史里的助手消息按 `metadata.route` 渲染卡片（含「助理已办好」自主办理回执卡与一键「撤回」按钮，调用 `/v1/assistant/actions/{request_id}/{action_id}/undo`），按 `metadata.butler.trace_id` 渲染进展卡。管家 503 时原话回到输入框，提示位置显示系统状态。
- **卡片**调用原模块接口、原幂等键与版本号：草稿确认卡（`/v1/assistant/proposals`）、列表卡（提醒、待办、日程、事项、文件）、交办工作状态卡、匠人提问答复卡、通知卡；业务跟进、执行安排、企业连接（`module-cards.js`）与共享事项、工作交接、组织审批（`collab-cards.js`）的列表与确认卡。必须本人选择或确认的动作（授权同意、审批决定、交接对象与资料版本、跟进时间）都由本人在卡片里点击，模型不代做；同一张卡重试复用冻结的请求。需要原生页面的少数动作留在「更多」：企业微信绑定（跳转官方授权页）、交接的转交与补充资料、提交与交付成果、下载核验固定成果。
- **进展卡**：一条 trace 一张，订阅 `/v1/traces/{id}/events`；记录不完整时标注；刷新后由历史重建并重新订阅（最近 3 张自动订阅）。浏览器支持 SVG 时是「小院」（R7，见下节），否则只显示执行树与瀑布。

## 小院（R7，`courtyard-*.js`、`courtyard.css`）

为什么这么定见 [ADR 0023](../decisions/0023-execution-story.md)；设计见 [R7 设计](../superpowers/specs/2026-11-19-r7-courtyard-design.md)。

- **常驻小院**（`courtyard-stage.js`，页面 `#stage`）：打开入口就在——宽窗口（≥1100px）整页是小院，右侧整列是概览与对话记录（独立滚动，员工没往上翻时跟着最新内容），输入框在最下面横贯；窄窗口按上下排。管家在管家台、本人可用的匠人（`GET /v1/assistant/artisans`）在垫子上待命。员工发一句话后对话以流式回执发出：第一帧拿到 trace 标识，进展卡立刻打开并让小院以这件事为焦点（trace 落库前订阅会 404，进展卡每秒重试至多 120 秒）；管家回复逐段出现（没写出字时气泡提示看小院）。一次只演一件事：最新发出的请求，或员工在某张进展卡上点「在小院里看」的那件；进展卡只讲「经过」与执行树，不再各带场景。管家还没动手时头顶「我想想怎么办…」，执行工具、工具完成组织回复（如「处理完成，正在组织回复…」）与流式回话阶段气泡实时同步当前进度；匠人一轮未完时留在上一步的家具旁「想想下一步…」（真实工具往往一眨眼就完）。
- **分层**：`courtyard-model.js` 是纯函数（执行记录 + 细节 → 角色位置、动画节拍、经过条目），`courtyard-art.js` 画角色，`courtyard-scene.js` 只按节拍或终态画 SVG，`courtyard-card.js` 接进进展卡（订阅帧 → 取细节 → 画 → 写经过）。所有文字走 `textContent`，SVG 只放常量画法。
- **事实 → 画面**：管家根 span 是管家；派工 span 让匠人上垫（按包名，最多 5 位）。交代方式：会诊编组 → 圆桌当面，任务承载 → 写信，其余 → 走过去当面说。工具按名称归到家具：等待类 → 小床，`read_*`/文档/知识 → 书架，脚本 → 工作台，报表/看板/趋势 → 看板，带 `.` 或 `__`（连接器、MCP）→ 电脑，其余 → 档案柜。匠人等你时：审批 → 红色「等你盖章」，提问 → 打电话；会诊等裁决 → 管家在圆桌边红色「等你裁决」。派工到终态 → 交回、管家按验收结果打勾或记失败。
- **动画是讲解，事实为准**：快照帧（刷新、重连、已结束）与「减少动效」直接画终态；增量帧播节拍，排完后再对齐到最新记录。
- **经过**：管家的信（任务说明，来自 `GET /v1/assistant/dispatches/{id}`）、匠人每一步的旁白（span 的 `say`；没有时按工具名拼并在「细节」里注明）、提问与代答（带出处）、等盖章、结果摘录、验收五项。点角色只看它，再点回到全部。轮到本人的条目有「去处理」，打开既有的答复卡。
- **换角色**：管家与本次出场的匠人可换样子、颜色、配饰；管家可改称呼（6 字内），匠人名字是包名。存本设备（`localStorage`），存储不可用时只是不记住。
- **降级**：没有 `document.createElementNS` 或小院脚本没加载时，进展卡照旧；派工细节读不到时不出信纸、交代方式按当面说。
- **身份**：退出或切换身份时代际加一，中止在途请求与流，清空概览、卡片、提示与输入；旧代际的异步结果不回填。
- **入口选择**：`GET /v1/me` 的 `entry` 为 `minimal` 时，旧页（`index.html`）加载后跳到新页；`?classic=1`（新页的「更多」）与管理员入口 `?admin=1` 留在旧页。新页读到 `classic` 时回到旧页。旧页与其全部功能脚本保留一个版本，之后另起提交删除不再引用的脚本（功能页脚本保留）。
- **点击概览摘要**在对话里展开对应卡片：今天 → 列表卡；等我处理 → 确认卡、答复卡或按钮卡；进行中 → 进展卡；未读 → 通知卡。

## 提示（`dashboard/tips.py`）

随 `GET /v1/dashboard` 返回，确定性生成、不调模型，最多 3 条。按固定优先级：概览有块读不出时的状态提示（排最前，同一位置）→ 首次使用（主对话没有消息）→ 有事在等本人 → 今天有安排 → 本人可用的匠人（管家开启时，最多 2 个）→ 通用「记一件待办」。管家暂不可用（503）、额度用完（429）等由页面在请求失败时在同一位置补充，并说明概览、通知与「更多」仍可用。

## 开关（`minimal_entry`）

`enabled` 默认 false，`tenants` 默认空，空名单始终关闭；名单内租户必须同时开启 `butler`（配置加载时校验），因为新页的对话只经管家。未启用的租户仍是旧页。

## 已知限制

- 小院的角色设置只存本设备；工具归类按名称猜，业务包不能声明。
- 新建执行安排（非管家起草）、共享事项的成员与资料、交接的文件类动作、下载核验固定成果仍只在「更多」。
- 「等我处理」里的助手草稿最多统计最近 100 条；「未读通知」不含共享事项与协作通知流。
- 系统状态提示里还没有「连接授权过期」与「预算将尽」两类；目前只有概览读不出（服务端）与管家不可用、额度用完（页面）。
- 真实浏览器验收里「各模块在对话内查看与确认」需要真实模型，未执行；其余项见 [验收记录](../guides/releases/2026-11-14-r5e-browser-acceptance.md)。
