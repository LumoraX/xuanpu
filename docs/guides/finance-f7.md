# F7 发票与报销流转记录

当前F8按用户要求聚焦发票报销内部流转记录，不做支付。最新契约finance `0.9.0-f8`、74项API、7个Skill；见[F8指南](finance-f8.md)及[F8本轮验收](releases/2026-10-22-finance-f8-acceptance.md)。下文阶段记录保留原有验证范围。

F7阶段按当时要求只做内部记录。当时契约finance `0.8.0-f7`、72项API、7个Skill；财务服务发行`2026.10.22.4`，人工页发行`2026.10.22.3`。F7当轮实际门禁与运行范围见[F7验收记录](releases/2026-10-22-finance-f7-acceptance.md)。

员工可在对话中粘贴发票信息并说明报销事由，Skill按受控公司与分类准备草稿；金额和费用发生日期不清楚时补充说明，模型不能代填批准结果。`invoice_information`原样保留申报文本，显示为未查验；它不创建正式结构化发票，不防范跨单重复申报，不占正式票额，也不构成付款或记账资格。需要正式票据额度管理时，仍须使用原有受控结构化发票/分配流程。

无需模型时，在“财务记录与审批”新建报销，填写事由、明细和可选的发票信息。附件可上传到平台文件入口，再确认固定文件版本导入独立财务原件存储；取得接收回执后才关联报销。附件可选，资料缺失如实保留。上传平台文件成功不表示独立财务已收件，保留原受理操作查询，不重复新建。

申请人先核对资料和预检，再点击本人确认提交。分派的审批人登录，读取实际原件、核对发票申报和事由后逐级决定；申请人不能自审、后一步不能越级。需要补充时驳回并说明理由，本人修改后重新提交；历史批准不会沿用。当前审批完成显示“审批通过”，是内部流程完成，单据及历史继续留存。申请人仍可按已有规则撤回；没有删除历史或额外支付步骤。

“查看流转历史”分页读取每次不可变单据版本和实际人工决定，包括原费用、原申报信息、原附件、审批意见和时间；同时保留驳回、补充重提和撤回。历史版本没有记录操作者的字段时只显示保存事实，不从当前角色推算。附件下载每块验证当前权限及原字节摘要；角色撤销后不能继续下载，历史附件仅限当前仍有单据读权者查看。

## API 与存储

- `createExpenseClaim` / `updateExpenseClaim` 增加可选`invoice_information`（1–20000字符，非空白、合法UTF-8且不含NUL）。只允许公司制度`internal_record`，其它模式拒绝。草稿创建或修订不代替本人确认提交。
- `listExpenseClaimHistory`：GET `/v1/finance/expense-claims/{id}/history`，`cursor`和`limit`分页（1–100）；每项`id/kind/created_at/data`，kind为revision或decision，data为当时不可变内容。游标绑定当前租户、员工、公司和单据，total与页大小独立。人工页报销列表和完整原文历史每页1条，确保长申报可完整加载。
- `getExpenseMaterial`：GET `/v1/finance/expense-claims/{id}/materials/{receipt_id}`，仅human来源。`offset`从0开始，`limit`默认131072、最大262144；可选`document_version`读取历史版本实际关联的原件。返回base64分块、完整SHA与next_offset，不返回独立存储地址和凭据。Skill不暴露该原件工具给模型。

独立财务PG保有历史、决定和业务幂等，独立加密原件存储保有原字节；玄圃只提供身份、文件固定版本与入口。服务/业务包可停用，数据不会随开关删除。仅记录部署使用[轻量配置](../../docker/finance/internal-record.example.yaml)，替换真实员工并显式启用内部制度，无须配置支付/ERP/税务/档案通道。配置示例不代表已经部署。

当前不接入支付、记账、税务查验、法定档案或外部审批平台。既有其它阶段接口继续兼容，其隔离模拟证据与未验边界见[缺口台账](finance-gap-register.md)。企业微信/飞书未来仍可作为替换适配器，不改变独立记录归属；本轮未实现这些集成。正式生产、真实模型起草质量、异机容灾与法定票据标准另行验收。

## 重复验收

使用本机独立`finance_test`数据库和权限0600的DSN文件运行`scripts/finance_acceptance.py`；quick固定集已包含F7普通报销、签名API、实际CLI重启、契约、真实cookie入口及人工页行为，full运行全部packages测试。维护用例优先用本机成熟PG工具；本机未安装时须显式设置`FINANCE_TEST_PG_CONTAINER`为实际承载该测试库的本轮容器，不能依赖旧阶段容器名。容器名只允许字母数字及`_.-`，备份恢复仍使用测试中真实创建的独占数据库，结束删除。F7本轮实际命令与结果在验收记录中提供。
