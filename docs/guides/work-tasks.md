# 交办办公工作

管理员先发布普通版本化业务包`examples/office-assistant`并激活，执行环境使用办公Docker镜像。
员工登录后，在主对话添加本人文件并说明目标，例如“整理会议纪要，提出我的行动项”或“按部门列汇总金额列，
没有币种列，不要去重”。也可从“功能/交办工作”选择已上传的文件版本直接交办。

受理后会出现工作卡。关闭页面不会停止执行，重新打开“交办工作”可查看持久进展；停止须明确点击卡上的停止。
“等待你确认”时只批准愿意执行的操作。会议候选默认不勾选，可编辑标题及时间后选中本人记录；未选项不会创建。
全部取消仅保留纪要。日程提醒在选中该项时一并创建站内提醒，不会默认向外部发送。负责人不明确的记录须先核实。

成果通过卡上的下载按钮保存。会议提供纪要和行动项JSON；表格提供CSV、XLSX、报告及来源行证据。
输入固定到交办时指定版本；后续改文件不会悄悄改变计算材料，但确认旧候选时发现来源更新会要求重新生成。
摘要、行号和来源版本可由接口回执核对。行动项文件保留原始候选；确认卡展示平台按固定正本核对后的引用，最终创建以原生记录回执为准。

支持UTF-8 TXT/Markdown、DOCX、文本PDF，以及CSV/XLSX。一次最多8份材料、总计20 MiB；会议材料与表格分开交办。
扫描PDF须先提供OCR文本正本；加密PDF、无可提取文字页、公式、宏、外部链接和超限文档拒绝处理。
表格最多10个工作表、合计10000条记录、256列，金额最多12位整数和6位小数，用Decimal计算，不默认去重。
币种不同分别汇总，不作跨币种总计；缺失币种显示“未注明”。输出XLSX的金额用精确十进制文本保存，避免浮点精度损失。
CSV/XLSX的自由文本会防止被识别成公式；不支持的金额明确指出位置，不补零、不静默跳过。

默认R1策略下，“中断”表示服务重启等原因停止，不会自动续跑。“结果待核实”表示可能存在无确定回执的操作，须先核实，
不能反复点新任务来假定撤销。保存中断后仍可看到已成功上传的成果；部分成果缺失时不会显示成功。
模型不可用时，既有工作状态、文件下载和原生待办/日程的直接操作仍可用。

应用接入使用`POST /v1/work-tasks`受理并得到202与task_id，之后GET补读；相同request_id与内容返回同一任务，
改内容返回409。任务列表及事件每页最多100条。停止和决定分别使用`/{task_id}/cancel`、`/{task_id}/decisions`，
决定携带request_id及state_version。网络结果未知时保留原请求内容及标识重试；不要为同一次决定另造标识。
具体字段见[HTTP接口](../architecture/http-api.md)及[Python SDK](../../packages/xuanpu-sdk-py/README.md)。

部署者使用独立办公执行镜像：`docker/office-sandbox.Dockerfile`和带hash的`docker/office-requirements.lock`。
办公依赖仅装进执行镜像，平台不import业务包。当前本机local开发沙盒拒绝办公执行；生产必须选择Docker，
按既有只读包、断网、内存/CPU和宿主目录隔离要求部署。候选构建及验收证据见[R1验收记录](releases/2026-10-21-r1-acceptance.md)。


## 持久恢复试点（R2-A）

本期实现与本地验收完成后，生产仍默认关闭。部署者可在平台配置的`durable_execution`段设置
`enabled`，并在验收模型文本预算上界和网关限制后设置`verified_text_bounds`。
两项默认均false；不能只因模型网关可连通就开启预算验收标记。配置由服务端注入，员工及业务包不能更改。
后台模型请求明确关闭隐藏推理并限制单次输出4096 tokens；不透明推理回传或多模态输入会阻塞后续采样。

启用后新交办任务会持久排队，服务正常关闭后从安全阶段继续。执行中断时先确认旧环境退出，
再在新的隔离环境中重算；已完整冻结的成果只补上传，不重复调用模型。已有R1任务维持原策略。
预算不足、授权失效、材料/能力不可用或资源清理未确认时会停止推进，查看任务的execution.block_reason定位原因。
“结果待核实”始终需要核对下游；不要用重复批准或新call标识假定第一次操作没有发生。

需要续接工具批准时，部署者必须逐项登记已验收的无状态HTTP工具到`stateless_http_tools`；默认没有登记项。
脚本、文件、scratch及MCP相关批准本期不能跨重启续接，原批准内容与核查证据会保留。
模型不可用仍可查看状态、下载现有文件、取消、补齐已冻结成果和确认原生待办/日程。

应用可使用`POST /v1/work-tasks/from-capability`交办已发布只读能力，提交request_id、text和
`capability: {package, entry}`，可省略input_files。必须实际调用只读工具并保存回执才会成功；
结果通过result_summary/result_receipt读取，不要求制造空附件。该入口尚未新增独立控制台表单或SDK便利方法。
R2-A不包含定时、事件触发或外部写入自动重发。详细证据见[R2-A验收](releases/2026-10-21-r2a-acceptance.md)。
