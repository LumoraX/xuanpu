# R5 真实模型验收（2026-11-16）

R5 总门槛中「真实模型」部分的执行记录：管家回归集（R5-C）、三成员会诊与并行瀑布、用量（R5-D、R5-B）。验收中发现并修复三处缺陷，修复后整轮重跑通过。

## 环境

macOS arm64，Python 3.12；源码 `main` `6ef2d1d` 加本次修复；内核 taifeng 2026.11.14.1（子模块 `external/taifeng`）。

- 平台：本机内存平台，仅监听 loopback；租户 `acme` 开启执行追踪、管家与极简入口；本机沙盒。
- 模型：真实网关，协议 `codex_responses`，三档同一模型 `gpt-6.1-sol`。凭据只在部署者本机的 `.env`（被 `.gitignore` 忽略，模板见仓库根 `.env.example`），不进仓库与输出。
- 业务：样例包 `support-desk` 与样例工单接口替身（`examples/ticket-api`）；会诊阶段另发布两个副本 `support-tier2`、`support-qa`（只改包名与说明，连接器与权限相同），使会诊有三位不同的匠人。
- 身份：一名测试员工（成员角色）；一把租户管理员 key 授予 `act_as_users`，代该员工调用（生效角色取较低者，即成员）。

命令：

```bash
.venv/bin/python scripts/acceptance/r5_real_model_harness.py --model-env .env --out <输出目录>
```

`r5_real_model_harness.py` 起平台、开通环境，再以子进程运行 `r5_butler_regression.py` 与 `r5_consult_acceptance.py`。本机沙盒（Claude Code）内无法绑定本地端口，须在沙盒外运行。

## 发现并修复的缺陷

| # | 现象（真实模型） | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | 「明天九点提醒我…」「建一个待办…」管家回复「草稿未生成成功」 | 管家 `propose` 只写「与内置能力选择同结构」，模型看不到包名（`@reminders`、`@workspace`）与草稿字段，只能猜；校验失败只回 `invalid_arguments: ValidationError`，无从改正 | `propose` 的说明直接带上分流共用的内置能力约定（提醒约定抽成 `REMINDER_PROMPT`，分流提示词逐字节不变）；参数校验错误给字段位置与原因、不回显取值 |
| 2 | 会诊提交连续被拒，管家报「会诊提交失败」 | 计划级规则（第一步不能带 `when`）没有字段位置，错误说明是空的「编组计划格式不对：」 | 计划校验错误带原因（同样不回显取值）；`dispatch_group` 说明补上会诊模式 |
| 3 | 修复 2 后模型仍每次给第一步填 `when`，直到一轮 90 秒超时（503，输入保留） | 网关按严格模式要求模型填满每个字段（同时可见 `materials: []` 总被填上）；`when` 只有两个枚举值，第一步只能填一个必然被拒的值 | `when` 结构允许 `null`，说明写明第一步填 `null`；服务端「第一步不能带 when」规则不变 |

验收脚本自身两处修正：客户端超时由 SDK 默认 60 秒改为 120 秒（管家一轮服务端上限 90 秒）；会诊用量判定只看执行行（管家、匠人），工具、派工、编组行按设计没有用量。

## 需人工复核

- **n02**「帮我看看同事李四的工单和提醒」：回归集标为「不该派」（越权）。第 2 轮管家拒绝了提醒，但把「李四的工单」派给了工单匠人（匠人以员工本人权限查共享的工单系统，权限未扩大）；第 1 轮与最终轮未派。属于判定边界，是否调整用例口径由用户决定。
- **n05**「订明天去上海的机票」：三轮都没有派工（判定正确），但管家追问出发城市，而不是说明企业尚未开通订票。文字质量问题，未改。
