# R4 原生页面真实浏览器核对清单（2026-11-18）

本轮新增或改动的原生页面都已有代码层测试（Node 行为测试与接口测试），**尚未在真实浏览器里验收**。下面是逐项核对步骤与应看到的结果；结果请如实记录，未核对的不算通过。

## 准备

- 企业开启：`knowledge`、`capability_delivery`、`shared_matters` 的 `enabled: true` 且租户在名单里；准备一名管理员、两名员工（下称甲、乙）。
- 业务包用 `examples/support-desk`（清单已声明显示名「工单助手」与工具显示名）与 `examples/office-review`。
- 每项都在桌面宽度与手机宽度（390px）各看一次；切换账号后确认上一位的内容没有残留。

## 1. 显示名（ADR 0022）

| 步骤 | 应看到 |
| --- | --- |
| 甲新建对话，打开业务选择 | 选项显示「工单助手」，不是 `support-desk` |
| 会话列表与会话标题 | 显示「工单助手」 |
| 让工单助手改一张工单，触发审批 | 待确认卡显示「修改工单」，不是 `mcp__…`/`api__…` |
| 管家派工后回报 | 回报里称匠人为它的显示名 |

## 2. 功能 → 知识与记忆

| 步骤 | 应看到 |
| --- | --- |
| 「从我的文件登记来源」选一份 UTF-8 文本 | 来源列表出现，写明版本与段数；选 PDF 时提示只支持文本 |
| 「从共享资料登记来源」选一个共享事项与材料 | 来源标「共享资料」 |
| 检索一个词，勾选一两段，提问 | 回答下方列出 `[编号]` 对应的文件、版本、段落；材料没有依据时写明找不到依据 |
| 断网后再点提问，恢复后重试 | 不产生第二个问答；同一次提问只回答一次 |
| 删除一个来源，或让共享事项管理员移除乙 | 乙再提问时旧回答先被清掉，提示重新检索；检索不到原文 |
| 「记一条」 | 记忆标「本人陈述（未经材料核实）」；可删除 |
| 停用模型后打开页面 | 检索、来源与记忆管理照常可用 |

## 3. 功能 → 我的能力

| 步骤 | 应看到 |
| --- | --- |
| 甲有能力工作时打开 | 「我的能力工作」：计数、技术完成率、token；没有用量记录的写「无用量记录」，不写 0 |
| 「导出本人记录（CSV）」 | 下载 CSV，Excel 打开中文不乱码；只有本人记录、没有正文 |

## 4. 能力配置（管理员）

| 步骤 | 应看到 |
| --- | --- |
| 能力卡「分配给员工」选甲 → 核对 → 确认 | 先显示确认卡，确认后才提交 |
| 「发起评测」选 `examples/office-review/evals/suite.json` → 确认 | 显示评测编号；「查看评测结果」逐条显示通过或未通过 |
| 「发布给员工」勾选甲 → 预览发布 | 列出「甲：新开通 → 修订 1」及将停止的重叠发布；评测未通过时写明原因、不能确认 |
| 确认发布后甲新建对话 | 能用；乙没在名单里，用不了 |
| 「运行结果与发布」 | 按能力显示计数与用量；没有价格表写「未配置价格表，不估算」 |
| 「导出汇总（CSV）」 | 每行一个能力修订，没有任务或员工明细 |
| 「查看发布与分配」→「撤销发布」 | 先显示确认卡；撤销后甲新建对话被拒 |

## 记录方式

逐项写：通过 / 不通过（附截图与现象）/ 未核对。真实员工与真实材料的业务签收仍按 R4-G 单独记录，不因页面核对通过而视为完成。
