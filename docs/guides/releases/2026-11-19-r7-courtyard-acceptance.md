## 验收中发现并已修复

1. **旁白只留最后一句会丢掉要紧的话。** 第一次跑出「不会修改工单或优先级。」——模型把「做什么」与「不做什么」拆成两句。改为放得下（≤160 字）就整段保留，放不下按整句保留结尾；重跑后见上表。
2. **管家第一轮交代完就回话，匠人还在干活。** 真实 trace 里管家有两轮根（交代、被唤醒复核），原模型在第一轮结束时就显示「办完了」并重复两次。改为管家各轮与全部派工都到终态才算办完；后续轮显示为「复核」；匠人干活时管家端茶。
3. **结果摘录重复旁白并带 Markdown 记号。** 结果里先去掉已作为步骤讲过的旁白，再去掉 `**`、标题记号。
4. **span 全部结束后仍在等本人裁决。** 原来按 span 判断显示「办完了」；改为派工细节里还有未处理的提问、审批或裁决时显示「停在这儿，等你」，管家在圆桌边红色等裁决，不说办完。
5. **裁决项正文是各位的完整结论。** 经过里只给一句「几位匠人的结论分歧大，这事我不能替你定，请你裁决。」，各位结论去掉 Markdown 记号后折叠在「看各位的结论」里，「去处理」打开既有答复卡。

独立复核（另一位审阅者读代码）另发现 7 处，已在 `947fb8a` 修正：没配对的推理块可能进旁白（已去掉，宁可少一句）、旁白缓冲封顶、工具每步重取细节、信号跨派工沿用、展开的细节每帧收起、非 404 失败没记日志；说话约定在任务承载时对员工可见并计入指纹，写进[管家](../../architecture/butler.md)已知限制。
