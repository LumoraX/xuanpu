# F12 内部试用：收件中途撤权与故障续办

当前只作发票申报、报销材料和人工审批流转记录，不支付。finance业务包`0.13.0-f12`保持77项API、24内部操作与7个Skill；服务/镜像`2026.10.23.3`，人工页面未改行为，版本保持`2026.10.23.1`。正式公司、人员、环境尚未提供，本轮为隔离验收；实际结果见[F12验收](releases/2026-10-23-finance-f12-acceptance.md)。

## 员工收件与权限变化

员工仍可在对话中贴上发票信息、说明费用事实，或通过“功能 → 财务”人工辅助入口上传固定版本材料。系统独立保全原字节、准备本人草稿，本人提交后由分派人逐级确认。申报与附件保全不是票据官方查验，approved只表示内部审批完成。

后台收件在原件准备和回执事务中重新核对当前公司授权。下载或写原件期间撤权的，当前项明确failed/COMPANY_FORBIDDEN；其余合法收件继续。已经保全的责任索引、原件或回执仍保留，但失败项不取得材料可选资格。不会通过恢复权限自动补写成功或复活旧人工计划。

遇到失败先查询原收件项及真实错误，由当前责任人确认角色和材料后按当前权限补充或重提。COMPANY_FORBIDDEN不能靠换身份或模型调用解除。数据库、对象故障和失租约分别保留原错误行为，不都算权限问题。F12隔离结论限定内部支持材料，不对未开放的通用票据解析流程作同等承诺。

## 断线、重复确认和结果未知

收件已受理时保留原operation和幂等线索，只查原操作的逐项状态，不因页面断线或服务重启另建重复请求。材料是否可选仍由真实material_received及selectable决定，不能把已有密文或回执当作流程成功。

人工确认没有收到明确结果时，先核对原计划、原幂等键、本地operation和单据实际状态。可信人工入口按同一计划与请求核对；相同请求返回原操作，不重复推进。另一决定已先完成或版本变化时，应读取最新单据、核对实际理由，再由有资格的真人决定后续动作。模型不能代发、换键重建或把未知说成批准。

同一计划的重复确认只产生原操作。approve/reject竞争只有一个有效决定；页面显示或本地HTTP受理不是另一笔批准，也不能绕过当前分派、版本和授权代际。历史决定和原件继续留在独立财务存储。

## 运维与强制退出边界

沿用[内部记录配置](../../examples/finance-internal-records/config.example.yaml)、[F9准备](finance-f9.md)和[F11门禁/只读核对](finance-f11.md)。正式启动仍检查固定私有凭据与HTTPS、独立实例锁；check-config只结构，preflight只离线，通过仍not_verified。没有真实资料时保持模板受阻断，不生成正式身份或自动启用。

本轮实际执行以下仓库入口，未填写模板退出2并返回blocked、production_status=not_verified，不连接数据库或创建对象目录：

```bash
uv run python -m xuanpu_finance --config examples/finance-internal-records/config.example.yaml --preflight
```

F12隔离验收在原件已经完整落盘、回执事务尚未提交时强制结束实际产品CLI，并移除平台源文件。新进程等待真实持久租约自然到期后，使用责任索引与独立原件恢复原操作；不得为了加快上线而手改lease、回执、状态或批准。实际恢复耗时只说明该测试条件，不能作为正式RTO/RPO。

停机原件verify继续由受信运维执行，只认证当时的local字节及索引，不改业务/审批或API就绪结论。正常停止、SIGKILL进程、主机掉电、磁盘故障与异机恢复是不同层次；本轮未验写入中残留文件自动处理、掉电持久性或真实灾备。密钥须另行保全，备份恢复仍使用独立库与原件配套工具。
