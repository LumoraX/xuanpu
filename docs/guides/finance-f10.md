# F10 内部试用检查与恢复验收

本页保留F10阶段的版本与验收事实。当前业务包为0.16.0-f15；最新真实模型验收及版本以[F15指南](finance-f15.md)和[F15记录](releases/2026-10-23-finance-f15-acceptance.md)为准，正式资料缺项见[清单](finance-company-readiness.md)。

当前只记录发票申报、报销、附件及人工审批；不支付。业务包finance `0.11.0-f10`发布77项API和7个Skill，财务服务/人工页面版本`2026.10.23.1`。正式公司、人员、环境仍未提供，本轮只交付配置与隔离验收；具体执行层次见[F10验收](releases/2026-10-23-finance-f10-acceptance.md)。

## 内部员工与复核人

员工继续在对话中提供发票信息、报销事由和费用明细，由Skill准备本人草稿；原始申报保持未查验。真人确认提交、分派审批人逐步批准或驳回。也可通过“功能 → 财务”使用无模型的辅助入口，查看本人记录、收件和历史原件。两种入口共用独立财务服务、权限和流转事实，approved只表示内部审批完成。

“内部试用检查”供当前公司财务复核岗位reviewer主动读取；collector和普通approver无权查看公司的配置核对报告。平台管理员不会自动取得岗位资格。无权时页面说明所需岗位，不转用通用财务检查或自动给人授权。

报告只核对当前公司的资料、内部制度、有效分类、审批和异常责任岗位、申请人与审批链分离、授权代际、外部配置关闭与模拟关闭；同时展示当前模式、独占锁、原件与站内提醒任务实际状态。报告不显示人员账号、税号、地址、密钥、报销原文或原件。出现阻断时交实际配置责任人处理，不能修改报告结果来通过检查。

所有检查通过仍显示正式环境未验收。它不核验票据、不批准任何单据，不证明备份、独立凭据、生产SSO或异机灾备合格，也不自动切换enabled。运行状态可能在读取后变化，报告没有持续健康保证；公司配置摘要用于比较该公司持久配置与授权代际，不是签名证书或全实例证明。

## 准备与只读试用

沿用[内部记录模板](../../examples/finance-internal-records/config.example.yaml)和[F9准备步骤](finance-f9.md)。实际责任人填写公司、真实员工ID及岗位、版本化制度、独立PG和原件密钥/目录、受控身份及文件网关等。没有正式资料时保持模板受阻断，不能用测试身份代替真实授权。

仓库可直接验证未填写模板：

```bash
uv run python -m xuanpu_finance --config examples/finance-internal-records/config.example.yaml --preflight
```

实际退出2并输出脱敏blocked；不连接数据库、不建目录或启动任务。私有配置检查全部通过仍not_verified。上线由操作员另行选择正式环境，本任务没有部署。

独立实例先以read_only验证。启动仍会取得实例锁、检查兼容结构、迁移并注入显式公司/授权/制度配置；read_only限制业务写命令，不能解释为数据库零写入。签名鉴权防重放也会记账。核对实际配置和角色后，复核人读取当前报告；没有receipt/notification实际运行任务的测试应用会明确阻断，不把空任务当正常。

站内提醒故障或实例锁丢失现在使health返回503；不输出错误正文。健康HTTP200只表示已检查的服务状态，不能证明业务完成、票据验真或生产合格。内部报告额外核对任务是否已退出及外部执行器/注册表缺席。

## 配套备份恢复和撤权

停机维护使用既有独立库/local密文工具，详见[F4维护](finance-f4.md)。必须将密钥另行保全；不能仅备份平台库，也不能仅复制原件。维护持有与运行实例互斥的锁，恢复只允许空白目标库和不存在的新原件根，不覆盖已有数据。S3与异机恢复仍须另验。

恢复后先用与备份时相同的公司、授权、制度和密钥，仅替换DSN/原件根与mode。启动前后核对配置摘要、授权代际、历史版本及实际原件字节，随后以read_only读取；不能把启动注入新配置伪装成原状恢复。检查通过后是否启用由正式操作员另行决定。

撤权及恢复会递增授权代际。原审批预检与旧分派不会因为岗位恢复而重新有效；不能重复执行旧计划来绕过。申请人按当前单据状态撤回、重新提交后，由新分派人读取新版本并重新预检、本人确认。历史决定保留，不删除或改写。unknown请求仍沿用原幂等键核对，不创建重复业务。

## API和Skill

`getInternalRecordsReadiness`：GET `/v1/finance/internal-records-readiness`，必填`legal_entity_id`；仅internal_records实例和当前公司reviewer，仍要求可信身份。general返回403，disabled沿用503。存储投影在单一readonly repeatable_read事务中读取，同事务检查公司授权。配置无效返回blocked，数据库查询故障正常报错。

返回公司ID、内部profile、时间、固定检查/expense版本、当前配置摘要、有限运行状态及固定未验项；没有正文、凭据或人员名单。`finance-review` Skill可按需读取；403说明岗位要求，模型不能执行真人决定，也不能把not_verified写成通过上线验收。其他Skill继续先读capabilities，内部模式不调用支付、税务、档案或通用readiness。

实际公司/制度/人员、生产身份和独立凭据/IAM/网络、真实模型语义与生产负载、异机恢复仍not_verified。支付、ERP、官方查验/税务、法定归档和飞书/企业微信审批不属于当前记录流程的依赖。
