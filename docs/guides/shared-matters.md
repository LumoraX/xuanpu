# 共享资料与受保护对话候选

以下接口已进入候选代码，尚未生产发布。原生员工页面、通知、SDK及CLI已经接入候选代码；完整真实试点及生产发布仍待后续阶段，当前线上不能据此假定已有这些入口。

共享事项由明确员工持有，邀请另一位员工即可协作，无需先建部门。共享文件是明确选定版本的独立副本，保留SHA及历史，不跟随原件修改。删除原件与撤回共享分别操作；其他人已经收到的字节无法追回。

有读取权限的员工先通过 `POST /v1/shared-contexts` 选择事项和精确材料版本，确认后才能补读来源。每个上下文仅属于本人。共享主对话通过 `POST /v1/assistant/route` 提供shared_context_id及text、稳定request_id；回复和草稿保留来源，不能自动另存私人待办、文件、提醒或后台任务。普通个人对话仍独立使用，不混入共享内容。

业务阅读需管理员发布examples/shared-reader；为本人创建尚未使用的普通会话，再创建kind=runtime_session、runtime_session_id指向该会话的来源上下文。旧业务包不会自动获得共享工具，已经使用的会话不能补绑定来源。该阅读模式仅核对所选正文及UTF-8文本/JSON材料节选；其他格式请在原生页面阅读，不假设模型已经解析。

需要公开共享文本草稿时，在明确目标事项中原生确认固定助手消息。发布接口material-texts要求source_context_id、draft_message_id、name及操作号/事项版本；不接受客户端替换正文。目标参与者同时需要原来源当前权限，不能借转存给未获授权的人。

事项成员、来源范围或身份改变后，旧上下文可能失效。页面历史会显示权限失效提示，API返回shared_access_revoked，旧会话和旧草稿不能继续读取或发布。重新获得授权后重新选择来源开始新对话。模型曾经收到或用户已下载的内容不宣称能够回收。

操作发生版本冲突时重新读取并明确确认，不自动覆盖；网络重试沿用同一request_id。负责人关闭新共享灰度后，已有读取、撤销和撤回仍经过原有权限检查。


候选员工页面路径为「功能 → 共享协作」。新建后选择具体员工和范围：整事项，或只读资料包。资料包有独立名称，明确勾选正文固定副本及每个材料版本；未选择的材料不包含。接收人只看到已授内容，不看到原事项负责人、其他成员和其他材料。

「核对并开始阅读」先选择正文及最多8份精确材料版本；继续旧阅读可从「查看我的共享阅读」进入。结束阅读不能再启用。共享助手可读所选UTF-8文本/JSON的有界节选，其他文件在页面下载查看；提示未读时不要把答复当成完整解析。发布助手草稿时核对原文和目标，保留所有来源，不能借转存扩大其他人的可读范围。

来源动态在已有通知中心的「共享动态」中显示总数及未读数。撤权后通知、总数、导航和旧阅读均重新检查；失效时页面清空旧资料，需要重新选择。网络不确定时重试本次提交，记录变化时刷新并重新核对。

CLI命令及私有凭据说明见[命令行文档](../../packages/xuanpu-cli/README.md)，SDK方法见[客户端文档](../../packages/xuanpu-sdk-py/README.md)。这些入口共用同一员工权限，不需要临时配置部门。
