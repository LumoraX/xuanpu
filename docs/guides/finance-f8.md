# F8 发票报销记录的实际使用

本页保留F8阶段的版本与验收事实。当前业务包为0.16.0-f15；最新真实模型验收及版本以[F15指南](finance-f15.md)和[F15记录](releases/2026-10-23-finance-f15-acceptance.md)为准，正式资料缺项见[清单](finance-company-readiness.md)。

当前交付围绕内部发票申报、附件、报销流转和真人审批，不做支付。业务包finance `0.9.0-f8`，74项API、7个Skill；财务发行`2026.10.22.5`，人工页发行`2026.10.22.4`。本轮实际验证范围见[F8验收记录](releases/2026-10-22-finance-f8-acceptance.md)。

员工可以粘贴发票信息、填写报销事由和费用明细，上传附件或选择已收件附件，保存本人草稿，再预检并本人确认提交。审批人按当前分派查看原文与原件，填写意见后明确批准或驳回。驳回后由本人补充、替换附件并重提，两级批准完成内部流程。用户申报保持未查验，审批通过也不会产生付款、记账或官方验真。

## 附件和恢复

“我的收件记录”按当前公司显示本人的持久收件批次，整页刷新、关闭或离开表单后仍能找回。报销表单内“选择已收件附件”不重建表单；选择、取消或翻页保留未保存的事由和费用明细。已关联附件可移除；历史版本和旧原件不会因当前版本移除而删除。技术回执ID保留在折叠的可选区域。

收件状态与每份材料状态分开。只有服务端判断`selectable=true`的`material_received`项可选择；一个批次部分失败或取消不抹去已经保全的单项。文件名、类型、大小和摘要来自实际收件元数据。能选择表示责任索引齐备，原件下载仍会独立核对实际字节，不等于票据查验。

浏览器有限保存上传恢复线索，按租户、员工和公司隔离：每公司一个未决请求，单条最多8192字符、每员工最多10个公司。仅保存文件元数据、SHA、原请求编号、固定文件版本、收件幂等键和已知操作号；不保存原件字节、发票申报正文或令牌。该线索不授权业务访问，所有读取和执行仍经服务端复核。

平台上传结果未知时，主动恢复需重新选择相同文件，复用原请求编号；财务收件结果未知时复用原固定引用和幂等键并人工确认。已知操作号只查询。恢复不会自动重发；存储被拒、线索损坏、超限或身份变化会明确阻断新请求。放弃本地线索不删除服务端文件或历史。整页刷新不恢复尚未保存的报销正文。

## API 和 Skill

- `listSupportingMaterialImports`：GET `/v1/finance/supporting-material-imports`，必需`legal_entity_id`，可选`cursor/limit`，默认20、最大100。仅本人且当前公司有权的支持材料；返回`items/total/next_cursor`。列表total是批次数，每项total是文件数。count和items采用同一读取快照，按`created_at,id`倒序。
- `getSupportingMaterialImport`：GET `/v1/finance/supporting-material-imports/{id}`，返回兼容的`operation`及逐项`materials`。包含真实文件名、状态、receipt_id、大小、类型、SHA、`verification_state=not_checked`和可选标志；不提供对象地址或正文。

reviewer也不能查看他人的收件目录。Skill可以读取本人元数据并准备草稿或预检；原件读取和实际决定保持human来源。七个Skill、API、人工页面共用独立财务规则与数据。关闭财务集成不会要求玄圃使用财务数据库，平台不加载财务业务代码。

## 隔离验收入口

`scripts/acceptance/finance_browser.py`仅用于开发验收，要求显式私有DSN文件、loopback且`finance_test`前缀空白数据库，平台与财务使用真实HTTP。测试员工会话由专用夹具签发，平台构造时注入拒绝模型工厂，后台尝试分别计数且全部拒绝、实际模型调用应为零；并非生产登录、正式人员或真实模型验收。测试PDF格式有效，但不是正式税务发票。夹具登录与证据路由不加入产品服务。

固定quick验收增加F8材料、API、契约及入口门禁用例；full仍运行全部packages。实际命令、结果、浏览器截图、制品和清理以本轮验收记录为准。

当前内部记录的摘要检索、专用部署配置与上线准备见[F9指南](finance-f9.md)，原阶段验收事实仍以对应记录为准。
