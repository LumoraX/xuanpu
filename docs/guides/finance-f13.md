# F13 内部试用：独立原件目录边界与真人续办

当前只作发票申报、报销材料和人工审批流转记录，不支付。finance业务包`0.14.0-f13`保持77项API、24内部操作与7个Skill，工具名单和shell=false不变；服务/镜像`2026.10.23.4`，人工页面版本仍为`2026.10.23.1`。正式公司、人员和环境尚未提供，实际专项及最终门禁分别见[F13验收](releases/2026-10-23-finance-f13-acceptance.md)。

## 员工与审批人

员工继续通过对话或“功能 → 财务”辅助入口提交固定版本材料、准备本人草稿，并由本人提交和当前分派人逐级确认。持久收件、原件回执和独立副本仍由财务服务保存；平台源文件移除不删除已保全副本。材料保全不等于官方验真，approved只表示内部审批完成。

材料处理失败或原件读取返回OBJECT_PATH_UNSAFE时，保留原operation、原请求及实际逐项状态，不以另建请求、换键或人工改状态掩盖故障。原件存在不表示material_received或selectable成立。模型只核对持久事实并说明失败，不能读取原件正文、删除文件、替换链接、执行维护或代发批准。

受信管理员先核对独立原件目录，恢复合法目录和原文件后，再由当前有资格的人查询原operation和实际原件，按当前资格补充或续办。恢复文件不会自动恢复已失效的岗位、计划或人工决定；每一级审批仍须真实本人确认。恢复过程中不得手填回执、成功状态或批准。

## 本地原件边界

本地适配沿用原有AES-GCM/XF01、对象键、哈希目录与幂等语义。运行读写使用已打开root/shard的目录描述符和相对文件名，不跟随根、分片和叶子的符号链接。叶子只允许普通文件，FIFO/socket等特殊文件被有界拒绝；新对象在分片内私有临时文件写完关闭后原子创建，不覆盖既有密文。缺件仍为OBJECT_NOT_FOUND，认证异常仍为OBJECT_CORRUPT，异内容重放仍为OBJECT_IMMUTABLE。

可识别的不安全路径返回OBJECT_PATH_UNSAFE/500，响应不包含物理路径或正文。其它IO故障仍按真实错误传播，不保证所有替换竞态都返回同一码。内部支持材料写入坏路径沿既有规则形成failed/OBJECT_STORAGE_FAILED，不生成成功回执或成功事件，其余合法材料继续。S3适配不变。

支持macOS/Linux的POSIX dir_fd/O_NOFOLLOW，缺少必需系统能力时失败关闭。配置根目录祖先必须由运维信任与管理；服务账号与受信管理员独占原件根、分片和临时项的修改权。系统既有路径别名由受信祖先约束管理。

目录打开后若被改名，操作仍可能通过旧fd在被移走的原目录成功，不会跟随新植入链接；这不证明当前配置路径持续可达，也不会自动修复责任路径。恶意本机管理员、硬链接、挂载更换、磁盘掉电、写中孤立临时文件自动修复和Windows不在本轮安全承诺内。Linux仅有另列的基础文件IO演练，完整PG/CLI联合验收不得据此宣称已在Linux完成。

## 运维和验收边界

正式准备继续沿用[F9配置](finance-f9.md)、[F11启动门禁及停机verify](finance-f11.md)和[F12撤权/故障续办](finance-f12.md)。独立备份须配套数据库、原件和密钥；停机verify只核对当时local索引与密文字节，不批准单据、修复目录或验证生产可写性。

本轮真实CLI/loopback签名HTTP专项覆盖不安全路径拒绝、除认证防重放表外全部public表不变、测试管理员恢复文件后两级真人续办、原件独立性及停机只读核对。它们不代表浏览器、真实员工、真实模型、生产负载或异机灾备验收。本轮无页面行为变更。

真实公司/制度/人员、生产SSO/独立凭据/IAM/网络、真实模型语义、生产存储和恢复指标仍not_verified。支付、ERP、官方票据查验/税务、法定档案和外部审批继续不作为当前内部记录依赖。本轮仅本地提交，不推送、合并或部署。
