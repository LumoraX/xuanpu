# F9 内部报销记录配置与试运行

本轮聚焦内部发票信息、报销草稿、附件、真人审批和流转记录，不做支付。业务包finance `0.10.0-f9`包含76项API、7个Skill；独立财务服务`2026.10.22.6`，人工页面`2026.10.22.5`。实际验证结果以[F9验收记录](releases/2026-10-22-finance-f9-acceptance.md)为准。当前没有正式公司、人员和部署环境，交付可填写模板与隔离试运行，不代表生产上线。

## 员工与审批人的操作

员工在对话中提供原样发票信息、事由和费用明细，Skill读取实例能力、授权公司和费用目录后准备本人草稿。必要事实缺失时补充，申报保留`not_checked`。用户也可直接打开“功能 → 财务”，手动新建、上传或选择已收件附件；两种入口共用独立财务存储。

列表默认“本人记录”，每页20条摘要。可按状态、单号或事由搜索；“本人草稿”只显示自己的草稿，“全部可看记录”仍按当前公司授权和实际审批分派过滤。总数独立于当前页，搜索不扫描发票申报原文或附件。打开详情才读取完整申报、历史和原件。

本人查看预检计划后确认提交；审批人打开待审记录，核对事实和原件，填写理由后明确批准或驳回。驳回后本人修订补件并重新提交，两级审批重新开始。Skill、聊天确认、工具调用确认、实例能力或预检通过均不能代替人工决定。approved仅表示内部审批完成。

材料失败提醒只在当前公司本人的收件元数据中定位原异常，每次最多核对五批，较早记录由员工继续翻页；展示实际接收状态和原因代码，不能用其他批次替代。遇到网络故障可按同一游标重试。重新上传会形成新收件记录，不会自动解除原异常；提醒已读也不是异常完成。

## 准备独立实例

从[内部记录模板](../../examples/finance-internal-records/config.example.yaml)复制到操作员控制的私有配置目录，再填写全部`REPLACE_`字段并替换`.invalid`网关地址。模板默认`profile=internal_records`、`environment=production`、`mode=read_only`。保留这些边界；不能为了通过检查打开模拟或改成通用profile。

需要由实际责任人准备：

- 公司和平台租户的固定ID、正式公司名称与税号。
- 平台真实申请人、负责人审批人、财务复核人的user_id。申请人使用collector，审批人不能兼作本公司唯一申请人；审批顺序和费用分类由公司确认，制度修改递增版本。
- 独立PostgreSQL数据库/账号及DSN文件，不能使用平台库。服务启动前检查整个财务实例，不接受含通用发票、资金、外部操作、未完发票导入或通用执行计划的旧库。
- 独立财务服务令牌、平台文件/身份网关令牌、平台签名公钥及key_id。令牌分别签发、文件和字节均不可复用；签名私钥保留在平台保险库。
- 独立原件目录与32字节AES密钥文件。原件和密钥不可与平台共享；保存密钥的备份副本及恢复责任。秘密文件为普通私有文件（0600），不使用符号链接，不把密钥写入配置或聊天。
- 受控TLS网关、独立服务网络访问范围和只读部署位置。S3若替换local，必须填写独立桶、端点与独立访问凭据；当前模板使用local。

所有funding/settlement/compliance策略和供应商、业务目录、收款账户保持空。内部profile不会构造付款、记账、税务、档案客户端或worker，不登记其HTTP及回调路由。旧通用计划不能借共享执行入口穿过profile守卫。独立存储仍依赖在线企业身份校验，平台不可用时不会放行新业务。

## 离线检查与只读验证

在仓库根目录用模板执行离线检查：

```bash
uv run python -m xuanpu_finance --config examples/finance-internal-records/config.example.yaml --preflight
```

未填写模板应输出脱敏`blocked`并以2退出，不读取数据库、不建目录、不启动worker。填写后的私有配置用同一入口检查。全部checks通过时`status`与`production_status`仍为`not_verified`：只证明本地配置/凭据格式，未验证网络、实际数据库、身份权限、备份、制度或生产服务。

实际部署由操作员另行选择环境并确认，先以read_only启动。启动会取得独占锁，以只读快照检查整个实例兼容性，再运行明确的迁移/配置写入；发现通用数据或未知旧表结构即拒绝，不自动清理历史。请先做好独立备份，并在隔离恢复副本上检查版本兼容性。

平台侧安装相同finance业务包，配置受限HTTP连接器的独立服务令牌、签名issuer/audience/key_id及允许的origin；使用真实员工cookie验证capabilities、授权公司、本人记录与待审。平台管理员不自动获得财务正文权限。未准备正式人员时，不用测试员工替代。

read_only下读取正常而新草稿、预检和执行拒绝。核对公司/角色/审批制度、网关在线撤权、原件隔离与恢复后，由操作员明确决定是否将同一私有配置改为enabled并重启；这是上线操作，当前任务没有执行。修改授权、制度或mode需要重启，旧计划仍会复核版本和当前权限。

## 备份、停用与回退

备份必须同时覆盖独立财务数据库、原件密文及密钥，保留制度、角色映射与发布版本。备份加密并限制读取，分别记录数据库恢复和原件SHA核对结果；有备份文件不等于恢复验收通过。不得仅恢复平台库来恢复财务。

暂停新业务时改为read_only并重启；完全关闭员工财务入口可用disabled或停用平台finance集成，原记录不删除。先确认在途收件已保存或可恢复，再停止实例。未知执行结果复用原计划/幂等键查单，不重新创建批准。

应用回退前保全当前数据、原件、配置与版本，在隔离副本确认旧服务支持现有schema和内部profile；不能直接用早期通用服务绕过profile。若不兼容，保持read_only/停用并制定迁移方案，禁止通过删表或改历史单据模式使检查通过。

## API、Skill与验收边界

`getFinanceCapabilities`返回`profile/mode/service_version/internal_records_only`，仍要求可信员工身份。它是实例元数据，不是个人权限、审批决定或生产就绪报告。

`listExpenseClaimSummaries`要求`legal_entity_id`，支持`view=mine|visible`（默认mine）、六种既有status、`q`（trim后最长128）、cursor、limit（默认20、最大50）。q按字面量忽略大小写匹配单号/事由，`%`和`_`不作为通配符。响应只含九个摘要字段，不带原文、明细、流程或对象地址；旧详情和历史契约不变。游标绑定身份、公司和筛选，变更筛选重新分页。

专用隔离入口仍是`scripts/acceptance/finance_browser.py`，只接受loopback、`finance_test`前缀空白库和0600的DSN文件；使用显式测试人员、测试PDF、真实HTTP/cookie/CSRF/签名出口，所有模型入口拒绝。不会注册测试登录路由到产品。配置的离线报告随私有ready文件提供，正式状态保持未验。

仍待真实资料和环境验证：公司制度与人员授权、生产SSO/网络/凭据/IAM、真实模型语义、生产负载和异机恢复。外部支付、ERP、官方查验、税务、法定档案及飞书/企业微信审批不属于本轮依赖；未来按可替换接口单独验收。
