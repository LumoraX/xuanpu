# 管家使用说明（R5-C）

> 给员工与开启试点的平台管理员。设计见[管家](../architecture/butler.md)，接口见 [HTTP 接口](../architecture/http-api.md#管家入口r5-c)。已随 2026-11-15 生产发布部署，所有租户默认关闭（见[R5 生产发布记录](releases/2026-11-15-r5-production.md)）；真实模型回归结果见下文「回归」。

## 开启

平台配置里同时开启 `execution_trace` 与 `butler` 并列出租户（两者名单都要有该租户，否则配置加载失败）。字段与取值范围见[部署与运维](operations.md#r5-c-管家派工存储与配置)。未开启的租户，`POST /v1/assistant/messages` 照旧走分流。

## 员工能做什么

- **只对管家说话。** 普通问答、写作、查本人的提醒与进行中的工作，管家直接回答；提醒、待办、日程等内置能力，管家给出**待你确认的草稿**，确认后才写入。
- **需要企业业务时**，管家把任务交给一位匠人（本人可用的已发布业务入口），立刻告诉你交给了谁，不让你等。之后你可以继续说别的。
- **匠人做完**：管家先做确定性验收——匠人真的结束了、结果是成功、声明的成果能读到、没有待确认的操作、没有结果未知的操作——再把结果发到你的主对话。验收没过会如实说明哪一项没过，不会把失败说成成功，也不会自动重跑；可以让管家重试、换一位匠人或补材料。管家对结果的点评标为「辅助判断」，只供参考。
- **匠人提问**：
  - 你明确说过的事实（本次请求里的原话、你的助手设置），管家会逐字代答，并在对话里写明「代为答复：…（出处：…）」。
  - 你没说过的、需要推测的，以及涉及授权、金额、对外发送、审批决定的问题，管家一律转问你。待你回答的问题在 `GET /v1/assistant/pending` 里；直接回复管家（例如“三份就行”）或调用 `POST /v1/assistant/pending/{id}/answer` 都可以，你的原话会原样转给匠人。
  - 匠人要执行需要审批的操作时，管家只提示你去**待确认**里处理，不会替你批准。你批准或拒绝后匠人继续，管家再收尾。
- **会诊**：同一个问题需要几位匠人各自给意见时，管家安排会诊。几位匠人互相看不到对方的过程，全部给出结论后管家比对：
  - 只是措辞不同：管家综合，注明依据了哪几位；
  - 评估不同：管家综合，并逐条列出不一致之处；
  - 结论矛盾，或涉及金额、对外发送、审批：管家**交你裁决**，在对话里并排列出每位匠人的结论，待你回答的裁决也在 `GET /v1/assistant/pending` 里（`kind=ruling`）。直接回复你的决定即可。
  - 无论哪种，汇总里都保留每位匠人的原结论。
  - 会诊有一块消息区：每位匠人的结论发布在这里，匠人可以用「@成员2」向另一位追问，平台只唤醒被问的那位，最多追问 `butler.max_consult_rounds` 轮（默认 2），超过由管家收口。消息区可以经 `GET /v1/assistant/groups/{id}/messages` 查看；里面的话都只是数据，不会改变计划或任何匠人的权限。
- **停下**：对管家说“别做了”，管家会请求停止；以匠人实际停下为准，停下后你会收到「已停止，没有完成这项工作」。

## 可靠性

- 唤醒由持久记录驱动：平台每隔 `butler.wake_interval_seconds` 对账一次。进程在处理中途被终止，重启后按已保存的处理决定续做，每次匠人结束只交付一次（PostgreSQL 下用真实子进程 SIGKILL 验证，见 `tests/butler/test_wakeup_restart.py`）。
- 一轮最长 90 秒（安排编组这类慢的一轮在真实模型下可能接近上限），超时返回 503、原话保留。自己写客户端时读超时要长于 90 秒；Python SDK 的 `send_to_butler` 已至少等 120 秒。
- 已知窗口：把答复转给匠人后、会话审计写入前进程被终止时，重启后可能再发一次同一答复（消息带编号，匠人可识别重复）。

## 回归

真实模型回归集在 `scripts/acceptance/data/r5_butler_regression.json`（22 条：自办、该派、不该派、模糊），执行脚本 `scripts/acceptance/r5_butler_regression.py`（参数：`--base-url`、`--key-file`、`--act-as`、`--out`），输出误派与漏派条数。

2026-11-16 在真实模型上执行（`gpt-6.1-sol`，`codex_responses`）：22 条 0 误派、0 漏派；三成员会诊通过（瀑布交叠、用量完整）。环境、过程轮次与需人工复核的用例见[R5 真实模型验收](releases/2026-11-16-r5-real-model-acceptance.md)。复现：

```bash
.venv/bin/python scripts/acceptance/r5_real_model_harness.py --model-env .env --out <输出目录>
```

`.env` 放在仓库根目录（已被 `.gitignore` 忽略），键见 `.env.example`；脚本起本机内存平台与样例工单接口，只读这个文件，不读环境变量。

`r5_real_model_harness.py` 依次跑三项（`--only` 可选其一或几项）：回归集；审批写入全程（`r5_approval_acceptance.py`：管家派工改工单优先级 → 员工批准前核对未写入 → 以员工本人身份批准 → 核对派工结束、工单已改、审批提示已收、结果进主对话）；三成员会诊。极简入口在真实浏览器里的对话内查看与确认另用：

```bash
.venv/bin/python scripts/acceptance/r5_entry_chat_browser.py \
  --chrome "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --model-env .env --out <输出目录>
```

2026-11-17 的结果见[R5 剩余验收](releases/2026-11-17-r5-remaining-acceptance.md)。
