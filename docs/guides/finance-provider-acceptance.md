# 财务供应商正式接入验收清单

本清单是工程交付和证据要求，不是上线许可或法定合规结论。当前没有选定真实供应商；所有行初始状态均为`not_verified`。由公司明确指定实际负责人，不能用下表岗位名代替真实授权。支付、ERP、税务、档案应分别建接入工作包，各自绑定公司、adapter_version、configuration_version、实际制度和有效期限。

## 工作包需要交付的材料

## 接入顺序和失败处理

1. 保持正式能力关闭，先填写真实负责人、公司/作用域、供应商及固定版本；获取制度、权限和沙箱材料。
2. 运行F6离线检查，再由同公司reviewer读在线当前配置检查。二者仅发现配置缺口，`production_status=not_verified`必须保留。
3. 在隔离测试库跑可重复验收入口；保存源码/制品/配置摘要、实际JUnit及日志，财务skip、失败或证据缺失均不能作为通过。
4. 真实供应商使用单独授权的环境/账户/金额/期限逐项执行上表，不把隔离工具切换为任意正式POST工具。固定通道配置改变应新版本并重新验收，原在途请求继续原版本查单。
5. 企业依据真实证据另行批准正式切换；本清单和任何自动检查均不自动开通通道。切换后逐单仍需原业务审批、专用批准和经办确认。未知结果保留、查原号，不靠重发消除未知。
6. 证据不一致时保持该能力关闭；记录原回执/差异、撤销未执行资格并核对在途。已付资金不能通过删除记录或改变内部状态声称撤回。

证据包应保存作用域、制度/通道/适配器/制品版本、运行时间、真实步骤、预期与实际、原请求号、证据摘要、负责人及外部批准引用。只记录必要脱敏信息，不提交私钥、数据库DSN、Bearer token、完整个人银行账号或受保护原件到源码仓库。正式秘密独立保管；财务原件保留在自己的加密存储。
