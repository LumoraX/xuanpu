# 本地真实模型与飞书登录

本工具供管理员配置一次，员工随后只需打开控制台并用飞书登录。它启动真实玄圃服务、持久化 Postgres 控制面和本地样例工单接口；不是模拟登录，也不会自动把首位登录者设为管理员。

## 管理员准备

在仓库根目录执行 `uv sync --all-packages`，并启动 Docker。工具使用 `postgres:16`，缺少镜像时 Docker 会拉取；没有可用 Docker 会明确失败，不会改用内存数据库。

把真实凭据保存在仓库外的 JSON 文件，并限制为仅本人可读写（`chmod 600 /你的私有路径/input.json`）。格式如下，尖括号是要替换的占位值：

```json
{
  "model": {
    "base_url": "https://<模型网关>",
    "api_key": "<模型密钥>",
    "name": "<模型名称>"
  },
  "feishu": {
    "app_id": "<飞书应用 ID>",
    "app_secret": "<飞书应用密钥>",
    "encrypt_key": "",
    "verification_token": ""
  }
}
```

普通用户不需要填写协议、租户或服务地址。管理员输入中 `model.protocol` 默认为 `codex_responses`；兼容其他网关时可显式选 `responses` 或 `chat`。网关只有域名时自动补 `/v1`，已有自定义路径则保留。三个模型档位使用同一模型与协议。

飞书应用使用官方地址；两个事件密钥各自可留空；已有的 Verification Token 可以保留，缺少任一项时只提供登录，事件回调关闭。之后补齐 Encrypt Key 与 Verification Token 再重启，即可启用加密事件；不支持明文事件。权限、应用可用范围、通讯录范围和首位管理员操作见[飞书登录接入](feishu-login.md)。

## 启动、查看与停止

在本仓库根目录，使用同一个 Python 环境中的真实 `xuanpu` CLI：

```bash
uv run python scripts/local_trial.py up --input /你的私有路径/input.json
uv run python scripts/local_trial.py status
uv run python scripts/local_trial.py down
```

默认控制台为 `http://127.0.0.1:8420/console/`，租户为 `acme`，工单接口绑定 `127.0.0.1:8431`，Postgres 绑定 `127.0.0.1:25432`。启动完成后自动显示控制台、飞书登录回调和事件地址，以及管理员凭据文件的位置，**不打印凭据值**。本地回调是 `/v1/auth/feishu/callback`，事件地址是 `/v1/identity/feishu/events/acme`；回环地址无法接收飞书公网事件，正式事件接入仍需公网 HTTPS 部署。

样例发布版本固定为 `1.0.0-local.<工单端口>`；重启不会自动升级仓库中新修改的样例内容，需要管理员另行发布新版本。

首次启动自动迁移控制面、建立 `acme` 和管理员 API key、配置保管库及飞书、发布并激活 `support-desk` 样例包。这个 key 是管理员进入 `/console/?admin=1` 初次连接控制台和管理员工使用的后台凭据；员工仍需本人通过飞书授权，首次登录保持成员角色。

重复 `up` 在输入一致且两个进程都属于本工具时复用运行实例。修改模型或飞书配置时，先 `down`，再用更新的 JSON 执行 `up`。更新保留数据库、根凭据、管理员 key 和保管库主密钥；不要删除配置文件来更换模型密钥。重启后旧会话仍属于原协议，切换模型协议后请新建会话。

默认运行目录为 `~/.local/share/xuanpu/local`（0700），配置、凭据与输入副本为 0600。`credentials.json` 包含后台凭据；`config.json` 包含模型凭据、数据库连接和保管库主密钥。请作为一个整体备份，不能把它们提交到仓库或粘贴到聊天。平台日志在 `platform.log`，工单日志在 `tickets.log`；工具过滤已知配置密钥，但日志仍可能有会话内容与其他敏感业务信息，不宜公开。

`down` 核对 PID、启动时间和命令后优雅停止服务，停止专属 Postgres 容器，**保留其 named volume**。它不停止其他开发服务、不删除数据库。工单样例本身使用内存，重启会恢复两条样例工单；平台会话、审计、用户、密钥、业务包与本地会话数据保留。

## 管理员高级选项

可用 `--runtime` 指定仓库外私有目录；同一部署的后续 `up/status/down` 必须使用相同目录。`--port`、`--ticket-port`、`--postgres-port` 可覆盖端口。已有部署的 Postgres 映射固定，后续启动须沿用首次选择；平台或工单端口可在停止后调整。端口已被占用时工具会拒绝接管，不会杀掉原服务。输入变化但仍在运行、进程归属不符、配置丢失、管理员凭据失效时也会停止并要求管理员处理，不会静默重置。

单实例本地状态存储用于兼容 Responses；控制面始终是 Postgres。这不是多副本或云端部署工具。实际模型请求会发往所配置网关；首次试用只使用样例工单。模型联通、工单查询、脚本、审批和真实飞书登录分别验收，模型可用不代表飞书授权已完成。
