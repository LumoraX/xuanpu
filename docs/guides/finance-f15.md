# F15 真实模型发票与报销 Skill 验收

本轮范围是内部发票申报、材料和报销流转记录：不支付，财务数据库和加密原件独立，提交、驳回及每级批准由单独人工身份确认。正式公司制度和实际人员尚缺，见[资料缺项清单](finance-company-readiness.md)；合成测试值不能作为正式配置。

## 真实调用与判定

验收运行器使用已配置的真实网关模型，经生产GatewayModelClientFactory、公开主对话分流、公开会话消息、实际Skill和财务HTTP访问专属测试PostgreSQL。主对话分流只建会话，业务回合另行发送。每个实际模型请求、原始事件、工具调用、签名来源与独立持久状态检查分别留证。测试员工cookie与签名走实际认证/CSRF链路，但身份是明确合成的；HTTP用户流程不等于浏览器点击、正式SSO或真实员工签字。

完整场景包括事实不足澄清、PDF上传与独立收件、模型选择材料并准确起草、修订与提交预检、本人确认、负责人驳回、补充后重提、负责人和财务分别预检/确认、新会话查询历史，以及源附件移除后的独立原件读回。票据申报中的指令、要求代批/付款及无权员工查询作为负向挑战。实际草稿、版本、决定、来源和零付款/入账/正式票据写入是业务门槛，不能仅以自然语言回复或HTTP200通过。

模型工具许可只用于草稿写入和预检。测试人驱动器从公开人工入口分别扮演申请人、负责人、财务；模型不取得这些cookie，不能调用executeFinanceAction或原件下载，也不能将工具确认升级为业务批准。

## 开发验收资源

`scripts/acceptance/finance_model.py`为显式opt-in开发运行器，不会由常规pytest隐式调用付费模型。仅接受本机空白`finance_test`数据库和私有配置文件，仅读取现有配置的models段；不复用原平台数据库、员工身份或财务数据。每次旅程使用新数据库、状态目录和身份，跨探针、失败与重跑使用同一个持久用量账本。

单旅程最多120次stream和1200秒，单模型请求最多90秒、4096输出tokens及256KiB请求JSON。整轮全部尝试最多240次stream、5400秒模型阶段、报告input累计300万/output累计15万tokens、请求32MiB/模型事件128MiB；具体预算及异常停止规则见[F15设计](../superpowers/specs/2026-10-23-finance-f15-design.md)。字节不冒充精确token估算；实际usage缺失即停止。私有网关价格未知，不承诺货币金额，不自动充值、扩额、换模型或隐藏重试。

现有F8/F9浏览器运行器仍严格禁用模型，证明人工入口在模型不可用时能工作；它不能替代本轮真实模型证据。两类验收互不冒称。正式供应商、官方票据标准、生产SSO/IAM/网络、生产负载、实际S3和异机恢复仍须单独验收。


## 当前效率修订与未完成项（2026-10-24）

普通internal_records报销由根入口直接查询、起草/修改及准备本人或当前审批人的计划，不默认委派子Skill。根工具从1项调整为原expense/review已有13项，整包模型可调用API并集仍68项；77项声明、24内部操作、7 Skills、shell=false及业务授权保持。缺新草稿事实时纯追问；同会话未变目录仅作定位线索，修改仍取当前授权详情/版本。用户改单据事由对应draft.reason，行事由与审批意见分别处理；用户问历史意见时须覆盖所问各轮真实人工决定，取消步骤不当作人工决定。查询q只按当前单号/事由字面，类别或旧事由线索默认本人无q查询。

原240次总调用、单业务会话20万tokens未提高。前三阶段从35次/205306tokens降为10次/83000及10次/84738，见[部分效率计量](releases/evidence/finance-f15-2026-10-23/partial-efficiency-comparison.json)；两次整条仍失败，不能据此声称完整验收通过。当前208次调用、206次完整usage和2次未知；余32次保留，停止进一步真实模型消费。final8已走到两级人工批准、零付款/入账及独立原件回读，但新会话答复遗漏旧驳回意见，09/10负向挑战未执行。最后历史答复修订仅离线验证，最终新源真实完整双轮与本地完成提交仍待完成，实际门禁和制品见[当前验收记录](releases/2026-10-23-finance-f15-acceptance.md)。
