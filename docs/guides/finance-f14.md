# F14 内部试用：维护凭据安全与恢复后真人续办

本页保留F14阶段的版本与验收事实。当前业务包为0.16.0-f15；最新真实模型验收及版本以[F15指南](finance-f15.md)和[F15记录](releases/2026-10-23-finance-f15-acceptance.md)为准，正式资料缺项见[清单](finance-company-readiness.md)。

当前仅作发票申报、报销材料和真人审批流转记录，不支付。finance业务包`0.15.0-f14`保持77项API、24内部操作与7个Skill，工具名单和shell=false不变；服务/镜像`2026.10.23.5`，人工页面仍`2026.10.23.1`。本轮实际专项与最终交付状态见[F14验收](releases/2026-10-23-finance-f14-acceptance.md)。

## 员工与审批人

员工继续通过对话或“功能 → 财务”提交固定版本材料、准备本人草稿，并由本人提交、当前分派人逐级确认。独立原件保全不等于官方验真，approved只表示内部审批完成，不表示付款或入账。恢复后保留原operation、原receipt、申报原文和理由，不换键重发未知结果，不手填回执、批准或业务状态。

备份、恢复或停机核对失败时，保留实际失败码与原操作线索，交受信管理员处理。模型不得读取数据库凭据或AES密钥、调整权限、修复文件、执行维护或代发批准；不要将凭据贴进对话。管理员核对配套备份、独立密钥及实际维护结果后，再由当前有资格的人查询原请求、读取实际材料并逐级真人续办。维护成功不等于业务批准或生产验收；恢复文件不会复活失效的岗位、计划或决定。

## 受信管理员与固定凭据

备份和恢复沿用[F4维护步骤](finance-f4.md)，停机核对沿用[F11 verify](finance-f11.md)，本地原件目录沿用[F13边界](finance-f13.md)。财务数据库、原件存储与密钥独立于玄圃平台；管理员应持有匹配的数据库/原件备份包和独立AES密钥，备份包不包含密钥。不覆盖旧库、不自动启动业务worker；目标必须符合既有空库/目录要求。

F14使backup/restore与既有固定凭据安全读取一致：连接数据库、调用PG工具和建立维护暂存目录前，安全捕获DSN与AES一次。固定叶子必须为不跟随符号链接的普通文件，拒绝目录、FIFO、socket等特殊文件；每文件最多65536字节，必须非空且私密，建议权限0600或0400，拒绝0644及组/其他用户权限。DSN按严格UTF-8解码并去首尾空白后不得为空；AES必须为32原始字节。不要将文本编码、换行或错误长度当作AES密钥。

配置凭据的祖先路径必须由受信运维管理。此次沿用固定叶子读取，不承诺防御恶意管理员或祖先替换。每个文件只读取一次，读取后路径变化不影响本次捕获值；这不等于多个文件原子轮换。跨文件一致轮换须通过受控部署完成，不能靠运行中替换两个路径碰运气。

## DSN与有限失败

backup/restore继续使用维护DSN规则：支持既有`sslmode`、`sslrootcert`、`sslcert`和`sslkey` query白名单，拒绝未知或重复选项；保留编码密码和端口语义。verify继续使用更严格的DSN规则，禁止全部query；不要把维护TLS配置直接移给verify。选项解析兼容不证明真实TLS握手、证书链、网络或生产IAM已经验收。

| 结果 | 处理边界 |
| --- | --- |
| `MAINTENANCE_INPUT_INVALID` / 退出1 | 固定文件读取、类型、权限、大小或文本格式不合法；管理员核对原配置，模型不得修权限 |
| `KEY_INVALID` / 退出1 | 安全读取的非空AES文件字节长度不是32；不是更换任意密钥继续尝试的许可 |
| `MAINTENANCE_FAILED` / 退出1 | backup/restore未知程序故障的有限JSON；仅含status/code，不输出原异常、路径、凭据或堆栈 |
| `RESTORE_FAILED_DATABASE_MAY_BE_COMMITTED` / 退出1 | 数据库可能已提交，先核对真实数据库/对象/包和错误边界，不可盲目重试或宣称已回滚 |
| verify `VERIFICATION_FAILED` / 退出1 | 未知核对故障保持有限失败，不表示业务事实已修复 |

已知错误继续返回原稳定code；参数错误退出2，verify incomplete仍退出2，成功回执语义保持。backup既有只读路径与目标冲突检查顺序保留，不保证坏凭据先于参数错误。实际维护结果应按回执、库/密文和原请求核对，不能仅凭退出码或目录存在宣称业务成功。

## 本轮验收和未验边界

专项覆盖坏凭据在单测连接/PG工具/暂存边界前拒绝、真实CLI八种坏输入拒绝与数据不变、合法配套备份恢复，以及恢复目标上agent逐级403和实际签名human逐级确认。真实CLI的库/密文快照不变不能单独推导“从未连接数据库”；零连接是单测spy边界证据。测试human是隔离客户端真实签名来源，不等于正式员工SSO或真实人员验收。

本轮无页面行为变更；CLI/loopback HTTP专项不是浏览器、真实模型或Linux完整业务验收。最终.5安装镜像的8项坏凭据CLI演练已通过，见[基础演练证据](releases/evidence/finance-f14-2026-10-23/linux-final-image-credentials.json)；其范围仍不扩展为Linux全业务或生产验收。正式公司/制度/人员、SSO/独立凭据/IAM/网络、真实模型语义、生产负载、生产存储、实际S3/异机恢复与正式部署仍not_verified。不支付、独立存储、真人审批不变；支付、ERP、官方查验/税务、法定档案和外部审批继续不作为当前内部记录依赖。
