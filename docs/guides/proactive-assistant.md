# 使用主动业务助理

直接在对话中说明工作，例如“下午把项目报价发给客户”或“等供应商给我交期后再确认”。即使未创建待办，助手也会按后台检查节奏识别需要跟进的承诺。通知会显示判断原因和原始对话依据；没有完成记录时会询问进展。

收到通知后点“处理”，可以确认完成、延后、设置提醒、记录新进展或忽略本阶段。也可以在对话里告诉助手你的决定，核对建议卡后确认。时间安排在确认后才保存，刷新页面仍保留；完成后相应跟进停止。

“功能 → 业务跟进”可查看关注事项和已处理记录。“助手设置”可以关闭主动跟进、暂停某类提醒、设置免打扰和选择已有通知渠道。站内通知始终可用，飞书只作为可选出口，员工不需要填写任何密钥。

默认规则为：有截止待办在截止、逾期1小时、1天、3天分阶段关注；无截止待办按3天、7天、14天未记录进展关注。改标题不会重置进展时间。语义评估默认每用户30分钟一次，检查扫描默认60秒一次；不是即时或硬实时承诺。

## 运维与验证

新增数据库迁移0008，升级应先备份并执行迁移，再更新服务。主动状态与通知保存在现有PostgreSQL，模型仍使用原配置。服务器配置项为 `proactive_interval_seconds` 与 `proactive_scan_seconds`，普通员工不需要调整。

本次实际运行过的验证入口：

```bash
uv run pytest -q packages/xuanpu-server/tests/proactive packages/xuanpu-server/tests/identity/test_proactive_flow.py
```

浏览器场景使用脚本模型和模拟身份源验证界面操作；真实模型验收必须另行使用当前模型配置，并记录调用、证据、通知、完成停止与持久化回执，不能以浏览器脚本代替真实模型结果。
