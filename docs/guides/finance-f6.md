# 财务F6：接入准备与端到端验收

F6沿用独立财务PG/加密原件、进程外API、7个Skill、实际员工HITL。它提供接入检查和可重复隔离验收；正式支付、ERP、税务、WORM和外部审批尚未选定供应商，仍需按[正式接入清单](finance-provider-acceptance.md)取得真实证据。

## 两类只读检查

离线检查使用受信运维配置文件及其中固定凭据路径，补充结构校验之外的资源检查；不连接数据库、平台或供应商，不迁移、不启动worker，不产生任何财务动作。私密文件须限制权限、令牌不可复用，公钥/AES/回调秘密有明确格式和长度要求；报告不包含秘密、凭据路径或数据库连接正文。

在线`getFinanceReadiness`由当前同公司reviewer读取当前持久配置，包括岗位、审批链、制度及通道版本/代数/启停、账套期间、受控账户和资金场景能力。它依赖真实独立库快照，配置变化后摘要变化；撤权立即失去报告访问权。模式、锁丢失和后台任务健康与业务配置分别反馈。

模块处于disabled时，包括在线检查在内的员工API仍按原约定返回停用；运维可用离线preflight诊断配置，不因此打开模块。

配置检查通过不代表某个单据可付款，也不代表供应商已正式验收。报告始终保留`production_status=not_verified`及外部待验项，没有将外部证明手工标passed或用检查结果自动放行的接口。付款、记账、税务和归档继续走原固定计划、人工批准与执行确认。

## 隔离验收的范围

仓库验收入口只接受显式本机测试DSN文件与新输出目录，在执行pytest前核对真实数据库名以`finance_test`开头。quick使用固定真实HTTP、cookie/CSRF、资金专用场景、归档补包、备份恢复、生命周期及双向数据库凭据拒绝模块；full执行整个仓库测试。报告由实际JUnit归纳测试数、失败、错误和跳过，并记录源码状态、固定模块、时间和证据SHA；没有JUnit、零测试、财务skip或子进程失败不能显示passed；full中的既有非财务skip只能显示partial/有skip。

两库/两角色测试仅在本轮明确的隔离管理库创建随机临时资源，撤销继承CONNECT后验证各自成功、双向拒绝，最后删除临时库和角色。它不读取或变更原平台数据库，也不能证明真实生产凭据已经隔离。原件IAM、S3维护、异机恢复、真实模型语义和生产并发仍需单独验收。

实际运行命令和最终结果见[F6验收报告](releases/2026-10-22-finance-f6-acceptance.md)。当前接口包及详细响应以`examples/finance/apis/finance.yaml`为准。

## 验收入口的本机准备条件

当前仓库的维护/恢复测试复用成熟PG工具，通过名为`xuanpu-finance-f4-test-pg`的专属测试容器执行pg_dump/pg_restore。运行quick/full前须准备与显式DSN对应的这个隔离容器、可用Docker及创建临时库/角色的测试管理员权限；名称沿用旧测试约定，本轮标签为finance-f6。不可把已有平台或正式容器改名复用。未满足前提时测试应失败，不能跳过维护或恢复模块。验收超时/取消报告会提示核对临时资源；在清理前不要把报告当作完整验收。

源码入口为`scripts/finance_acceptance.py`，使用`--dsn-file`、`--output`和`--suite quick|full`；DSN文件必须是私密普通文件，新输出目录保留JUnit、脱敏日志及report.json。完整报告中已有非财务skip逐项列出，正式供应商仍not_verified。
