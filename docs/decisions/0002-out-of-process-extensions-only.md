# ADR 0002：业务扩展只走进程外 —— 平台进程内不加载业务方代码

- 状态：Accepted
- 日期：2026-09-29
- 关联：ADR 0001

## 背景

业务方总会需要平台内置能力之外的东西：调内部系统、查私有数据、做特殊计算。最省事的做法是允许业务方写 Python 插件，由平台进程直接加载。

但平台是多租户共享的：

- 进程内插件可以读到同进程里其他租户的数据和凭据，隔离只能靠自觉；
- 插件崩溃、卡死、内存泄漏会拖垮同进程的所有会话，平台的崩溃接管也无从谈起；
- 插件直接依赖平台和 taifeng 的内部 API，平台每次升级都可能打破业务方。

## 决策

1. **平台进程内不加载任何业务方代码。**
2. **业务方的自定义能力只有两种形态**：
   - **MCP server**：业务方自己部署，经 xuanpu MCP 网关接入；
   - **沙盒内脚本**：随 skill 提交，经 taifeng `ScriptExecutor` 在 taifeng-sandbox 提供的隔离环境里运行。
3. 业务包里只能有声明（skills、连接器、策略、评测用例）和上述两种进程外扩展。

## 否决的方案

- **允许进程内插件，靠代码审查把关**：审查挡不住运行时行为，出事即跨租户事故，方向上不可逆。
- **允许进程内插件，但按租户分进程**：隔离问题解决了，但升级兼容问题还在，且每个租户一组进程成本高。可以作为高等级套餐的部署形态另行讨论，不改变本决策。

## 后果

- MCP 网关成为业务方唯一的扩展通道，重要性上升为平台核心组件：凭据注入、出网控制、副作用分类、调用审计都要在网关做全。
- 需要 taifeng 与 taifeng-sandbox 支撑：脚本执行走沙盒、MCP server 若由平台代为运行也要进沙盒。
