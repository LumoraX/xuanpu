# ADR 0021：桌面客户端经浏览器接力完成飞书登录 —— 等待页轮询，不用深链、不开本地端口

- 状态：Accepted
- 日期：2026-11-16
- 关联：ADR 0010（飞书登录、服务端登录会话）

## 背景

桌面客户端（`packages/xuanpu-desktop`）在自己的 WebView 里打开企业服务，原先飞书登录整条链路也在 WebView 里走：服务端 → 飞书授权页 → `<public_url>/v1/auth/feishu/callback`。实际使用中，飞书授权常由飞书 App 或系统浏览器接手（装了飞书客户端时授权页会唤起它；授权途中经过白名单以外的飞书域名时客户端把它交给系统浏览器），授权后回调落在系统浏览器里：

- WebView 收不到回调，登录不会完成；
- 系统浏览器里没有登录尝试 cookie（它写在 WebView 里），回调按登录伪造防护判为 `state_invalid`；
- WebView 与系统浏览器的 cookie 互不相通，浏览器里登录成功也不会让客户端登录。

考虑过的做法：

| 做法 | 结论 |
| --- | --- |
| 本地回环端口接回调（`http://127.0.0.1:<端口>`） | 要在飞书后台另登记回调地址，端口不固定时无法登记；授权码还要再转给服务端换令牌（App Secret 只在服务端）。不采用 |
| 服务端读「浏览器当前登录的飞书账号」 | 飞书登录态是 `feishu.cn` 下的 cookie，服务端读不到。不可行 |
| `xuanpu://` 深链唤起客户端 | 要注册 URL scheme（Info.plist、各平台注册），开发包与验收复制品抢同一 scheme，浏览器每次弹「是否打开」；任何应用都能注册同名 scheme，安全仍要靠客户端持有的凭据。可作后续增强，不作基础方案 |
| 浏览器接力 + 等待页轮询 | 不需新的系统注册与飞书后台配置，客户端只改导航策略。采用 |

## 决策

1. **入口**：桌面客户端把 WebView 里对 `/v1/auth/feishu/login` 的导航改写为带 `client=desktop`。服务端为这次登录记下 `client=desktop`，写登录尝试 cookie（只在 WebView 里），返回**等待页**而不是 302：显示 6 位确认码和一个 `target="_blank"` 的授权链接；客户端把指向登录来源的新窗口交给系统浏览器。
2. **回调**：飞书回调落在系统浏览器。对 `client=desktop` 的登录尝试不核对登录尝试 cookie，认出员工后不在浏览器里签发登录会话，而是建一条**桌面接力记录**（绑定 WebView 登录尝试 cookie 的摘要，5 分钟有效），浏览器显示**确认页**：同一确认码与「确认登录」按钮，表单里带一次性确认串。浏览器原有的登录会话不动。
3. **确认**：`POST /v1/auth/feishu/desktop/confirm` 凭确认串把记录标为已确认，只能一次。确认页写明只有本人正在客户端登录、且确认码一致时才确认。
4. **轮询与换取**：等待页轮询 `GET /v1/auth/feishu/desktop/status`（`pending` / `confirm` / `ready` / `invalid`）；`ready` 后导航到 `GET /v1/auth/feishu/desktop/redeem`，凭登录尝试 cookie 取出已确认的记录，重新检查租户与员工状态，签发登录会话并写进 WebView，302 到 `return_to`。客户端在导航到换取地址时把窗口切到前台。
5. **存储**：登录尝试加 `client` 列（默认 `browser`）；新表 `desktop_handoff`，只存 cookie 摘要与确认串摘要；过期记录由既有维护任务一并清理（迁移 0027；最初以 0026_desktop_handoff 部署到生产，与主线 0026_local_credential 撞号后改号，脚本可重复执行，生产的一次性对账见运维手册）。
6. 飞书后台的重定向地址不变；浏览器登录流程不变。

## 安全考虑

- 换取凭登录尝试 cookie：它只在发起登录的 WebView 里，不出现在任何链接或页面中。回调链接、确认页被别人拿到都换不到会话。
- 把授权链接转发给别人、诱骗对方授权是这类接力的固有风险（与设备码授权同类）。缓解：对方授权后还须在确认页手动点确认，确认页提示核对确认码；确认码与对方自己的客户端不一致，或对方并没有在登录。接力 5 分钟过期，确认与换取各一次，换取前重查员工状态。
- 确认码只供肉眼核对，不是凭据。页面是固定模板、插入值全部转义，CSP 只放行带 nonce 的固定脚本、不允许外联，禁止被嵌入，不发 Referer。

## 后果

- 桌面客户端登录多一步：在浏览器里点「确认登录」。浏览器里已登录飞书时通常不需要扫码。
- 网页版登录不受影响；`client` 只接受 `browser` 与 `desktop`，其他值报 `400`。
- 以后要免去手动切回，可以在此基础上加 `xuanpu://` 深链，只用来唤起客户端，凭据仍走本方案。
