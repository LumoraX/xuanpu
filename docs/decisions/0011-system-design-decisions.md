# ADR 0011：整体设计定下的九件事 —— 底座先无状态、员工内容管理员默认不可见、新增触发与个人 skill

- 状态：Accepted（2026-10-01 用户对整体设计及其个人 skill 增补回复「可以」）
- 日期：2026-10-01
- 关联：ADR 0005（取代其决策 5）、ADR 0007（收窄其拍板结果第 5 项；其「对内核的依赖」一节以本 ADR 决策 1 为准）、ADR 0009、ADR 0010；taifeng ADR 0109–0116
- 详细设计：[平台整体设计](../superpowers/specs/2026-09-30-system-design.md)

## 背景

把第一版底座、企业版的三份决定（ADR 0007、0009、0010）、P1 详细设计和内核刚补齐的 14 项对接口放在一起看，发现两类问题：一是内核补了缺口之后，第一版为绕开缺口做的几处取舍可以撤了；二是几份 ADR 各自成立，合起来有出入（检验标准无人承接、管理员可见性与取证通道矛盾、审计会存下邮件正文、「外部内容进入会话」的标记没人记、评测没有员工身份、用量没有应用维度）。整体设计逐项给了建议，本 ADR 记下通过的部分。

## 决策

1. **底座升级（P0）排在所有子项目之前。** 以 taifeng `feat/kernel-seams` 发版为前提：会话主存进 Postgres（取代 ADR 0005 决策 5），业务包归档进对象存储，计算节点本地盘上只剩可重建的缓存；新增停止生成；连接器进程进沙盒；过闸审计直接归到那一轮；远端 MCP 作为连接的一种传输。同一步收掉已知限制里的五处（停机时限、`/openapi.json`、拒绝留痕、配额修改、指标端点）。
2. **内核的审计模式与会话日志后端本阶段不用**，不为它在「只依赖稳定层」上开例外。平台的审计走自己的审计表；等它转为稳定再评估。
3. **新增 P9：定时与事件触发、动态。** ADR 0009 的检验标准（员工不在时 agent 做完了什么）在 P1–P8 里没有子项目承接。触发出来的就是普通会话，走同样的闸门、预算、审计。排在 P4 之后。
4. **员工的内容，管理员默认看不到。** 管理员与系统 API key 默认只看得到会话的元数据；正文只有本人可见；系统 key 只能读它自己建的、或它代调用的那名员工的会话。管理员要看正文走取证通道（ADR 0007 拍板结果第 2 项）。P1 可以先按其详细设计 8.1 做，但这条在 P6 上线前必须落地。
5. **以员工身份读到的内容，审计只记摘要。** 连接上标了「读到的是外部内容」的工具，审计里只记参数摘要、返回内容的大小与摘要，不记正文。正文只在会话里。
6. **「外部内容进入会话」的标记放在平台的会话记录上**，由闸门在文件拷入、以员工身份的读取成功返回、打开网页三个时机置位，只增不减，随会话保存。工具上同时声明输出是否可信（稳定层类型上的字段）；内核的来源标记转为稳定后可以改为以它为准。
7. **执行环境按用户隔离维持 ADR 0007 决策 5 的做法**（引擎池按用户拆），不用内核新给的脚本会话标识做路由：命令执行器与工作区文件协议的调用里没有归属标识，用它会隔离不全。向内核提需求（缺口清单第 15 项），拿到后并回引擎池是纯优化。
8. **对象存储抽象放在 xuanpu，不进 taifeng-stores**（文件中心不是内核协议）；实现两个：兼容 S3 的，和落在本地目录的（只用于单机试用）。**预置的连接模板独立成包 `xuanpu-connections`**，只有数据，可独立发版。
9. **新增 P10：个人 skill，收窄 ADR 0007 拍板结果第 5 项。** 员工可以写自己的 skill（一个目录一份 SKILL.md，标识带 `me.` 前缀，存在个人空间，只对本人生效），入口仍然是管理员上架的应用。第一版不带脚本、不能当入口、不能引用应用没开放的工具；应用在清单里声明 `personalSkills: true` 才启用，租户可整体关掉。进会话的办法是组装时把应用的 skill 目录与本人的个人 skill 合成一个目录交给内核，并把入口可调用的子 skill 列表追加上它们（只改本地缓存里的副本）；内核的 skill 授权策略与来源分层晋升稳定层后换过去（缺口清单第 16、17 项）。

另外两项由整体设计分派给子项目，不单独列为决策：评测如何获得员工身份放到 P6 详细设计（方向是给连接配「测试身份」）；用量加「应用」维度放进 P2。

## 否决的方案

| 方案 | 原因 |
| --- | --- |
| 跳过 P0，直接做 P1 | 后面每个子项目都站在底座上；现在不去掉共享卷与「只适合受信任租户」，后面每一项都要带着它们做 |
| 用内核的脚本会话标识做按用户路由，不拆引擎池 | 只有脚本带了标识，命令与文件工具没有，会变成隔离不全 |
| 用内核的输入来源标记实现「外部内容进入会话」 | 它在实验层；平台的会话标记一个字段就够，先不依赖 |
| 管理员可读全部会话正文（P1 设计 8.1 的现状延续到 P6 之后） | 等于绕过取证通道读员工邮箱 |
| 员工自建入口（助手） | 入口受管理员上架控制是企业场景的前提；个人 skill 在上架的「通用助手」里就是自己的助手 |
| 个人 skill 第一版就带脚本 | 员工写的代码要等按用户的沙盒稳定后再开 |

## 后果

- ADR 0005 决策 5 被决策 1 取代；ADR 0007「对内核的依赖」一节过时，以决策 1 与缺口清单为准；ADR 0007 拍板结果第 5 项按决策 9 收窄。
- 子项目从 P1–P8 变为 P0–P10；顺序见整体设计第 13 节。
- 缺口清单新增第 15–17 项。
- 每个子项目的详细设计要对照整体设计第 5 节的七条规则。
- 决策 1 的前提（内核发版、三仓合入发布）是操作，另行确认后执行。
