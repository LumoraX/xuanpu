# ADR 0012：员工端是个人工作站 —— 一人一个助理、事项、四种待办、部门助理透明

## 背景

ADR 0007 把员工端定为「工作台」：左栏应用列表、中间对话，员工从应用中心挑一个应用开始对话。用示意稿把它做出来之后，用户逐轮否定了这个形态：

1. 页签式的管理界面没有「一台电脑」的感觉。员工要的是直接进入对话、从对话里打开文件夹和应用。
2. 「同事列表」里把财务、行政各做成一个 agent，用户指出：员工只有一个助理；报销是助理去调报销系统的接口或去找财务部，不是员工去找「财务 agent」。
3. 别的部门那边也是助理在接，但对员工应当透明，界面上只出现「财务部 · 已受理」这样的进展。
4. 待办要把「要你确认的」「你让它记的提醒与定时任务」「交出去的事」合在一起。
5. 不同岗位（销售、研发、财务、管理者、项目经理）要用同一个形态，差别只在助理会什么、接了什么系统。
6. 最后一问：它能不能像操作系统一样承载全部工作。答案是能承载协调、流转、例行、检索类的工作；高带宽的创作、实时沟通、本机的事留在各自的工具里，但从这里出发、回到这里。

## 决策

1. **员工端是「个人工作站」，不是工作台。** 整屏是桌面；底部的对话是入口，打开就是对话状态；文件、事项、设置以窗口打开；没有页签式导航，没有「应用中心」。
2. **一人一个助理。** 员工只跟自己的助理说话。管理员按岗位上架的能力包（原来叫「应用」）不再是员工挑选的入口，而是助理会的事；员工说一件事，助理自己决定用哪个能力包、调哪个接口、要不要找别的部门。
   - 会话结构：一条长期存在的主对话，加上按事项各自的会话。主对话里的助理把事情派到事项会话里。
   - 组装单位从「一个业务包」变成「一名员工的助理」：对他可见的能力包加上他的个人 skill，在他自己的执行环境里合成一个 skill 目录（做法与 ADR 0011 决策 9 相同），各能力包的版本在会话创建时钉住。
   - 助理的名字、性别或声音、对员工的称呼、说话风格由员工自己设；它不用问就能做的事在管理员定的上限之内由员工调。
3. **事项是员工自己的业务容器**：一件事的对话、文件、进展放在一起，桌面上按事项摆。事项是个人的。项目管理经连接接现有的项目管理工具，每个人的事项只是「我这边的那一份」；多人共享的团队事项列为后续，等确有需求再做。
4. **部门助理是部门养的岗位 agent**：有自己的身份与企业凭据，排队接全公司的交接（审核报销、给差旅标准、登记假期），审计记在部门名下，所有人看到的是同一个它。**对员工透明**：界面上不出现它，员工的对话里只出现「某部门 · 进展」；想知道进展就问自己的助理。两个助理之间的交接是平台机制，两边各记一笔审计。
5. **待办有四种，在一个列表里**：要你确认的（助理办到对外一步停下）；你让它记的（提醒与定时任务，同一个机制：到点以你的身份跑一轮对话，只说一句话也是一轮）；交出去的（交接给别的部门、等对方的）；要你批的（别人的事等你点头，管理者用）。飞书日历、飞书任务里已有的待办经连接读进来显示；平台自己只存触发规则和等确认的事。人不在工作台时经飞书消息提醒。
6. **窗口可以承载外部的网页应用**（飞书文档、CRM 页面、WOPI 编辑器），这样高带宽的工作「从这里打开、做完回到这里」。搜索是助理的一等能力（跨空间、邮件、文档、工单一次问完），仍不建全局索引（ADR 0009 决策 3）。手机端至少要能做待办、确认、看进展。
7. **不替代的**：高带宽的创作（表格、设计、代码、视频）、人与人的实时沟通与会议、本机的外设与离线。这些从工作站出发、回到工作站，但不在工作站里完成。
8. **子项目随之调整**（改 ADR 0011 的清单）：P2 改为「能力包与岗位」（上架、按组可见、按岗位组合）；P5 改为「个人工作站」（含事项、待办索引、外部网页窗口、手机端的待办与确认）；P9「定时与事件触发、动态」并入待办的产生；新增 **P11「部门助理与交接」**（部门身份、队列、交接协议、双边审计），在 P6 之后。

## 否决的方案

| 方案 | 原因 |
| --- | --- |
| 工作台 + 应用中心（ADR 0007 原案） | 员工要先知道「该用哪个应用」；管理后台的形态，不是一台电脑 |
| 每个岗位一个 agent 出现在员工的通讯录里 | 让员工误以为「丢给财务」就完事；责任边界混乱（它其实是以员工身份在办） |
| 员工直接和别的部门的助理对话 | 多出一层员工不需要理解的东西；交接应是基础设施 |
| 平台自建项目管理、团队事项 | 违反小核（ADR 0009）；先接现有工具 |
| 平台建全局搜索索引 | ADR 0009 已否决（权限同步代价高）；助理去各来源搜 |
| 把一切工作都塞进对话 | 高带宽的工作在对话里做不好；窗口承载外部应用解决「从这里出发」 |

## 后果

- ADR 0007 的「工作台」「应用中心」说法作废；「应用」一词在员工端不再出现，管理端叫「能力包」。
- 执行环境的键从（租户，业务包，版本，用户）变成（租户，用户，能力包版本集合）；运行时组装要支持多个业务包合并，连接器按能力包各自声明、取并集。
- 新概念进控制面：事项、交接、部门身份（非人的用户）。
- 整体设计第 3、6、7、11、13 节随之修订。
