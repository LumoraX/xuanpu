# ADR 0022：匠人、skill 与工具各有给员工看的名字

- 状态：Accepted
- 日期：2026-11-18
- 关联：规范 `xuanpu/v1`（向后兼容的可选字段，不升大版本）；[业务包规范](../architecture/package-spec.md)

## 背景

R5 验收发现，平台对员工说话时用的是技术名：管家回报写「「support-desk」有一项操作需要你确认」，待确认审批显示 `mcp__crm__update_ticket`，控制台只靠前端写死的一条映射把 `support-desk` 显示成「工单助手」。业务规范没有显示名字段。

用户于 2026-11-18 决定：匠人有自己的名字（如「医生匠人」「设计师匠人」），工具和 skill 也各有自己的名字。

## 决策

1. 规范新增三个可选显示名，均为 1–40 字、单行：清单 `metadata.displayName`（匠人名）、连接器 `tools[].displayName`（工具名）、SKILL.md frontmatter `display_name`（skill 名）。不填时一律回退到技术名。
2. 显示名只影响给员工看的文字：会话与业务包视图的 `display_name`、待确认审批的 `detail.display_name`、管家的匠人目录（`name`、`entry_name`）与派工回报。引用、授权、审批规则、审计与工具调用仍只用技术名。
3. 派工时把匠人显示名冻结进派工记录（`ArtisanRef.display_name`），之后包升级改名不影响已派出的工作怎么称呼；旧记录没有这一项时用包名。
4. 显示名由业务包声明，不在平台另建改名表；企业需要不同叫法时发新版本业务包。

## 后果

- 可选字段对已有业务包与校验器无影响，`xuanpu/v1` 不升大版本；旧版本平台读到带显示名的清单会因 `extra=forbid` 拒绝，所以业务方用这些字段前需要平台先升级。
- 控制台去掉写死的映射，示例 `support-desk` 在清单里声明「工单助手」。
- 显示名不是唯一标识：两个包可以重名，员工以对话上下文区分；管家派工仍按技术名。
