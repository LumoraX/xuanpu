# ADR 0016：复用PostgreSQL承载组织及跨员工协调

状态：R3-B候选实现，生产验收尚未完成。

跨员工授权、业务状态、回执和治理事件需要同一提交边界。个人WorkspaceStore不能承担跨员工原子操作，进程内监听者不能作为恢复事实。

采用既有PostgreSQL、asyncpg和原生行锁，增加平台协调工作单元。按租户、排序员工、领域实体、outbox取锁；仓储和姓名写集使用同连接。HTTP、模型和对象存储不进入短事务。内存只用于契约和本机试用，遵守同样回滚边界。

不引入Temporal、Celery或BPMN引擎：当前是有限组织变更与短事务，R2执行仍由现有TaskRegistry负责。新增任务生命周期和身份体系不能解决同库授权提交问题。协调层不实现通用工作流DSL，不修改泰逢。

领域事实与治理事件一起持久化，消费者逐事件确认。身份停用先提交，再做协调收尾；当前权限直接检查身份代次和职责，收尾延迟不延长授权。

代价是试点按租户串行并加载类型化快照。后续吞吐优化必须保留既有事务与隔离契约，不能新增多实例并行来掩盖单实例边界。
