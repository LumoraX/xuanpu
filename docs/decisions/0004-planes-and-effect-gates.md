# ADR 0004：平台按「四平面 + 效应闸门」组织，不照搬「CPU + 外设」

- 状态：Accepted
- 日期：2026-09-30
- 关联：ADR 0001（定位与分层）、ADR 0002（业务扩展只走进程外）、ADR 0003（成熟组件采用不自研）；taifeng ADR 0017、ADR 0025、ADR 0028
- 参照：codex（`exec-server` / `sandboxing` / `network-proxy` / `thread-store` 各自独立 crate）、openclaw（gateway + SecretRef + sandbox backend 注册表）、hermes-agent（`tools/environments/*` 多后端、`plugins/memory/*`）

## 背景

最初的设想是照传统计算机来搭：taifeng 是 CPU，存储、显示、第三方调用、记忆是外设。这个类比在「机制与实现分离」这一点上成立，也是 taifeng ADR 0017 的出发点。但拿它当平台的整体架构，有三处对不上：

1. **CPU 是确定的，模型不是。** 传统系统信任被调度的指令，靠内核态 / 用户态隔离；而 skill 是自然语言，模型的输出无法事先证明安全。所以信任边界不能画在「内核」上，只能画在**副作用发生的地方**：进程启动、文件写入、出网、调第三方、花钱调模型。
2. **算力在机器外面，而且按量计费。** 真正的「CPU」是模型供应商，内核做的是调度和上下文管理。模型访问本身就是一种要配额、要路由、要审计的外部调用，和调一个 MCP server 没有本质区别。
3. **工作状态不在内存里，在日志里。** 上下文窗口随时会被压缩换页，可靠的事实源是追加写的会话日志（taifeng ADR 0025）。只要日志可共享，执行节点就可以是无状态的——这更接近数据库和持久化执行引擎，而不是一台 PC。

企业场景要的三件事——可配置接入、完整审计、高并发——恰好分别落在这三处：配置决定副作用闸门放行什么，审计记录每一次过闸，高并发靠无状态执行节点加共享状态。

## 决策

1. **内核加外接的分层不变。** taifeng 仍是零租户概念的微内核，`taifeng-sandbox`、`taifeng-stores` 仍是只实现内核协议的适配包（ADR 0001）。本 ADR 只规定 xuanpu 自己怎么组织。
2. **平台分四个平面**，每个平面可以独立伸缩、独立替换：

   | 平面 | 职责 | 由谁承担 |
   | --- | --- | --- |
   | **计算面** | 承载 taifeng 引擎、会话放置、单写者租约、事件流 | `xuanpu-server` 运行时；节点本身无状态 |
   | **效应面** | 一切副作用的出口：沙盒、MCP 连接器、模型调用 | `taifeng-sandbox`、连接器桥（后续为 MCP 网关）、模型网关 |
   | **状态面** | 会话消息、线程目录、长期记忆、业务包制品 | `taifeng-stores` 加平台自己的表 |
   | **治理面** | 租户、密钥、业务包版本、策略、配额、审计、计量 | `xuanpu-server` 控制面 |

3. **副作用必须过闸门。** 效应面的每个出口都是一个策略执行点：先按租户策略判定放行与否，再执行，结果写审计。模型在闸门之内可以自由决策，闸门之外的事它做不了。平台不依赖提示词约束模型行为。
4. **审计以闸门和会话事件为准。** 审计记录来自两处：内核事件总线（按 `(会话, seq)` 去重）与效应面闸门。二者都带租户上下文，追加写、不改不删。
5. **密钥只以引用出现。** 业务包与策略里只写密钥引用，明文只在效应面出口处解析并注入到目标进程，不进提示词、不进日志、不进审计正文。
6. **计算节点无状态是目标形态，分两步到达。** 第一版会话日志仍是节点本地文件（受 taifeng-stores ADR 0002 约束），靠会话租约保证单写者，跨节点接管需要共享卷；等 taifeng 公开日志协议后切到共享日志后端，节点才真正无状态。

## 否决的方案

- **照搬「CPU + 外设」做成单体宿主**：所有外设挂在一个进程里，租户隔离、横向扩展、审计口径都要各处各自保证，最后审计会漏、隔离靠自觉。
- **改用图编排或多 agent 框架做平台骨架**：那是另一种范式，和 taifeng「模型即调度器」的前提冲突（taifeng ADR 0003、0006）；而且它解决的是编排表达力，不是这里要解决的隔离、审计、并发。
- **把策略和审计下沉进内核**：违反 taifeng R1（业务零侵入）与本仓红线 2（平台概念不下沉）。

## 后果

- 新增任何能产生副作用的能力，都必须说明它走哪个闸门、审计记什么；说不清的不合并。
- 内核稳定层目前缺几处对接口，平台第一版因此有已知限制，清单见 `docs/architecture/kernel-seam-backlog.md`，按红线 3 回 taifeng 立项，不绕道。
